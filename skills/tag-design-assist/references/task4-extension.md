# Task 4 — 后续拓展的可能性

## 目标

在完成 Task 1–3 的过程中，你可能会发现：某些效果组合写起来很自然，但现有机制列表（`docs/现有机制列表参考.md`）里没有对应的**原子机制**来支撑它。

本任务的目标就是：**把这些"缺失的积木"提炼出来**，产出 2–5 个新的原子机制候选。

## 什么是"原子机制"

原子机制**不是**单个动作或单个触发器，也不是现有机制的内部行为细节。它是一个**开辟新游戏维度的基础系统**——加入它后，游戏的规则层面多了一整块新的可能性。

判断标准：
- 它引入了**现有系统无法表达的新规则/新维度**
- 它可以被大量不同主题的卡牌复用
- 它自身内部包含 T、C、A、K 中至少 2 个维度的要素

| 维度 | 含义 | 说明 |
|------|------|------|
| **T** (Trigger) | 该机制为系统贡献的触发时机 | 其他效果可以监听的事件 |
| **C** (Condition) | 该机制为系统贡献的条件/取值器 | 其他效果可以查询的状态 |
| **A** (Action) | 该机制为系统贡献的可执行动作 | 其他效果可以调用的操作 |
| **K** (Keyword) | 该机制自带的关键词/卡牌类型规则 | 定义卡牌运作方式的内在属性 |

### 粒度参照

现有的原子机制示例，帮助理解正确粒度：

```
对拼系统：双方各弹出一张卡，比较拼点数值决胜负
- T: OnClashWin、OnClashLose
- C: ClashDiff（拼点差值）
- A: Clash（发起对拼）
- K: 斩、刺、打、射击、盾、格挡（拼点类型）

冷却循环：卡牌按固定流程轮转——等待资源→冷却→就绪→待发→结算
- T: OnCooldownReady、OnCardPlayed
- C: CooldownProgress、IsReady
- A: 充能、冻结、减速、加速
- K: 被动（不参与冷却循环的特殊标记）

卡组操作：对卡组内卡牌的增删和位置管理
- T: OnAddCard、OnRemoveCard
- C: CardCount（某类卡数量）
- A: AddCard、RemoveCard、位移
- K: 消耗品（有层数，使用扣层，耗尽移除）
```

### 常见错误

- ❌ "叠层" — 这只是 Buff/异常 机制内部的层数行为，不是新维度
- ❌ "蜕变" — 这只是 RemoveCard + AddCard 的组合，属于卡组操作
- ❌ "标记" — 太小，只是 Buff 的无效果变体
- ✅ "闪避" — 新的拼点类型，扩展了对拼系统的维度
- ✅ "AOE" — 多目标系统，现有机制全是单目标，这开辟了新维度
- ✅ "召唤" — 生成独立实体，有自己的卡组循环，完全是新系统

## 要求

- 它是**通用积木**，不是只为当前主题服务的专用效果
- 粒度与"对拼"、"冷却循环"、"卡组操作"同级——是系统级的新维度
- 不是现有机制的换皮/重命名/内部行为/简单组合
- 内部必须能提供至少 2 个维度（TCAK 中至少覆盖 2 个）

## 步骤

1. **回顾 Task 3**：检查你在组合效果中是否暗含了"现有系统无法表达的新维度"。典型信号：
   - 效果暗示了新的运作模式（如：多个目标、新的拼点方式、新的实体类型）
   - 你发现自己不得不用"类比+脑补"来凑合描述，说明现有原子不够用
   - 某种玩法模式在当前系统中完全无法表达

2. **泛化抽象**：去掉主题色彩，提炼为通用系统。判断方式：换一个完全不同的主题，这个机制还有用吗？如果有，它就是合格的原子。

3. **TCAK 拆解**：为每条新机制列出它贡献的 TCAK 要素。

4. **去重检查**：
   - 能用现有机制的 A 组合实现的 → 不是新原子
   - 只是某个现有机制的子行为/细节 → 不是新原子
   - 引入了现有系统根本无法表达的新规则 → 才是新原子

## 输出格式

```
新原子机制候选：

- 机制名：一句话核心定义
  - T: 触发器1、触发器2
  - C: 条件/取值器1
  - A: 动作1、动作2
  - K: 关键词/规则（如有）

- 机制名：一句话核心定义
  - T: ...
  - C: ...
  - A: ...
  - K: ...（如无则省略该行）
```

注意：
- 2–5 条，不贪多
- 一句话定义风格对齐 `docs/现有机制列表参考.md`（简短、直白、无修饰）
- TCAK 各项只列名称，不加详细解释
- 如果某个维度该机制不贡献，省略该行

## 示例

**主题：蛇 → 发现的新原子机制**

新原子机制候选：

- 闪避：一种新的拼点类型，不比数值大小，而是按概率完全回避对拼伤害
  - T: OnDodge（闪避成功时）、OnDodgeFail（闪避失败时）
  - C: DodgeRate（闪避概率）
  - K: 闪避（拼点类型标记，区别于斩/刺/盾等）

- AOE：效果或拼点同时作用于多个目标，而非当前的单目标结算
  - T: OnAoeHit（AOE命中时，每个目标各触发一次）
  - C: TargetCount（受影响目标数量）
  - A: AoeApply（对多目标施加效果）
  - K: 群体（标记该卡为多目标卡）

- 召唤：生成一个独立实体，拥有自己的简易卡组并自动循环运转
  - T: OnSummon（召唤生成时）、OnSummonDeath（召唤物消亡时）
  - C: SummonCount（场上召唤物数量）
  - A: Summon（生成召唤物）、Dismiss（移除召唤物）
  - K: 召唤物（独立实体，有HP和简易卡组）

## 完成条件

将新机制候选列表呈现给用户。全部 Task 完成后，建议用户将有价值的新机制候选补入 `docs/现有机制列表参考.md`。
