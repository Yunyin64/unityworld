# 防御拼点与卡牌形状

## Why

人物模板轮测提出两项工程需求。现有 C# 结算直接规定同类攻击通吃，格、挡、闪共用伤害规则。把特殊拼点效果放进卡牌 Keyword，配卡时就能看到每张牌参与哪些机制。正式卡牌仍只能按 `Size` 生成横条，异形需要独立的配置入口。

## What Changes

- 卡牌 Lua 继续通过现有 `Attack`、`Defend` 提交拼点。装备提供的格、挡、闪读取绑定装备的防御值。C# 比较点数并计算基础差值，只调用本次配对双方来源卡的拼点结算 Keyword。
- 斩、刺、打各自的 Keyword 在同类型攻击对拼获胜时改为全额伤害。「斩对斩通吃」直接由「斩」承载。射击对攻击、异类攻击及攻击胜过格或挡走基础差值。
- 「格」赢过敌方攻击后，给自己等于胜出差值的下次攻击拼点强化。「闪」赢过敌方攻击后，为自己的背包充能等量 Tick，输给攻击时承受对手的全额拼点值。挡走基础结算。
- **BREAKING** 依赖旧同类攻击通吃的正式卡定义需要配置对应的拼点效果 Keyword。
- 功法提供完整的 `N × M` 矩形背包，保留宽高、等级布局和主功法固定格配置。
- 卡定义新增可选的 `SizeShape`，通过 ID 引用独立的 `ShapeDefine`。省略时沿用横条，显式形状按固定朝向摆放，格数等于 `Size`。
- **BREAKING** 将外部卡牌 JSON 的 `Size` 从隐式默认 1 改为必填正整数。已有显式 `size` 写法继续有效。
- 用独立工程样例验证规则和数据链路。首批正式卡牌、装备数值和形状组合留在内容配表阶段。

### New Capabilities

### Modified Capabilities

- `combat-contest-scheduling` 定义基础差值、卡牌 Keyword 的特殊拼点效果及伤害时序。
- `combat-backpack` 定义完整矩形空间、形状引用、占格和锚点。
- `combat-backpack-scan` 将正式跨行卡接入末格发动规则。
- `npc-template-backpack` 按所选功法和解析出的卡形预检并装配模板。
- `character-template-editor` 按实际矩形与卡形显示、拖放和诊断。

## Impact

涉及战斗拼点结算和 Keyword Lua、卡牌与功法定义、玩法数据加载、模板预检、Godot 模板编辑器及战斗显示验收。复用单次全攻击强化和整包充能动作。沿用现有扫描、SP、费用与伤口放置规则。
