# 实施任务

## 1. 将特殊拼点结果交给卡牌 Keyword

卡牌脚本提交拼点，C# 给出基础差值，本次配对的两张来源卡通过各自的 Keyword 处理特殊效果。

- [ ] 1.1 接通配对的基础差值与伤害入队前的来源卡 Keyword 回调。用实际配对验证胜方和败方各处理一次，场上未参与配对的卡不进入此回调，伤害只入队一次并走原伤害修正。
- [ ] 1.2 在斩、刺、打各自的 Keyword 实现同类通吃。分别验证 6 对 4 的同类和异类攻击、射击对攻击、Keyword 与本次实际提交类型不一致的情况。将依赖旧通吃的正式卡补上相应 Keyword，验收使用独立样例并确认原攻击接口签名仍可调用。
- [ ] 1.3 在格和闪各自的 Keyword 实现防御效果。用独立用例验证格的胜出差值由自己下一次攻击消费，闪获胜只给自己的背包充能，闪落败吃全额，格、挡落败取差值。以 6 射对 4 斩和 6 射对 4 闪验证分别提交 2、6 点基础伤害。另验证挡、平局、防对防和未配对防御均无奖励，格的奖励可保留大于 99 的差值。
- [ ] 1.4 确认可通过现有出招入口配卡。用独立样例让两件不同防御值的装备共用一个招式定义，验证卡 Lua 读取相应装备点数并通过 `Defend` 提交实际类型。通过 `--tca-tests` 验证新用例及原拼点、Buff 和充能用例。

## 2. 从配置得到矩形背包与实际卡形

在定义层确定合法形状，向装配提供可直接使用的格坐标。

- [ ] 2.1 正式主功法沿用宽高和等级布局并校验完整矩形。用默认 5×5 和一套显式非正方形布局确认容量、主功法固定格及等级读取，显式缺格的正式布局给出功法及等级诊断。
- [ ] 2.2 接入 `ShapeDefine`、形状定义加载及 `SizeShape`。验证缺省和空字符串均生成横条，3、4、5 格的显式形状通过正式卡定义加载并计入等量 SP。验证缺少 `Size`、未知或重复形状 ID、重复坐标和格数错误给出可定位的错误。
- [ ] 2.3 让卡实例、模板后端预检与装配使用解析结果。用正式 `SizeShape` 样例在 `--backpack-tests` 和 `--backpack-timing-tests` 验证实例锚点、末格发动、行额度和滑移，按完整形状验证伤口可落格及无合法位置的诊断。通过 `--template-tests` 验证形状引用错误、越界和实际重叠能在装配前定位。

## 3. 让模板编辑器预览与试战一致

编辑器从当前内容目录读取形状，沿用后端相同的占格解析。

- [ ] 3.1 将形状目录接入 `TemplateCatalog`、预检、草稿放置和画面。用 `TemplateEditor.Checks.csproj` 检查缺省横条、异形缺角可放单格卡、无效引用和非法放置保留草稿。用同一份输入核对编辑器与正式装配的格坐标和 SP。
- [ ] 3.2 编译 `UnityWorld.sln` 与 `Xianxia.Client.csproj`。在模板编辑器拖放一张显式异形并执行试战，核对预览、保存重载、真实快照与末格发动事件，确认缺角在试战画面仍可容纳另一张卡或灵元。
