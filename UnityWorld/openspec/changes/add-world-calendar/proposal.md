# Proposal

## Why

现有 `WorldTime` 只记录物理更新次数和累计秒数，无法表达按周推进的年月、月相、特殊周和节气。先建立独立、确定的世界周历数据，后续对象结算可以使用同一时间基准，不把玩家身份、执行批次或渲染帧写进时间模型。

## What Changes

- 新增以已过周数为唯一可变时间值的周历；初始为 4000 年新年，每年依次为新年特殊周、十二个月各四个普通周、除夕特殊周，共五十周。
- 普通月按新月、上弦、满月、下弦循环；月份地支从寅到丑。年份天干依据现实公元纪年的干支锚点计算，4000 年为庚年。
- 实现二十四节气数据和切换机制：从立春到大寒，每个覆盖两个普通周；特殊周独立标识，不占普通月、月相和节气槽位。
- 提供不可变日期投影、明确的一周推进入口、推进结果及只读变化通知；时间读取和分批执行本身不推进周历。
- 保留现有秒计时 API 和既有世界 Tick 行为。新增周推进不调用所有对象的 Tick，也不自动把秒换算成周。
- 本次只做后端基础。对象排序标记、周结算执行器、移动、探索属性、存档系统和前端接入留到后续；如后续需要前端任务，必须排在后端完成并验证之后。

**数字例子：** 已过 0 周是 `4000（庚）年 新年`；1 周是 `4000（庚）年 1（寅）月 新月`，当前节气立春；3 周是同月满月、雨水；49 周是当年除夕；50 周是 `4001（辛）年 新年`。

## Capabilities

### New Capabilities

- `world-calendar`: 五十周历法、日期和月相投影、按现实纪年锚定的天干、节气查询与切换、显式周推进及旧秒时钟兼容边界。

### Modified Capabilities

无。既有 `story-pool` 和 `world-generation` 的秒计时、Tick 驱动和生成事务要求保持有效；不在本变更中迁移其时间单位。

## Impact

- 后端：在 `Scripts/Game/World/` 增加周历值类型和时钟，通过 `WorldTime` 暴露当前周历与显式推进；沿用 `WorldMgr.Initialize()` 在地图成功发布之后初始化时间的生命周期。
- 验证：新增 `Scripts/Tests/WorldCalendarTests.cs`，在现有 `Program.cs` / `Console/UnityWorld.Console.csproj` 测试入口接入短测试，覆盖年界、月份、全部节气、通知和旧 Tick 隔离。
- 文档：提供规则、数字例子、API 接入说明及原文件改动清单；修改原版代码的位置须写必要注释。
- 相邻变更 `add-exploration-core-ui` 仍使用它自己的预览周数与界面规范。本变更不改其文档、预览语义或客户端文件，未来接入时显式替换预览数据。
- 无新第三方依赖，不使用系统当前日期、操作系统时区或真实秒数推算游戏周数。
