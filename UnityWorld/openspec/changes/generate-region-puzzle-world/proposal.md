# Proposal

## Why

世界需要在固定的 200×200 六边形大陆上支持逐格探索：四周地理固定，内部通过作者设计的完整地区拼图与加权基础地块组合出不同地图。目前实际生成只有空白地块填充；旧规范中的固定七类地形、矩形占地、越界裁切及重叠跳格，也无法保留作者设计的地区结构。

## What Changes

- 固定主大陆为 200×200（含边界、不环绕）；以明确坐标配置北方群山大漠、东方海域、南方雨林沙漠、西方隔绝一切的长城。边界不随种子变化。
- 引入海拔、温度、湿润度和水系约束底图，为地区与基础填充提供适配依据；最终地块由拼图和填充决定。
- **BREAKING**：地块类型改用数据定义 ID；山地、林山、荒山、火山、雪山均为同级类型。旧枚举及数字 JSON 提供显式迁移映射。
- **BREAKING**：地区按实际配置的相对 Axial 格子完整放置，内部逐格固定、默认保持朝向；取消矩形隐式占地、越界裁切和重叠跳格。必需地区放不下必须明确失败。
- 地区优先拼装，余下格子按环境、邻接关系与配置权重填满；用覆盖率目标和有界重试控制生成。
- 为跨格河流定义连接口和流向，检查通路、水系、固定边界及地区完整性；格内溪潭不参与跨格连接。
- 完成地区、地块和地标的必要运行时关联及管理器接入；自然初始元气与运行时每秒速率分开，最终自然快照按位面隔离。
- 增加种子、配置摘要与生成器版本驱动的可重复生成，以及 Console 诊断导出（JSON、可查看的 HTML/SVG 地图）；提供地块来源、放置失败原因及统计。
- 第一版交付生成内核、配置样例、迁移/校验及诊断预览。移动执行、迷雾、探索事件、社会模拟和 Godot 正式地图界面另立后续变更；地块保留通行与探索所需的数据基础。

## Capabilities

### New Capabilities

- `world-environment`: 固定大陆边界、连续环境底图、环境适配条件及有界局部调整。
- `world-hydrology`: 地区河流接口、基础地块水系连接、终点与通路检查。
- `world-generation-diagnostics`: 可重复生成、来源追踪、结构化失败、批量种子验证及可查看地图导出。

### Modified Capabilities

- `terrain-type`: 同级可配置地块类型、填充权重、通行和初始元气，旧枚举迁移。
- `region-system`: 固定不规则拼图、完整放置、环境适配、实例归属和数量规则。
- `world-generation`: 固定边界、环境、地区、补空、水系、地标和快照的生成流程及失败回滚。
- `plane-generation`: 显式生成模式、管理器初始化、生成成功后发布、主大陆固定尺寸。
- `tile-mgr`: 按类型 ID、地区及来源查询，正确注册生命周期。
- `landmark-system`: 适配类型 ID 与标签，地区地标原子生成、唯一性及初始元气配置。
- `tile-three-layer-aura`: 完成自然初始化后拍摄快照，保留现有逐秒累积行为。
- `tile-modifier-define`: 对齐实际速率语义，补全实例构造字段和来源归属。
- `aura-dao`: 原初快照按位面与地块复合定位、隔离失败生成、支持注销清理。

## Impact

- 实现范围在 `Scripts/Game/Data/`、`Scripts/Game/Domain/Object/{Plane,Tile,LandMark,Modifier}/`、新增地区运行时目录，以及 `WorldMgr`、`AuraDaoMgr`、`Rng` 的地图调用边界；保留现有 `.cs` 文件。
- 数据范围包括地块/主大陆配置、`RegionDefines.json`、`LandMarkDefines.json`、`TileModifierDefines.json` 的受控迁移与样例。诊断命令扩展现有 `Program.cs` 和 `Console/UnityWorld.Console.csproj`；验证沿用 `Scripts/Tests/`。
- 地区与地标旧数据需要批量审计后迁移；既有小位面和手工地块测试使用明确的基础填充模式，不被主大陆模板强行套用。
- 受影响主规范目前残留 delta 头且缺少 Purpose/Requirements，CLI 显示 0 条要求。实施时对本次涉及的主规范做不改语义的结构归一化，再正常同步本变更；本次提案只写 change 内的计划文件。
- 边界厚度/四角细节、南部雨林与沙漠的具体分布、覆盖率及数值权重属于内容配置。首版提供明确标注的验证样例，不把样例数值当作已确认世界设定。
