# Design

## Context

动机及能力范围见 [proposal.md](proposal.md)。本设计依据当前源码核查，不能把旧规范里的目标当作已实现功能。

| 已核查位置 | 当前状态与设计影响 |
|---|---|
| `Scripts/Game/Domain/Object/Plane/Plane.cs` | 有 odd-r 行列/Axial 转换、边界与地块存储；当前主世界工厂为 200×200。 |
| `PlaneMgr.cs`、`Plane/System/PlaneGenerator.cs` | 创建时先注册位面，再 Fill 空格并拍快照；新生成可能失败，需要改成候选成功后发布。 |
| `Tile/Tile.cs`、`Tile/Data/TerrainType.cs` | 地块仅有坐标、当前元气和修正列表；七类枚举存在，但地块尚未持有地形/地区/地标字段。 |
| `Data/Defines/RegionDefine.cs` | 固定相对 Axial 布局已存在，值为枚举；运行时 Region/RegionMgr 尚不存在。 |
| `GameDataMgr.cs`、`World/WorldMgr.cs` | 地区、地标、地块修正数据加载器未注册；TileMgr/LandMarkMgr 未接入域生命周期。 |
| `LandMark/LandMarkMgr.cs` | 有地标创建与唯一性判断，但缺占位回写；当前运行时 ID 是 int，沿用现有实体身份。 |
| `Modifier/TileModifier.cs` | 构造函数仅赋 AuraData，未初始化来源和时长，不能依靠现状实现可靠回滚。 |
| `Tile/System/TileSystemAura.cs` | 实际按 AuraData × deltaTime 累加；定义注释中的目标收敛不符合执行行为。 |
| `GamePlay/AuraDao/AuraDaoMgr.cs` | 仅复制 CurrentAura；快照键只有 TileId，会与其他位面同坐标混淆。 |
| `Core/Utils/Math/Rng.cs` | NewId 使用进程级静态已用 ID 集合；不能让实体 ID 分配影响地形随机流。 |
| `Program.cs`、`Console/UnityWorld.Console.csproj` | 现有 Console 链接主入口和静态 Run() 测试，可扩展诊断命令，不需引入新测试框架。 |

受影响主 specs 缺少主规范结构，`openspec show terrain-type --type spec --json --no-scenarios` 报 `Spec must have a Purpose section`；纯文本内容仍可读。本 change 沿用真实能力路径与 requirement 标题，实施时先归一化受影响主规范的结构。

## Goals / Non-Goals

**Goals:**

- 将作者固定拼图作为最终内容的首要来源，生成器选择位置并补空。
- 一次生成得到可查询、可验证、可追溯的完整大陆；失败不留下公开的半成品。
- 保留 C# 共享核心与当前元气运行规则；配置和报告能被脚本批量处理。
- 区分已确认的玩法规则与可调内容参数，默认样例服务验证。

**Non-Goals:**

- 本期不执行角色旅行、迷雾揭示、探索事件、道路/城镇社会模拟或动态地形演化。
- 不生成美术资产、不实现 Godot 正式地图交互；HTML/SVG 为诊断地图。
- 不建立气象/侵蚀仿真、局部可行走子地图或全局约束求解器。
- 不改变元气速率为目标收敛，也不处理失衡权重正负等与生成无关的旧差异。

## Decisions

### 1. 三种来源共享地块定义

拟新增 `TileDefine` 与相应加载器，稳定字符串 ID 是新数据的唯一类型标识。山地、林山、荒山、火山、雪山平级；标签只用于规则检索，不要求拆成地貌与生态的笛卡尔积。

定义包含：名称/说明/标签、初始五行浓度、基础填充资格与权重、环境硬条件/适配曲线、邻接允许与偏好、移动能力和代价、水文能力。资源与遭遇只留引用扩展位置，本期不引入其执行系统。颜色/符号用于调试，素材引用可空。

每个最终 Tile 保存类型 ID、来源（Boundary/Region/Fill）、地区身份（可空）、地标身份（可空）、环境与水文连接的查询入口。生成报告保存更详细的候选、权重、修整记录，不让每次 Tick 重算生成信息。无地区归属不等同于可改写：边界来源仍受保护。

相比扩充枚举，此方案允许内容作者和 Mod 新增类型，不需要给生成器逐类添加分支。保留 `TerrainType.cs` 和 `TerrainAuraProfile.cs` 作为迁移/兼容适配，不删除现有文件。

### 2. 主大陆模板是明确坐标表

拟新增主大陆生成配置（建议 `WorldGenerationDefine`），至少包含版本、边界条目、环境参数、地区目录、覆盖率目标、尝试预算、水系规则和关键地点连通组。尺寸固定为 200×200，包含边界，无环绕。

边界编辑/序列化使用 Offset 的 col/row（0..199），加载后调用现有转换得到 Axial。地区使用相对 Axial `(dq,dr)`；世界位置为锚点 Axial 加偏移，然后转换回 Offset 验界。不能直接把 q 范围当作 0..199，也不能把模板偏移当作 Offset 行列相加。

模板显式给出每个边界格的类型、固定内容及通行约束；重叠/重复坐标直接错误，四角不使用隐式覆盖优先级。西方长城的阻断是全移动能力的世界约束，不会被后续飞行模式绕过。其他边界的进入权限独立配置，地图外始终不可进入。

边界在生成期间锁定；“固定”不规定未来剧情能否修改它。首版样例会覆盖四种方向语义，但边界厚度、南方两类环境的位置和四角细节是标注的验证内容，非世界观定案。

### 3. 环境先提供条件，拼图决定类型

环境阶段产生归一化海拔、温度、湿润度，使用北南/海岸趋势加多尺度连续变化，种子从地图专用随机流派生。按六边形真实平面位置采样，避免 odd-r 奇偶行错位；固定边界提供锚点，向内以配置距离平滑过渡。

第一版使用可测试的确定性连续噪声/插值和简单气候偏置，不引入物理侵蚀依赖。参数控制斑块尺度，避免四万格独立抽样。地块类型并非根据这些值提前定死。

候选地区依次检查占位、边界、关键格、整体比例与水系硬条件，再计算软适配分数。明确使用有限值、区间、满足格子比例和非负权重；不把“适合湿润山地”留成不确定自然语言。

地区可声明各格有限的环境偏移，默认全零。以调整后的候选值重新计算硬条件、适配和下游水文；只调整自己的实际格，不调整外接框孔洞或邻居。保存原值便于事务回滚。允许局部调整的原因是主峰与谷地需要与固定内容一致，但范围和水系约束阻止模板任意重塑大陆。

### 4. 固定拼图的实际格集合是唯一占地真相

扩展现有 `RegionDefine`，将 TerrainLayout 的值迁为类型 ID（命名可保留以降低数据迁移成本）。布局键集合就是 footprint；Width/Height 只保留作旧数据迁移或展示元信息，不隐式占地。footprint 必须非空，允许内部孔洞或作者显式配置的非连续格集合；未配置格仍为空地。默认固定朝向，无自动旋转/镜像。

地区保留名称、标签、AuraProfile、固定地标，增加显式 MinCount、间距、环境条件和水文端口。`IsGuaranteed=true` 迁为 MinCount 至少 1；MaxCount=-1 仍表示无上限，其他值必须大于等于 MinCount。稀有度、权重、间距按定义配置；首版间距为同类实例锚点的六边形距离，实际 footprint 永远不得重叠。

新建 Region/RegionMgr 作为运行时归属；稳定生成序号用于报告，运行 ID 与地图选择分离。查询地区必须含位面信息，不能只用 TileId。OwnedTiles 恰等于平移后的配置键集合。

候选先生成全部计划：地块类型、环境修整、固定地标及单例预留、水文。所有引用、占位与连接均通过后一起提交到候选地图；任一失败撤销全部计划。固定地标不受散布权重影响，仍必须通过存在性、唯一性和占位检查。

独立地标散布仅选择来源为 Fill 且没有地标的格；地区内未配置地标的位置不随机追加地标，固定边界也不参加散布。地标运行身份沿用现有 int，不引入旧规范中尚未实现的 LandMarkId 包装类型；相应 delta 同步唯一标识条文，避免同步后互相矛盾。

### 5. 必需地区优先，有界搜索

先以合法候选数由少到多、面积由大到小、定义 ID 为稳定次序安排必需地区。相同约束优先级内部用专用随机流按适配分数抽取锚点。候选集合可以用环境分桶和占位掩码预筛，避免每次扫描所有类型与所有格。

若必需地区失败，允许撤销本阶段近期地区并换候选；用尽阶段预算后换一次环境子种子重试整图。所有重试受配置预算限制且写入报告。最终失败返回缺失地区及拒绝统计，绝不能把 MinCount 当作“尽量满足”。

可选地区在必需地区之后按 `SpawnWeight × 适配分数` 选择，检查数量和间距。达到软覆盖率目标、合法候选耗尽或预算耗尽即停止。覆盖率分母为 40000 减固定边界格数，分子为所有地区实际格数；最后一块允许略超过软目标。低于目标而硬约束满足时成功并警告。

相比强制完全铺满或无限回溯，保留空隙让基础填充承担过渡，避免搜索时间失控。验证 profile 显式设置有限预算并报告实际耗时，性能阈值由实测决定。

### 6. 基础填充是受约束的加权生长

从已占用格边缘形成前沿；若存在没有前沿的独立空区，按稳定排序选择起点。每轮优先处理合法候选最少的格，同优先级以专用随机顺序交错处理，避免固定方向扫描。

候选必须允许 Fill，满足环境、水文和与已定邻居的双向硬限制。最终权重为基础权重、环境适配、邻接偏好的乘积；权重为零不被抽中，负数/NaN/无穷为配置错误。相邻未定格至少保留一个合法候选，尽早发现死路。

空候选或总权重为零时，在本阶段预算内撤销近期基础填充；不得把未知类型当成平原，不改写边界或地区。最终邻接全量审计通过后，才可选做预算内的孤立 Fill 格修整；每次修整再检所有硬约束。配置可指定相容的宽适配基础类型作为正常候选，但不存在绕过规则的隐式兜底。

### 7. 水系先规划骨架，模板负责兼容

第一版明确区分格内景物和跨格有向图。环境阶段由高程、湿润度和允许的水源规划骨架；处理洼地时按配置选择合法湖泊终点或重试，禁止悬空断流。等高路径使用稳定的排水次序并做环检测，不依靠浮点相等侥幸通过。

地区声明固定内部河段与边缘端口，普通类型声明允许的水文能力。所有覆盖骨架的地区必须完整匹配落点需要的连接；不匹配就换位置，不自动转动作者拼图。这个选择降低首版水文与拼图的相互修改复杂度，代价是涉水地区命中率可能较低，可通过增加作者模板变体改善。

Fill 落实骨架所需的河谷/湖泊等类型与连接元数据。每个陆地河段最多一个下游、允许汇流；出入口互为对侧（方向差 3），最终连到东海或指定内陆湖。局部修补仅可改变允许的 Fill 内容与未锁定连接，不能改固定骨架端点、边界或地区内部布局；改变后重查高程、无环与终点。

通路校验使用独立移动能力 profile，地区模板可声明关键格，生成配置把已落地实例的关键格组织为互通组。桥渡/河流跨越规则作为静态连接条件，不包含运行时建造或旅行。未被要求互通的岛屿、禁地可保留；西墙始终不能作为绕路。

### 8. 候选世界与发布事务分离

生成过程在候选上下文内持有地块、地区、地标、占位、单例预留、随机流和诊断。不能在重试时调用依赖全局位面索引的删除方法来假装回滚。先生成所有实例计划，完成结构校验、初值和快照副本，再在单次发布操作中安装到各管理器；发布失败撤销本次新增索引与快照，不影响已有位面。

初始化顺序为：加载/严格验证地图配置 → 建立并初始化地图依赖管理器 → 生成候选 → 校验及自然初始化 → 准备快照 → 完成人工初值与未来修正绑定 → 原子发布 → 世界其他依赖继续启动。可将 PlaneMgr.Init 的“绑定自身”与“创建主世界”拆开；不能依赖列表里偶然的 Init 顺序。

定义加载器当前会记录异常后继续，所以地图必须有严格审计阶段：文件解析失败、重复 ID、缺引用、错误坐标、非法数值均返回失败。不能把空列表视作成功加载。

主大陆与基础填充使用显式模式。主大陆必须具备完整依赖；缺失配置/管理器直接失败。小位面与旧手工测试可显式使用基础填充模式，保留原 Fill 的补全语义和已有尺寸约定；小位面不强制 200×200。既有 `InitialTiles` 只适用于基础填充/明确恢复路径，不把旧存档通过新大陆生成器重掷。

### 9. 初始元气与未来速率分开

自然初值公式：地块定义 InitialAura + 地区 AuraProfile（一次）+ 自然地标 InitialAuraOffset（一次）。没有地区和地标时对应加数为零。深拷贝写入 CurrentAura，准备自然快照后再应用初始人工地标的 InitialAuraOffset；自然/人工 Modifier 都作为未来每秒速率挂载，不在生成期 Tick，不把速率加一次，也不等待“稳定态”。

拟为 LandMarkDefine 增加 InitialAuraOffset，默认全零；现有 ModifierDefineIds 仍表示未来变化。旧 AuraData 数值保留，不自动转成初值；新增样例在一次性偏移与持续速率上分别显式配置，防止双计。已有数据激活后的长期平衡是数值设计问题，生成测试只验证语义和账本。

修复 TileModifier 构造的 Id、SourceId、Duration、RemainingTime 和 AuraData 深拷贝，使地标清理与生成事务有效。按秒累积的公式和世界 Tick 顺序不在本次重设计。

快照最小修复为 `(PlaneId, TileId)` 复合定位；旧单 TileId 查询明确代理主世界，跨位面必须显式传位面。读取返回副本/只读值。销毁位面、End 与发布失败注销对应数据；全局余额逐位面对照自身快照。失衡权重正负和 AuraDao 的其他历史问题留在原行为边界内。

### 10. 随机隔离、诊断与预览

使用地图专用 Rng，按 worldSeed、生成器版本、阶段名与重试序号通过明确稳定散列派生子种子；禁止 string.GetHashCode() 和无参随机。定义、候选与序列化按固定次序排序。Rng.NewId 仅在提交/身份分配路径使用，其调用数和静态已用集合不能影响地图随机流。

结构哈希按 Offset row/col 的稳定顺序写入类型、来源、地区定义/锚点/稳定序号、规范化环境、水文和固定地标定义/坐标。浮点使用明确精度与文化无关序列化。配置摘要取解析后的规范化内容和语义版本，不纳入文件绝对路径；地图哈希不纳入耗时和临时实例 ID。

拟扩展命令：`--map-generate --seed N --profile <ID> --output <目录>`、`--map-generation-tests`。参数在世界初始化前解析；诊断模式只调用核心生成，不进入 NPC/战斗 Tick。现有正常世界入口使用相同生成服务，不能出现“预览成功、游戏仍是空白”的双实现。

输出每次运行独立目录中的 `manifest.json`、`map.json`、`diagnostics.json`、`map.html`（内嵌 SVG 或 Canvas 视图）；可额外导出 SVG。默认建议放外层已忽略的 `docs/world-map-preview/`，也允许明确输出路径。成功清单最后发布，失败使用独立失败报告；重跑不把旧成功文件当作新结果。

预览展示全图、缩放、图例、地区边界、选格详情和环境/来源图层，标签安全转义。HTML 内嵌导出数据，避免本地 file 页面跨文件加载限制。候选拒绝统计聚合计数并保留有限样本；选格需要的填充决策记录保留，避免对每次拒绝输出海量日志。

### 11. 验证与最小内容集

沿用 Console 静态 Run() 测试，新增地图测试集与 JSON 批量审计脚本。微型失败夹具只测局部规则，最终验收必须使用 200×200。

- 配置：至少包含旧七类映射及林山、荒山、火山、雪山变体；固定边界验证模板；普通山地、湿润林山、干燥荒山、涉水山谷四类完整地区，包含不规则轮廓/孔洞样例和自然地标。
- 坐标：同一模板在奇偶行锚点平移保持邻接；四角越界整块失败，孔洞不占地。
- 事务：唯一地标冲突、缺定义、无填充候选、水文断口、必需地区无解都失败且无全局残留。
- 语义：软覆盖率不足只是警告；零权重不被选；自然初值与人工初值的快照顺序、modifier 来源清理、位面同坐标隔离和深拷贝。
- 复现：固定验收种子集建议 1..20，完整运行；两个独立进程同 seed/config/version 比较，再做同进程 B→A 与干净 A 比较。记录实际内部差异，不把“任意两种子必不同”当契约。
- 集成：核心/Console 构建，现有 `--core-smoke-test`、背包/模板相关回归覆盖 WorldMgr 初始化变更；用生成诊断与真实默认世界入口核对同种子地图摘要。

## Risks / Trade-offs

- [拼图条件过严导致无解] → 硬条件与软适配分离、候选数报告、有界回退；必需地区失败明确暴露，内容作者可调规则。
- [先定水系降低涉水拼图命中率] → 报告端口拒绝原因，配置多个固定模板变体；首版不自动改作者布局。
- [填充邻接限制互相矛盾] → 双向检查、一步前瞻和局部回退；无合法候选时失败而非无规则兜底。
- [四万格生成拖慢默认启动] → 阶段预算、候选预筛、独立诊断计时；集成阶段实测，不先承诺未经验证的毫秒指标。
- [旧规范格式妨碍同步] → 先仅规范化本次修改的九个能力结构，保留每条旧正文，再应用本变更 delta；检查修改标题存在且没有丢失未修改要求。
- [旧数据字段变化] → 先生成迁移报告和新输出，再替换受影响 JSON；保留旧枚举适配及原始备份，拒绝未知值。
- [自然地标速率被误当初始浓度] → 独立 InitialAuraOffset，零默认与明确数值夹具；保持现有 Tick 公式。
- [快照复合键扩大改动范围] → 只改定位/生命周期与兼容查询，不改天道权重或事件机制。

## Migration Plan

1. 为本次九个受影响主能力补主规范标题、Purpose 和 Requirements 结构，不改原条文行为；建立标题/场景清单，保留未修改要求。只在实施阶段执行。
2. 批量审计现有 JSON 和源码引用；旧数字 0..6 显式映射到 `plain/hill/mountain/river_lake/ocean/desert/forest`，复制旧七类基础元气值作为迁移初值。
3. 地区只迁移原 TerrainLayout 实际键；旧 8×8 外接框未列出的格不自动补为地区。将 IsGuaranteed 转 MinCount；地标类型过滤转 ID，ExtraTerrainIds 保留为普通地区语义标签，不新增未实现的 ExtraTerrainDefine 系统。
4. 新配置写 SchemaVersion，迁移脚本支持检查/预览输出，重复运行不会再次转换；混用新旧字段或未知值时报错。现有 modifier 值不自动搬到自然初值。
5. 接入生成内核、诊断、严格校验和样例，再接默认世界启动。完整 seed 集与回归通过后完成文档同步；生成产物不进入 Data/Scripts。
6. 回退按同一提交边界恢复代码与受影响 JSON、配置版本；已生成地图按清单的版本读取，不能用新生成器静默覆盖旧地图或宣称兼容尚未实现的存档格式。

## Open Questions

- 固定边界具体厚度、四角形状、南部雨林与沙漠分布；验证模板明确标为开发样例。
