# Tasks

## 1. Core 资源源与预加载

- [ ] 1.1 建立 Core 资源源契约，接入引擎随包资源和游戏安装根的 `src`，并接受由启用包列表传入的 Mod `src`。验证给定相同列表，控制台及 Godot 都能独立于 Define 查询资源来源，游戏根无 `src` 时照常启动。
- [ ] 1.2 扫描并预载各源支持的资源，按配置的顺序解析同路径覆盖，在世界和编辑器接入生命周期。验证三个来源同名资源的结果、`src/` 可选前缀、越界诊断、未引用资源预载和切换目录后释放缓存。

## 2. 卡图外置与客户端实例池

- [ ] 2.1 将 10 张独立卡图和长剑卡使用的玉剑副本放到仓库根 `src/cards/`，同步正式映射和素材台账。校验 PNG 内容、长剑裁切与转置，以及旧预览对原玉剑图的读取。
- [ ] 2.2 用 `AssetMgr` 解析映射中的相对地址，Godot 共享同一来源和版本的纹理，接通卡库、背包、待发、对拼及详情。验证所有 11 项正式卡图，去掉对拼场景对旧卡图位置的引用，验证缺图时显示名称。
- [ ] 2.3 完成 Godot 全局实例池及卡面控件、Spine 演员的借还。验证空池借出、同键复用、上限调整、跨场景归还和状态重置。以同时借出 20 个、空闲硬上限 12 个的场景确认借出和回收数量。
- [ ] 2.4 将外部 `src/cards/` 纳入发布目录交付。分别从工程和发布目录启动验证，替换同路径的一张图后重新加载，确认各界面读取同一新图。

- [ ] 3.2 增加 `NpcDefine.Appearance`，实现逐槽资源和颜色解析，将两个演示预设展开写入既有测试模板。验证短地址、默认色、显式留空、缺项、错误颜色与旧 JSON。
