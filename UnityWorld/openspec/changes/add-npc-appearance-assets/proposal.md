# Proposal

## Why

模板编辑器已经能按部位换装、染色并在试战中展示。让外观选择进入 NPC 定义和实例后，同一个模板可以通过标准 JSON 交给世界生成、试战或 Mod 使用。现有卡图也需要支持从安装目录替换，并作为验证资源预载和客户端实例复用的一组真实素材。

## What Changes

- 扩展 Core 的 `AssetMgr`。游戏随包资源、安装根目录的 `src`、已启用 Mod 的 `src` 都作为内容包资源源注册，启动时按挂载顺序建立统一目录并预加载。引擎宿主提供随包资源的读取方式，`ModMgr` 提供启用包及其顺序。
- 把现有正式映射的 11 项卡图迁到安装根的 `src/cards/`，由 `AssetMgr` 统一查找，Godot 共享已解码的纹理。长剑卡使用玉剑副本，原图继续供旧素材预览使用。
- 由 Godot 全局宿主持有客户端实例池，卡库卡面控件和 Spine 演员借用并归还实例。各类实例初始数量为 0，空闲保留量随并发峰值增长，并支持设置硬上限。
- 由 Game 根据可用资源建立外观目录。每个组件对应一个插槽。`NpcDefine.Appearance` 按插槽填 `hair/jade` 等相对地址及可选染色，没填的插槽从本槽可用项中随机选，省略染色时使用原色。
- 在现有出生及模板装配流程中解析外观，`NpcAppearanceData` 保管选中的骨架、各槽资源地址及染色。模板编辑、正式导入导出和试战使用同一套外观规则。
- 将演示人物的固定部件写进对应 NPC 定义。兼容缺少外观字段的旧定义、个人草稿和已有试战输入。

## Capabilities

### New Capabilities

- `appearance-asset-preloading` — 三类 `src` 来源的挂载、预加载、共享资源、客户端实例复用，以及 NPC 外观对目录的使用。
- `npc-appearance` — 按插槽配置、出生时选定、实例保存及战斗展示。

### Modified Capabilities

- `character-template-library` — 标准 NPC JSON 保留可装配的部位及染色。头像、预览操作和界面状态继续作为个人展示设置保存。
- `client-card-assets` — 正式卡图从外部 `src/cards/` 加载，模板库和战斗界面使用同一解析结果。

## Impact

涉及核心资源生命周期、Mod 包列表接口、外部卡图发布、Godot 实例池、NPC 定义与生理数据、模板导入导出及战斗观察器。外观接入复用现有 Spine 骨架、动画和回退展示。手持装饰独立于实际装备，出生的身高继续由原规则生成。
