# Design

## Context

周结算已经沿 `WorldMgr.AdvanceWeek() → PlaneSystemNpc.AdvanceWeek() → NpcSystemBehavior.OnWeek()` 运行。世界负责快照成员、推进日期和发布完整结果。位面按出生顺序遍历。角色行为系统持有唯一的主行为槽。现在只有周模式的 `MoveBehavior` 能在这个入口推进，空闲角色抽中自身格就返回 `waited`。这次调整选择的顺序，动机见[提案](proposal.md)。

`NpcSystemPosition` 管理落地与到达。地形的 `TileDefine.EncounterRefs` 已预留，当前 26 个地形的遭遇引用均为空。`BehaviorCardMgr` 可以把已定义的行为卡授予指定角色。默认启动会加载行为卡定义，通用 Story 和 Option 定义的加载入口尚未启用。

## Goals / Non-Goals

让手动指定和 NPC 自主决定的 Move、Explore、Work 共用同一套启动校验和周执行规则。保留旧行为卡的秒制构造、主次槽和生命周期。此次只做本格事件到行为卡的最短通路，具体事件内容、人格决策、远程寻路、次要行为的周玩法和 Godot 交互各自后续设计。

## Decisions

### 1. 先接续主行为，空闲时才选择

`NpcSystemBehavior.OnWeek` 先核对角色存活、位面成员、实际位置和位面状态，再读主槽。已启动的周行为直接推进。旧秒制主行为占槽时返回 `busy`，其完成依然由秒 Tick 负责。只有主槽空闲且本格有效时才执行以下决策。无论这周结束、受阻或出错，处理完这个角色便将控制权交还位面。

在原有选移动目标的代码位置预留三个空函数。注释要写在函数体里，交代将来要填什么、能看哪些输入、输出交给谁。复用 NPC、位面、当周序号和只读候选列表即可。

| 空函数的职责 | 接收与返回 | 当前行为 |
| --- | --- | --- |
| 目标点喜好 `GetPreferredDestinations` | 根据角色和地图上下文，提供零个到多个想去的位面与坐标。意向点可以远于一步，也可供后续多次空闲决策参考 | 输出集合保持为空 |
| 行为决策 `SelectWeeklyBehavior` | 读取角色、意向点和本周可执行的选项，填写最多一个选项。以后若选项来自行为卡，可指明选中哪一张 | 输出保持未选择 |
| 短期移动目标 `SelectMoveTargetByStrategy` | 仅在 Move 被选中后调用。读取意向点与可走邻格，填写一个落脚格 | 输出保持未选择 |

默认选择写在调用处。第一层按固定顺序枚举可执行的 Move、Explore、Work，分别给一个等概率名额。Move 需要至少一个可走邻格，Explore 和 Work 只需要角色能在本格行动。第二层只在 Move 的合法邻格里等概率抽一格。将来策略明确返回了非法行为或非法落脚格时，记录该 NPC 的 `decision_error`，避免回退随机掩盖策略错误。两个选择和本地遭遇各用独立随机用途，复用 `PlaneSystemNpc.CreateRandom` 的世界种子、位面、出生序号和周序。邻格沿用六方向顺序。把随机写进三个空函数会让后续人格逻辑接手时难以判断是否已有选择。

例如，六个邻格可走时三个主行为各为 1/3，走向其中某一格的总概率为 1/18。只有两个邻格可走时 Move 仍为 1/3，每个邻格为 1/6。移速为 0 或所有邻格受阻时，Explore、Work 各为 1/2。意向点距角色 5 格时，未来策略仍只能把一个合法邻格交给本次 Move。

### 2. 手动启动与过周分开，沿用原位置和主行为槽

保留 `NpcSystemPosition.GetMoveCandidates(id)` 的公开查询语义。原有调用方可继续看到自身格及合法邻格。Move 在构造本步候选时剔除自身，并在启动时复查实际位置、目标、通行与有效速度。自主选择和显式命令共用这一校验。Explore、Work 的目标直接取角色当前位面和所在格，主槽空闲、存活、已在活动位面落地且本格有效即可启动，速度为零也可执行。

`TryStartMove(id, target)`、`TryStartExplore(id)`、`TryStartWork(id)` 只登记周主行为，成功时供调用方查询待执行状态。拒绝时保留原槽、日期和坐标。世界在 `AdvanceWeek()` 内通过已有内部提交路径启动自主行为，当周立刻推进一次。此处应注明公开启动方法受 `WorldMgr.EnsureMutable()` 保护，内部提交必须复用资格检查并避开对外重入入口。行走标记只由周 Move 启动和释放时设置。位置写回仍归 `NpcSystemPosition.Arrive`。

例如，显式开始 Move 时进度为 0。速度 50、相邻距离 100，过第一周仍在原格并完成 50，第二周到达并空闲。期间提交 Explore 会被拒绝。速度 150 时当周到达，多出的 50 随本周结束。将来接移动事件，可根据本次真实推进或到达结果确定触发时机，具体事件和概率留给移动玩法。显式开始 Work 时仍是原日期，过一周才得到工作结果。本周即使还有邻格可走，也不再选一次。

### 3. 周模式属于行为实例

将既有 `MoveBehavior.IsWeeklyManaged` 的判断扩展到行为基类，供主槽、秒 Tick、观察和清理共同使用。既有 Move 与 Explore 的秒构造仍走原来的故事生命周期。周 Move 保留来源、目标、距离和进度。周 Explore 与新增的 `WorkBehavior` 记录开始时的位面和本格，一个世界周就结算完。行为工厂显式识别 Work，旧卡按配置 ID 和持续秒数创建旧模式实例。Practice、Social、自定义 Extra 的周执行另行设计。

秒 `OnTick` 在推进及检查 `IsFinished` 前跳过周主行为。已有次要行为列表照常在秒 Tick 中逐个推进与结束。单独调用 `WorldTime.AdvanceWeek()` 依然只动历法。周边界直接提交周结果，绕过旧秒行为的 OnStart、OnTick、OnEnd 故事回调。把一周折算成秒会使旧探索卡的概率随 Tick 次数变化。注释应放在模式分支和周清理入口旁。

例如，一个角色主槽是周 Explore，同时带有一个旧次要行为。调用 3 次秒 Tick 只推进次要行为，再调用一次世界过周，Explore 才在本格处理 1 次。旧“探索四方”卡创建的秒制 Explore 遇到世界过周仍返回 `busy`。

### 4. Explore 读取本格遭遇，Work 只记一次工作

Explore 在执行业务前复查 NPC 仍处于启动时的位面与格。通过 `Plane.GetTile(position.TileId)` 查真实格，以 `Tile.TypeId` 读取地形定义的 `EncounterRefs`。只在这些引用内作一次本地选择。引用为空，或本次未命中，均记作已探索、无发现。命中时保留事件 ID。遭遇可选地授予一张后续行为卡，由 NPC 持有并留待以后使用。Work 越过遭遇选择，直接完成本周工作，坐标、持卡和资源均无变化。

在现有数据加载位置接一份独立的小型遭遇配置。条目用事件 ID 关联地形引用，包含可配置的命中率和可选的行为卡定义 ID。当前格若有多个有效引用，只抽取其中一个候选并判断是否命中，一次失败即结束本周探索。命中率为 0 或 1 时，分别能稳定验证无发现或命中。正式地形允许全部留空。验收以外部配置提供一个确定可命中的条目，测试可直接控制是否发现。真实内容与正式遭遇率由以后配置。这样可验证事件与卡的关系，也无须恢复整个 Story/Option 加载、全局标签匹配或建设一套叙事解释器。缺少事件或卡定义属于配置错误，应在装载或过周预检时明确指出来源与错误 ID，避免把坏引用记作正常无发现。

实际授卡交给 `BehaviorCardMgr`。现有 `GiveCard` 遇缺失定义会记录日志并返回，内部发卡路径要能向周结算确认写入成功，再把卡 ID 写入结果。保留旧调用入口。授卡、结束 Explore 和提交该 NPC 结果在同一轮完成。`WeekCompleted` 只观察，不能订阅通知再发一次。此处应注明获得卡与使用卡是两次操作。

例如，测试格 A 引用事件 E，邻格 B 引用事件 F。E 确定命中并授予行为卡 C 时，角色在 A 过一周得到 E、C，C 的持有数增加 1、使用次数为 0。若只在 B 配 F 而 A 留空，角色在 A 仍完成 Explore，事件与卡均为空。命中一个无卡事件时只返回事件 ID。在同一个 A 改为 Work，只返回本周已工作。

### 5. 查询、异常和周结果

`NpcActionSnapshot` 表示查询当下的真实状态。保留既有 `idle`、`move`、`busy` 和移动字段，补充待结算的 `explore`、`work`。距离和进度只由 Move 填写。扩展 `NpcWeekResult` 时保留 Before、After、目标和已完成移动进度等旧字段，另行记录本周执行何种行为、Explore 是否命中、实际发生的事件 ID 和成功授予的卡 ID。按现有结果风格区分 `explored`、`worked`、`moving`、`arrived`。周末都可能是 `idle`，控制台和上层应读当周结果来区分。快照和结果只包含值或只读副本，读取不重新掷骰、不发卡。

世界沿用稳定的成员快照。新增成员从下一次过周才参与。结算时已死亡、未有效落地或不属于该位面的快照成员返回 `skipped`，当前绑定失效的周行为清理。主动离位、注销沿现有位置/行为清理入口释放绑定。未激活位面跳过当周，不推进、不触发事件。已锁定的源格失效或移动目标受阻返回 `blocked` 并结束该周行为。不在同周补选 Explore/Work。非法选择或单个角色的非法数据记录该角色的结果，让其余角色继续。沿用 `WorldMgr` 的提交界线，过周前的配置错误不消耗日期，日期提交后若内部故障令整周无法完成则返回 `Complete=false` 并阻止盲目重试。

例如，一次推进处理 20 个 NPC 时世界仍只过 1 周。甲死亡被跳过，乙完成无发现的 Explore，丙完成 Work。乙和丙的 After 都是 `idle`，两条周结果记录不同的行动。观察者重复读取乙的结果 2 次，乙的持卡数不变。

## Risks / Trade-offs

- 旧测试或演示按 `waited` 统计自行停留。同步改为统计本周完成的 Explore 和 Work。涉及目标权重的断言改为两阶段概率，保留公开候选包含自身的回归检查。
- 直接给所有主行为贴上周标签会令旧卡停止推进。测试同一行为 ID 分别由旧卡和周命令创建，交错调用秒 Tick、纯历法与世界过周，覆盖已有次要行为。
- 开发样例全空会让授卡路径在普通地图上不可见。保留无内容的真实地图场景，再用带已知地形、事件及卡配置的测试世界验证一条成功路径和无卡事件。
- 进入主槽后又被外部换位会使本格事件串到别处。普通放置与主行为打断沿用行程保护，离位或世界结束显式清理。执行前再次核对绑定。

## Migration Plan

先补周行为模式、三个选择位置和兼容的显式入口，再接 Explore、Work、最小遭遇配置和观察结果。更新控制台演示及原有移动说明，在发生变化的选择、时钟、发卡位置写注释，交付时逐一说明改过的原文件。下列命令从 `UnityWorld/` 运行。

```powershell
dotnet build Console/UnityWorld.Console.csproj
dotnet run --no-build --project Console/UnityWorld.Console.csproj -- --npc-movement-tests
dotnet run --no-build --project Console/UnityWorld.Console.csproj -- --world-calendar-tests
dotnet run --no-build --project Console/UnityWorld.Console.csproj -- --npc-movement-demo --seed 12345 --npc-count 20 --weeks 8
```

在现有周行动测试入口加入手动与自主启动、无合法邻格、本格有无事件及授卡、越周边界和两种时钟的用例。固定种子重复运行的结果应一致。自动选择分布用可执行行为集合及六邻格/二邻格的理论概率核对，避免以少量抽样次数作为验收阈值。

本提案引用的 `npc-movement`、`world-weekly-simulation` 基线目前在 `add-npc-weekly-movement` 的增量中。向主规格同步或归档本变更前，先将该前置变更同步到主规格，然后在同名需求上应用本次修改。实施回退可按同一变更恢复旧决策入口及配套结果、样例和测试。本变更不引入存档迁移。
