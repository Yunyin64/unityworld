# 用 Main Keyword 决定卡牌运转方式

## Why

现在卡牌的 Keyword 同时承担分类、发动入口和效果，同一张卡在装配和战斗里可能得到不同的发动资格，法宝事件还会绕开背包的行额度。把核心规则收在唯一的 Main Keyword 上，让配卡时就能确定一张卡怎么运转、和谁争用同一行的灵元发动机会。

## What Changes

- **BREAKING** 在 Keyword 定义上标记 `Main`。每张 Card 都必须恰好有一个 Main，创建或读入时校验。法术、法宝、被动、招式是本次的四种 Main。伤口、物品、丹药仍是普通 Keyword。只占格的伤口可以使用空的被动 Main。
- **BREAKING** 法术、法宝、招式都在完整扫描到本卡末格时检查满灵与使用资格。一次成功发动使用本卡已经蓄满的灵元，并占本方该行的唯一额度。被动入场即生效。以法宝激活或续期替换原来的事件直接发动。激活产生的被动保持到下一次扫完本卡，当场续不上就关闭。
- **BREAKING** 招式由装备自带并绑定具体装备实例。装备决定招式列表和攻防底值，招式决定如何运用这些属性对拼。每件已装备装备带出的招式都须摆进战斗背包。每张招式卡默认每包扫描轮成功发动一次，独立于同名招式以及父法宝的被动激活状态。

### New Capabilities

### Modified Capabilities

- `keyword-system` — 规定唯一 Main、四个 Main 的运转分工、法宝激活周期及招式每轮次数。
- `passive-card` — 规定常驻被动的生命周期，容许没有效果的被动卡。
- `combat-backpack-scan` — 规定三种 Main 共用一行一次的发动额度、末格检查和灵元提交。
- `combat-backpack` — 更新主动蓄灵范围和装备自带招式的背包装配规则。
- `combat-contest-scheduling` — 用统一扫描发动衔接现有待发槽，法宝激活本身不入槽。
- `combat-status-effects` — 更新冻结对末格续期和已激活被动的规则。
- `npc-template-backpack` — 在模板显式坐标下检查装备自带招式是否齐全、绑定是否有效。

## Impact

卡牌定义、旧存档和程序生成的卡牌需要兼容唯一 Main 的约束。模板验证、正式装配和战斗需要用同一个 Main 判定。现有法宝卡的事件发动脚本要按激活期内的被动重新描述，招式卡需要有效的装备来源和背包位置。现有卡牌与装备的逐张迁移，以及具体效果的数值设计，留到后续设计和实施。

现有 `zhaoshi-rotation` 草案记录的是串行 CD 方案，本变更的招式以背包扫描和每轮次数为准。
