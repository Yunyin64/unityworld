# 现有 TCA 接口对齐

## Context

卡牌和 Modifier 通过 Lua Hook 与 `[APIFunc]` 执行效果。TCA JSON 保存供策划引用的触发和模板。Main Keyword 决定卡怎么发动，事件可以为已启用的效果提供结算时机。

## Goals / Non-Goals

现有目录每个可选条目有对应的 Lua 入口、有效的参数和可验证的结算。保留旧脚本依赖的兼容入口。本变更限于通用 TCA 和现有五行状态，新增卡牌效果、几何相邻和背包换位后续单独设计。

## Decisions

1. 触发目录登记战斗广播。区分实际事件和卡牌局部 Hook。保留攻击事件的派发行为，胜负用带结果的 `OnContestOverflow` 选择。按代码列出基础补灵、抽灵、伤害、治疗与 MP 变化的时机。
2. 选择模板调用 `SelectCards(ctx, Domain)`，直接返回类型一致的列表。复用现行 Domain。选择本方或对手随机一张时，无目标返回空列表。现有“相邻”模板明确命名为场上前后一张。
3. 从可选动作目录移除位移、候补部署和召回，保留兼容 API 的现行拒绝。补齐直接增减 MP，校正拼点、冻结、移除伤势及抽灵的描述。让动作参数名与 Lua 参数一致。需要从数据或角色上下文选取的 Buff ID、属性 ID 使用现有参数表表达，由使用者指定合法值。
4. Heal 只恢复实际缺少的 HP，事件表示已经结算的正向回复。浩瀚使用 `RecoverMP(ctx, "Self", n)`，先补 MP，再按基础补灵规则放置灵元。
5. Lua 包装由显式开发操作更新。运行时读随 Data 发布的包装。测试覆盖配置到已发布 Lua 再到战斗结算。

## Risks / Trade-offs

- `OnAttack` 仍可在输掉对拼或直击时派发。需要胜负的效果须读取对拼结果事件。
- 旧 `Adjacent` Domain 按场上顺序工作。二维共边属于独立的背包选卡需求。
- 可选目录的退役 ID 从配置移除。旧草案引用可查版本历史，旧 Lua 范围函数和禁用动作继续保留原入口。
