# Design

## Context

地图加载器 `MapCatalog` 同时读取单文件和递归目录中的定义，按 `TerrainLayout` 的相对 Axial 键确定真实占地。现有 `ExplorationHexProjection` 已负责从六边形坐标到屏幕位置的双向转换。

## Goals / Non-Goals

编辑工具独立于运行中的世界。保存后的定义在下次加载地图时由现有生成器消费，地图生成参数继续由现有定义和默认配置控制。

## Decisions

1. 首页入口与角色模板编辑器同级。左栏把常用字段放进表单，按主题提供其余字段的 JSON 编辑。保留原始文件中已配置的值，避免把默认值和旧模板省略的字段批量写回。
2. 中间画布沿用探索的六边形投影，显示原点、占地、地标和关键格。拖放 Tile 或选中地形后点击画布时，只写落点。擦除动作可撤销，相关定义由作者通过左栏调整。
3. 右栏按 `Tags` 和 `WaterKind` 生成过滤项，关键词匹配名称、ID、描述和标签。色块取 `Color` 与 `Symbol`，配置了有效 `AssetRef` 时通过共享图片入口加载。
4. 已有 ID 固定，复制模板可以为新 ID 另存。持有来源路径和读取时的快照，写入前让 `MapCatalog` 在内存中试读拟提交的文件版本。正式文件同目录暂存后替换。归档在写入前备份原文件，启动时只读取活动定义。

## Risks / Trade-offs

- 编辑后通过静态校验的模板仍可能影响部分种子的地图生成。校验反馈明确其范围，世界在重新加载定义后使用新值。
- 固定世界锚点属于放置安排。复制时清除 `ForcedPositions`，作者可在高级字段中重新设置，避免复制件自动争用原模板的锚点。
- 多条定义可能共用一个文件。只替换或移除目标记录，保留其他记录。涉及旧全局生成引用的模板依正式校验决定能否归档。

## Migration Plan

既有区域 JSON 可直接打开。省略 `Description` 的模板继续使用版本 2 的默认读法。归档备份含完整原始来源，文件恢复需核对当前来源中的其他记录。
