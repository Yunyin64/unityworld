# 打木桩实施与验收

## 1. 提供稳定的承伤对象

- [x] 1.1 新增同 ID 的木桩专用白板功法与单格被动功法卡，以及引用它的木桩模板。通过模板预检和装配核对开场 20 HP、30 MP、SP 1/10，唯一场上卡在 (3,3)，功法无战斗效果及解锁子卡。
- [x] 1.2 只对木桩实例将基础补灵覆盖为 0，记录覆盖值。验证开场和下一轮木桩均不补灵，MP 保持 30；用两次各 10 点伤害验证第二击出一格伤口、占用增至 2/10，再验证 SP 超限按真实规则结束。

## 2. 逐条采样，由 LogMgr 在战后导出 Markdown

- [x] 2.1 在开场前安装场景内观察，以伤害结算、用卡实付、本方轮末和伤口落盘为来源累加；用全盾吸收、扣血后同步回血、多次受击、自伤、无来源伤害及直接授予伤口核对双方归属和两个首次 Tick。
- [x] 2.2 在实际 MP 变动提交处记录带符号的改变量。用同 Tick 扣 5 回 2 验证消耗 5、回复 2、余额少 3；用已蓄但未付、法宝续期和同 Tick 多轮验证灵元实付分色与本方完整轮数。
- [x] 2.3 增加可编辑的条目清单和指标字典，按 ID、观察方、指标和时机调度。验证只配置「50 Tick 伤害输出」「100 Tick 伤害输出」时只写两条，加入同 Tick 的 MP 条目后只多一条；覆盖开场、终局、提前结束、键名冲突和非法配置。验证伤口分别在 75、90 Tick 落盘时，即使仅采样 50 和 100 Tick，firstWoundTick 仍只有一行且值为 75。
- [x] 2.4 在同一输入上比较密采、疏采和关闭快照三种运行，核对终局及共享节点；连续创建、结束或中断两个场景，核对无跨场计数且现有逐局战报仍可读取完整事件。

- [x] 2.5 给 LogMgr 增加按场暂存的离线快照入口。分别在诊断开启、关闭、普通文件写出关闭时测同一场，对照原始读数一致，并确认快照行未出现在控制台、普通日志文件、历史或普通回调中。
- [x] 2.6 在正常、提前、达到上限及可控异常的收尾路径自动保存一场一份 UTF-8 Markdown。逐行核对设计中的完整八行样例，表头只有「条目ID、值」，damageOut_100 为字面量 null，firstWoundTick 为 75，FinsihTick 和 Finishreson 独占最后两行。验证首次伤口未发生时为 null、开场发生时为 0，单场文件中只有键值表。验证同种子重跑保留两份文件、目录不可写时报告失败。

## 3. 批量比较并保留复测条件

- [x] 3.1 在模拟入口增加木桩基准参数、已有对手选择、种子清单以及逐样本独立初始化。用短种子清单核对一项一局、固定角色顺序、错误反馈；普通入口继续按原参数运行。
- [x] 3.2 记录运行清单、木桩模板及实例覆盖、数据与程序集指纹、条目清单与口径版本、单场 Markdown 相对路径、终点和单局异常。在同条件批次中抽一局单独复跑，比较所有读数与结束原因；验证输入版本变化不会混入同批。
- [x] 3.3 从已落盘的 Markdown 快照按对手和条目 ID 生成覆盖数、均值、最近秩分位数和首次事件发生比例，并随报告给出指标字典。用有零值、无人到达、无人受伤及 80/100 局有效到达的手算样例核对分母与结果；验证新增字段与旧报告缺项都可识别。
- [x] 3.4 在战斗模拟技能说明中加入基准命令、增添一个 Tick 测项的配置示例和报告读法，用文档命令运行一局，关掉进程后打开自动生成的 Markdown，并从批次 JSON 定位同一份文件。核对默认测项、固定行顺序，以及增添一个配置只新增一个键值对。

## 4. 验收完整的构筑测量流程

- [x] 4.1 构建 `dotnet build UnityWorld/Console/UnityWorld.Console.csproj`，用一个正式修士对木桩跑默认 100 场，检查种子唯一、每场结束即有对应 Markdown、每个节点覆盖数可对账，并单独复放第 37 局。再用相同种子和节点对指定已有修士跑 100 场，验证两份报告能按相同角色视角逐点比较。
- [x] 4.2 复跑已有模板对战的资源追踪，核对原报告仍按原口径产出；在新报告抽取一局，对照实际伤害记录、实付五行及轮末验证累计曲线，并用仅含单场 Markdown 和运行清单的输入重建相同汇总。
