# Proposal

## Why

地图生成初版已归档，但低海拔不会自然成为海域，湖泊只有类型而没有完整湖体，河网缺少细支流和宽度；固定地区的整片常量环境、最近锚点过渡和排水时改写海拔又加重了图层的割裂。需要在保留 200×200、固定锚点和作者拼图的基础上，补齐水域规划与连续环境，让地图预览和真实世界获得相同的可验证结果。

## What Changes

- 将最终自然海拔严格低于 `0.05` 的非固定格预留为海域，使用海水类型补齐；固定拼图保持作者类型。海域判定先于普通地区和随机填充，不再被“未在河道中心线上”排除。
- **BREAKING**：新内容统一使用 `river / lake / ocean` 三种同级地块类型；旧 `river_lake` 显式迁移为 `river`，保留原河类型的初始元气和已配置效果，未知映射明确失败。
- 制作开阔平原湖、狭长山间湖、湖群湿地三份固定内部布局的地区模板。开发预设各完整放置一份；湖体先于河网建立，支持明确的过流湖和封闭终点湖，不能只放一个终点格冒充大湖。
- 根据稳定排水方向和湿润度累计汇水量，生成主河及更细的支流；河道连通图与占水格范围分开，主河按流量扩宽，不能覆盖已经锁定的作者内容。
- 对全图（包括固定地区内部）生成连续环境；固定地区保留基准与允许范围，叠加按世界坐标采样的稳定变化，多个影响平滑混合，不逐模板重置噪声。
- 自然海拔与排水辅助高度、湖面水位分开，水系计算不再直接抬平展示用海拔；温度按最终自然海拔计算，保证环境数据一致。
- 降低腹地普通地区密度并增加不同类型地区之间的实际占地间隔；四周边界仍连续。开发预设建议普通陆地覆盖目标 25%、间隔 2 格、支流 1 格和主河 2～3 格，均保留为可调参数。
- 诊断增加水体分类、湖体、汇水量、河宽、自然／排水高度与地区间隔信息；环境图层可独立关闭地区轮廓，提供同种子前后对比及批量数值报告。

## Capabilities

### New Capabilities

无；复用现有能力，避免另建重复水文或世界配置体系。

### Modified Capabilities

- `terrain-type`: 分离河／湖／海类型，迁移旧河类型 ID，明确水体资格与陆地环境权重的边界。
- `world-environment`: 全图连续采样、固定地区内部变化、多个锚定影响平滑混合，以及自然海拔与排水高度隔离。
- `world-hydrology`: 海平面分类、大湖水体、过流／终点、汇水支流、河道扩宽与有向连通校验。
- `region-system`: 水文地区先放、三份大湖样例、跨类型地区的占地间隔和普通陆地覆盖率。
- `world-generation`: 调整阶段顺序，保护水域与固定内容，沿用失败回滚和自然地标→快照→人工地标的创建顺序。
- `plane-generation`: 使大陆创建入口遵守新的水域阶段顺序，基础填充模式继续保留。
- `world-generation-diagnostics`: 可解释水域选择、河湖指标、环境连续性与真实入口一致的地图预览。

## Impact

- 核心预计涉及 `Scripts/Game/Domain/Object/Plane/Generation/`、地图结果 DTO、`Tile` 的只读投影，以及 `World/WorldGenerationOptions.cs`、`WorldGenerationPresets.cs`、`MapCatalog.cs`。继续使用普通算法参数，不恢复独立世界生成 Define/Manager/JSON。
- 数据涉及 `Data/TileDefines/`、`Data/RegionDefines/` 与作者／审计脚本。三份湖泊模板各用小文件，布局适度合行；不展开世界坐标格列表、不在本次引入地区运行时玩法。
- 更新现有 Console 导出、HTML 图层、地图专项测试和配置说明；保留共享 C# 核心、基础填充模式、整数实体 ID 和已有元气运行语义。
- 本次为离线创世生成改进，不包含季节、洪水、蒸发、侵蚀、动态海岸、角色移动、桥梁建造或 Godot 正式地图界面。旧生成结果继续作为历史证据，新生成器使用新版本与摘要，不静默重掷旧结果。
- 本提案只创建计划文档；数值预设和模板造型可在实施及预览验收时调整，不代表正式世界地理设定。
