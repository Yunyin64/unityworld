# 基础战斗机制设计

## Context

当前行边界先匹配双方待发槽，轮末再强制单方结算。现有长剑在实际配对前修正招式，现有胜差广播在结果产生后派发。伤害已有修正及护盾吸收入口。背包坐标及格上灵元均存在战斗快照中。世界侧消耗已有 Stack 和 StackMax 字段，尚无完整的开战读取、主动扣次和实战回写路径。

## Goals / Non-Goals

- 策划能以现有 TCA 配置和 Lua 包装编写完整效果。所有效果由已有战斗阶段驱动，并保留确定性重放。
- 旧独立 CD、旧线性位移、候补部署和召回继续按当前兼容行为处理。装备速度作为装备实例数值供招式读取，背包时钟继续使用现有节奏规则。

## Decisions

1. 拼点必须有三个不同的阶段。当前待发可在槽中修改，双方实际配对时可在比较前修改，胜差监听只读取结果。保留长剑的局部配对 Hook 和原有胜差广播。给公共配对事件提供两个角色、两张卡与类型，写操作通过动作访问当前阶段。所有点数修正完成后才判胜负，数值最低为零。
2. 轮次归目标角色。统一使用本方轮次作为拼点、亲和、装备和状态的可选到期单位。轮末伤害及离场结算完成后派发轮末事件和到期清理，然后进入新轮。第一轮也派发轮开始。支持监听在未来轮开始发放收益，调用方通过注册效果携带其来源和剩余次数。
3. 卸力、护甲、坚甲、法宝供能及五行亲和变化使用角色现有战斗 Modifier 和数据定义。相同 ID、相同到期轮的效果合并。卸力和护甲分别消耗于第一次符合条件的对拼或伤害，坚甲保留到目标本轮结束。伤害先应用既有管线与新增固定减伤，然后扣灵盾，溢出再扣 HP。灵盾使用现有护盾值。
4. 装备由实例绑定。战斗对父装备 ID 持有本场攻防速修正，招式与装备本身读取同一有效值。用角色战斗 Stats 处理五行亲和，调用现有抽取管线，使基础补灵与主动抽取都能看到有效权重。
5. 法宝供能是在轮首补充卡上蓄灵。用现有接收资格筛选五行缺口，再用场景 RNG 从合格法宝和可接收元素中选择。它允许在空间不足时仍产生供给，不改变格上抽灵和扫描进度。准备和灵活作为普通 Keyword 注册，均须与 Consume 配合。
6. 备战配置沿用现有 Field 和 Reserve 的选择语义。对有消耗的主动 Main，扣次与扫描提交在同一入口。以已有战斗结算结果承载剩余次数，由 CombatMgr 的实战入口提交，CombatScene 观战与试战使用独立结果。最后一次效果仍完整结算。灵活卡在这次效果完成后走现有离场流程，准备卡在结算回写前补满。
7. 对二维邻接使用两卡实际占格的共边方向，由来源卡指向候选卡。选卡、计数与 OnUse 监听共用同一判断。监听读取发动时的占格关系，避免同一张卡在其脚本中位移后改变这一事件的判断结果。
8. 背包持有完整形状滑移资格和落点提交。逐步试探形状，成功后同时更新锚点、格索引及扫描覆盖。经过的灵元留在格上，最终占据的灵元让位。固定主功法和待发来源卡不能位移，确保不会破坏装配约束或已有待发。移动保留蓄灵和当轮次数，位置在成功提交后才可由事件读取。

## Risks / Trade-offs

- 事件回调能改变目标或继续触发效果。配对阶段锁定参与者，属性查找使用稳定顺序，联动移动先提交布局再派发事件，重复进入同一动作不得消费或触发两次。
- 两方轮次独立。效果记录到期所属者，不用全场 Tick 或施加者轮次换算；跨轮充能以原有批次结算顺序推进。
- 装备攻防速与消耗数据要隔离多场同源战斗。用同一 NPC 的实战、预览、再次开战覆盖初始化和提交。

## Migration Plan

从拼点、伤害和轮次入口开始，随后接通资源、装备及空间，最后接入消耗和战后回写。每组随实现更新已发布包装和目录，通过完整链路才标记 Ready。更新「现有 TCA」「玩法与接口索引」及「变更与反馈」，校验后同步并归档。
