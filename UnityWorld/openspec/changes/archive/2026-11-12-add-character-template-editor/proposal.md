# Proposal

## Why

目前人物与怪物模板主要通过 NPC JSON 配置，使用者需要手工维护卡牌坐标、功法进度和装备实例绑定，无法方便地浏览、组合并试打自己的角色。现有 Godot 战斗观察器已能展示真实战斗，本变更补齐它前面的模板制作流程，并让卡牌筛选随内容中的 Keyword 自动增长。

## What Changes

- 实施严格按三个阶段推进：**先生成和整理可用素材，再核查并补齐后端/非 UI 数据接口，最后实现前端界面**。本轮仅产出规划；阶段之间设交付检查点，不把整张参考图直接当成可交互界面。
- 沿用已确认的山水庭院、旧铜金框、羊皮纸、深青绿按钮风格，仅制作可伸缩 UI 面板，背景、人物、卡图和灵元图标复用已有资源。取消灰狼、赤炎狼、狼牙、兽皮及其他角色/卡牌补图任务；卡牌库只消费已有 Card，有图显示现有图片，没有图片直接显示卡牌名称，缺图不影响检索和合法配装。
- 提供独立人物/怪物模板编辑场景：左侧明确区分“项目模板”和“我的模板”，支持搜索、新建、复制、个人草稿保存、导入和标准 NPC JSON 导出。首版采用个人库保存，项目模板修改通过复制形成个人模板，不提供直接覆盖正式数据的保存动作。
- 中间支持主功法选择、按真实尺寸显示背包、拖放/移动/移除卡牌及重复卡实例；右侧编辑身份、八维属性、功法进度、装备绑定及招式所属装备，显示属性预览和配置问题。
- 卡牌库从实际 `CardDefine.Keywords` 去重动态生成可换行、多选的筛选按钮；名称/ID/描述、灵元需求、占格和兼容状态可组合筛选。未知 Keyword 显示原 ID，不要求修改 UI 代码才能看见新增项。
- 新增无实例化副作用的模板预检与结构化诊断，并与正式模板装配共用规则；明确哪些字段尚未被运行时消费，避免“保存了就已经生效”的误导。
- “进入试战”将自建草稿的不可变快照接通已存在的 `scenes/battle/battle_observer.tscn` 战斗模拟界面，在独立进程中复用现有背包显示、暂停、单步、播放、重开和结算；编辑窗口保留，重开使用同一份快照，不回退默认模板或另建简化演示界面。
- 验证控制在编译、少量高价值数据检查和一次真实 UI 冒烟。提供短人工验收清单，由用户判断视觉、操作手感与试战效果，不建设全量自动 UI 回归或战力平衡测试。

## Capabilities

### New Capabilities

- `character-template-library`: 项目模板与个人草稿的来源、身份、持久化、导入导出及数据隔离。
- `character-template-editor`: 素材交付、编辑布局、属性与实例装配交互、诊断反馈及人工验收入口。
- `card-library-filtering`: 由定义数据驱动的 Keyword 选项、组合检索、刷新及缺失显示名回退。
- `template-trial-session`: 自建模板快照、试战输入、新进程隔离及同输入重开。

### Modified Capabilities

- `npc-template-backpack`: 增加无实体创建/随机消耗的模板预检、结构化问题定位与正式装配共用规则；保留现有显式主功法、坐标、SP 和禁止自动补卡的要求。

## Impact

- 规划根目录：`UnityWorld/openspec/changes/add-character-template-editor/`；实际客户端仍在同一仓库外层的 `scripts/client/`、`scenes/`、`assets/`，不是另一个项目。
- 客户端新增模板目录读取、草稿模型/仓库、实例绑定转换、筛选、试战输入适配及编辑视图；调整 `GameBootstrap` 的模式选择和现有观察器输入入口。继续使用 .NET 8 与 Godot，不新增 Web 服务或数据库。
- 核心改动限于阶段二确认必需的纯定义校验、属性预览及装配规则复用，预计位于 NPC/背包/Stat 相关代码。用户本次要求的“检查需要补哪些后端代码”纳入计划，不沿用历史观察器任务“核心一行不改”的绝对限制；正式玩法 JSON、Lua 和战斗规则不因 UI 方便而修改。
- `user://TemplateEditor/` 保存个人草稿和试战输入；展示元数据放客户端 `assets/presentation/`。导出是独立文件，不自动写回 `UnityWorld/Data/Npc/`。
- 现有仅引用项目模板的观察案例保持兼容。更完整的世界 NPC 出生、境界成长、特质系统实现、随机组牌、卡牌效果编辑以及批量补齐全部美术不纳入首版。
- 设计与任务中列出当前字段缺口、素材清单、具体接口候选、阶段门槛和轻量验收。规划文件完成不代表功能或素材已交付。
