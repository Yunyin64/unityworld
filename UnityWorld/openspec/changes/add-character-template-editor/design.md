# Design

## Context

动机与交付范围见 [proposal.md](proposal.md)。本文件是实施设计，以下现状来自本轮只读检查，不表示功能已实现。规划目录在内层 `UnityWorld`，下文实现路径除特别说明外均相对仓库外层 `C:/Unity/Game/unityworld/`。

### 已确认的设计输入

- 用户需要能显示现有模板、手动拼装人物/怪物的客户端编辑器，已确认“项目模板／我的模板”两个来源分组。
- 视觉采用用户提供的战斗截图：山水庭院、旧铜金框、羊皮纸面板、深青绿按钮、小尺寸卡牌图标和角色单帧预览。
- 卡牌检索必须从已有 Keyword 动态生成，后续新增 Keyword 不应要求改 UI 布局代码。
- 用户进一步明确：灰狼、赤炎狼、狼牙、兽皮都不生成；本质是查看和组合已有 Card，没有卡图就用卡牌名称文字表示。本版不包含角色或卡牌补图工作。
- 用户明确实施顺序为“素材生成 → 后端检查需要补什么代码 → 前端 UI”，且要求测试轻量、亲自查看。规划时的只读核查用来形成具体任务，不提前实施任何一阶段。
- 个人库保存、标准 JSON 导出、多选默认同时满足等采用前文建议作为首版设计默认值；它们不是对现有实现的描述。首版不增加覆盖项目模板的保存按钮。

### 与既有规范及历史记录的关系

- `npc-template-backpack`、`combat-backpack` 的显式上场列表、重复卡、横条形状、主功法固定格和 SP 规则继续适用。本变更只为前者增加纯预检能力。
- `keyword-system` 中仍描述 `Keyword.lua` 索引，但实际 `LuaMgr` 扫描脚本自注册；本方案读取卡牌显式 Keywords，不依赖该已过时的索引描述，也不顺带重写 Keyword 加载机制。
- 已完成但未归档的 `battle-ui-observer` 早期规划写过“仅项目模板”“不改核心”。本变更新增独立的草稿试战入口和必要纯校验，保留旧案例路径；不修改历史提案以冒充它当时已经支持自建模板。
- `scripts/client/README.md` 仍有只存在静态预览的旧描述；以当前源码及根目录 `README_GODOT.md` 为准，交付时更新入口说明。

## Goals / Non-Goals

**Goals:**

- 用户能从现有模板出发，编辑身份和八维、挑选现有卡、摆包、绑定功法/装备，保存后再打开，并用当前配置进入真实试战。
- 模板文件、编辑中条目和战斗实例各有清晰身份；重排重复卡不串绑定，试战变化不污染草稿。
- 新 Keyword 自动可检索，面板能容纳持续增长的内容。
- 编辑器先交付可操作版本，由用户评估视觉与手感。

**Non-Goals:**

- 不实现完整世界 NPC 生活、出生/成长、境界突破、特质体系或随机组牌；不把 `Assemble` 变为 `Birth`。
- 不新增或编辑卡牌效果、Keyword Lua、功法内容、装备数值模板；只组合已加载定义。
- 不提供在线账户/云同步/多人协作、正式发布流程、全局撤销历史或批量模板生成。
- 不生成角色、怪物、卡牌图或角色动画，也不为缺图生成占位位图；按钮状态使用控件样式。无固定胜率/战斗平衡验收目标。
- 本次实施不承担已知旧告警的全面治理，也不扩大成全项目自动 UI 回归。

## Decisions

### 1. 三阶段串行交付

| 阶段 | 工作与输出 | 可以进入下一阶段的条件 |
| --- | --- | --- |
| A：UI 素材生成与整理 | 复核已有资源、生成 1 张通用 UI 面板、组织引用并检查拉伸区域，明确缺图名称文字呈现 | UI 面板和已有资源可加载；无图 Card 按名称呈现，不以角色/卡牌图完整度作为阶段门槛 |
| B：后端核查与必要补齐 | 按本设计逐项核对最新代码；补纯校验/预览；完成目录、草稿仓库、绑定转换、筛选与试战输入等非 UI 基础层 | 接口可编译；能以少量样例保存/还原、检出错误并组出试战输入；写出实际改动清单 |
| C：前端 UI | 场景、素材接入、两组模板库、背包操作、动态筛选、属性/绑定详情、试战入口和轻量交付 | 实际窗口可操作，关键流程冒烟完成，交用户亲自验收 |

阶段 B 的“后端”区分纯游戏核心和客户端非 UI 服务，不把个人文件夹或 Godot 路径放进核心。阶段 A 未完成前不开始 B 的代码修改；B 通过前不先搭交互页面。本轮读取源码不等于执行 B。

### 4. 后端必要补齐清单

| 项目 | 决定 | 理由与完成口径 |
| --- | --- | --- |
| 纯定义预检 | 必补核心接口 | 当前验证先创建 NPC/Card；拖动、筛选不能消耗随机 ID。重复检查相同输入产生相同报告且无实体注册 |
| 结构化诊断 | 与预检一起补 | 返回 `Code / Severity / Message / FieldPath / PlacementIndex / Cells`，客户端映射到稳定条目 ID；不能只截取异常字符串 |
| 属性预览 | 复用现有 Stat 算法，必要时补最小接口 | 使用未注册的独立 `StatBlock`，按 NPC 初始化语义加载默认值/InitStat，再读上限；不经 `StatMgr.CreateBlock`，不在 UI 固化公式 |
| 正式 Assemble 复用 | 必改小范围 | 在 `Soul.NewId()` 之前调用预检，公用形状、主功法、引用、容量条件；失败仍抛可读错误，运行时清理路径保留 |
| 草稿文件/序列化/搜索 | 客户端基础层新增 | 与游戏规则无关，不给全局 DefineMgr 增加可变个人模板池 |
| 自定义试战 | 客户端案例输入扩展 | `Assemble(NpcDefine)` 已可接收独立定义；不需核心“覆盖模板”接口 |
| 编辑宿主模式 | 客户端引导修改 | 编辑器加载定义即可；避免进入页面就生成世界或推进 Tick |
| 年龄、境界、Traits、道途 | 保留字段并标注，本版不补完整玩法 | 当前传递/消费存在断点，修复会改变角色玩法范围；不把“完整模板编辑器”扩大为完整角色系统 |

预检至少覆盖：模板 ID/必要引用；唯一主功法卡及匹配功法定义；主功法等级 1 的实际固定格；所有条目坐标、横条形状、重叠与有效格；功法/装备索引和定义匹配；同一实例重复绑定；父装备非自身且确有 Equip 绑定；卡兼容状态、禁用 Min/Max/ManaAdj；**占格 ≤ SP 上限 ≤ 有效格容量**。不推测卡的 Lua 效果是否一定有用或战斗一定结束。

预检对彼此独立的错误汇总，对缺定义导致的尺寸/布局未知停止依赖推算。程序输入仍保留防御性运行检查，静态通过不是保证所有 Lua 路径正确。

属性投影需检查现有公式依赖与缓存行为：独立块可修改自己的临时状态，但不能修改共享定义、已有运行实例、全局注册表或随机状态。沿用实际夹紧与公式；不能把 `HpMax = QiXue*2` 复制为 UI 专属规则。遇到未知/循环依赖返回不可用原因；SP 不可确定时正式导出/试战阻塞。已读可靠的 HP/MP 可单独展示。

### 5. 内容目录加载与刷新

编辑器使用纯定义目录，仿照当前 JSON 序列化约定支持大小写不敏感、注释和字符串枚举，读取范围与现有各管理器一致。不要为了编辑器初始化 `WorldMgr`，也不要调用包含地图生成相关依赖的完整 `GameDataMgr` 建世界。

建议只加载 NPC、Card、Cultivation、Equip、Stat 必需定义；先解析入临时目录，检测重复 ID/坏 JSON 后一次替换成功快照。原 `DefineMgrBase.Load` 会先清字典且容错跳过错误，不能拿它直接清空当前可用目录再宣称刷新成功。Stat 若仍需单例定义访问，只在编辑进程内安装已成功解析的 Stat 定义适配；将此依赖封装在投影服务，前端不可直接操作单例。

目录以只读对象或深拷贝持有；来源保留文件相对路径和条目序号。每次成功加载同时保存与试战相同范围的 JSON/Lua 数据指纹，读取前后指纹一致才发布新目录；不能把后来磁盘版本的哈希贴到旧目录上。刷新后重新预检草稿，失效引用保留为问题；已启动试战在独立进程不受刷新影响。首版显式“刷新”按钮，不做文件监视器或在运行中热替换 Lua。

### 6. 草稿结构与保存

个人目录使用 `user://TemplateEditor/drafts/<DraftId>.json`；`DraftId` 为客户端生成的 GUID，不参与核心随机序列，也不等同于用户可编辑的 `NpcDefine.ID`。

文档结构建议：

```text
TemplateDraftDocument
  SchemaVersion = 1
  DraftId / Revision / UpdatedAt
  Source = ProjectCopy | New | Imported
  SourceTemplateId / SourceFile / SourceFingerprint
  NpcFields = identity, Tags, full InitStat, InitAge,
              InitCultivationLevel, InitialTraits, legacy InitCardDeck
  MainEntryId
  Entries[]
    EntryId / CardDefineId / Position? / GongFaProgress?
    EquipDefineId? / ParentEntryId?
  UnresolvedBindings[] = fieldPath / rawValue / reason
  Presentation = portraitKey / actorVisualKey
```

`Entries` 是卡列表和绑定的唯一编辑真值，文档不再同时维护另一份可变 `InitCardPlacements/InitGongFa/InitEquip`。未放置条目的 Position 为 null；若主功法尚未选择，保留空 MainEntryId。

导入的已知字段如果因非法序号、缺少位置条目等原因暂时不能绑定，保留原片段到 UnresolvedBindings 并报告阻塞，不能在转换过程中丢弃它；修复或明确移除对应错误条目后才清除。它只承载未解析残片，不与已解析 Entries 并行维护第二份有效数据。删除父装备时保留原 ParentEntryId 作为失效引用，而非清成 null；重新打开仍能识别“待绑定”，直到用户重绑或移除该招式。

转换标准模板时按明确的 Entries 顺序产生位置列表，并建立 EntryId → 1 起始序号映射；所有功法/装备绑定统一写出 PlacementIndex，父装备写 ParentPlacementIndex。主功法从 MainEntryId 对应的定义导出。即使编辑文档能区分实例，当前标准格式要求主功法定义只匹配一张卡，重复该主功法定义仍应报歧义，不能靠稳定 ID 绕过核心约束。

复制整个模板时重新生成 DraftId 与 EntryId，并一次性重映射所有引用。复制单张卡不自动复制它的子招式；如果复制的是招式，保留对已有父装备的明确引用。重排只改变导出顺序，引用不变。

新建默认姓名为空、种族按用户选择、八维使用当前 Stat 默认值、无主功法/无卡，立即可以保存但不能试战；不凭空塞一套所谓“标准强度”。从项目模板复制时建议生成 `<原ID>_copy`，追加数字直到当前库不冲突；显示名可重复，标准模板 ID 冲突阻止导出/试战。

保存采用同目录临时文件写完后原子替换，保留一个最近成功的 `.bak`，成功后才清除 dirty 标记；无需版本数据库。切换模板或关闭时提供保存/放弃/取消。主按钮保存个人草稿；新建、复制、导入都进入个人库；首版不做删除项目模板功能。

导入支持标准对象/数组和本工具版本 1 草稿。已知但未展示字段（例如 Tags、额外 InitStat、旧 InitCardDeck）保留；旧 InitCardDeck 非空仍标记与显式位置冲突，不自动推断摆放。未知字段/版本提供具体字段诊断并停止该条导入，不静默剥离。数组导入先逐项诊断，仅用户选择的可解析项成为草稿；同 ID 不覆盖已有库。

正式导出写单元素或选中元素的 `NpcDefine[]`，符合现有加载器读取数组的约定，不夹带 DraftId、展示映射和缓存。默认导出到 `user://TemplateEditor/exports/`，可另选非正式源目录；编辑器内拒绝将导出目标落到项目 `UnityWorld/Data/` 以免覆盖项目模板，用户可在外部自行采用导出文件。未完成配置只保存草稿，不提供“忽略错误正式导出”。

### 7. 动态 Keyword 与组合检索

当前实际卡牌显式 Keyword 为 `FaShu`、`Passive`、`ZhaoShi`、`GongFa`、`Wound`、`Item`、`FaBao`、`Armor`。这只是当前目录快照，不是实现时的固定集合。

- 选项取完整目录所有卡 `Keywords` 的非空去重集合，使用原 ID 作为匹配键。没有卡使用的 Lua 注册项不列出；运行时 CheckCondition 派生项不在编辑阶段模拟。
- `assets/presentation/keyword_labels.json` 仅提供 DisplayName、可选 SortOrder/说明。缺映射显示原 ID，未知项稳定按 ID 排列；中文映射不能变成白名单。
- 多选默认 AND，同时具有全部所选 Keyword 才匹配；“全部”清空该维度。页面显示“同时满足”，避免用户把法术和法宝理解成互斥页签。首版不再增加 OR 切换。
- 文本：名称/ID/描述模糊包含、忽略英文大小写、去掉首尾空格；轻量 150–250 ms 防抖即可。
- 灵元需求：依据 ManaCost 键匹配，选择火可包含金火混合需求；单独提供“无灵元需求”；Tag 中的火不等于需求火。
- 占格：依据 Size，由实际尺寸集合生成选项，默认不限。
- 兼容：默认“全部状态”，可切换“可装配”；不可用卡仍可检索查看，置灰添加并显示理由，不能只因图标缺失变成不可用。
- 各维度交集；Keyword 选项集合不随当前搜索结果缩减，避免越筛越无法取消。首版只显示结果总数，省去容易误导的每标签联动数量。
- 刷新：成功后生成新集合并保留仍有效的选择；消失的选项取消并提示；失败保留旧目录。新增关键词无需编译前端。

布局使用 FlowContainer/可换行按钮区，默认两行，超出显示“展开关键词”，展开最大占卡库约 40% 高度并可纵向滚动；卡牌结果列表独立滚动。全部选项始终可达，避免无限横向挤压搜索框。

### 8. 具体页面与操作

目标画布 1600×900，1440×810 正常使用；更小窗口通过控件最小宽度与滚动处理，不增加全套响应式矩阵。

| 区域 | 功能细节 |
| --- | --- |
| 顶栏 | 页面名称、模板编辑/战斗观察入口、新建、复制、保存草稿；显示当前模板与未保存标记 |
| 左栏约 20% | 搜索、全部/人物/怪物、两组可折叠列表、来源及草稿状态、导入/导出；项目行进入只读预览，复制后才可改 |
| 中栏约 50% | 上半主功法选择、尺寸/SP、网格与可选静态外观；下半卡牌库与动态检索。外观区域不足时优先收窄，保证网格操作空间 |
| 右栏约 30% | 名称/ID、种族/性别、姓名/道号、八维、只读派生值；选中卡的效果描述、全部 Keyword、Size/需求/CD、功法进度/Equip 绑定/父装备；长详情滚动 |
| 底栏 | 当前阻塞数/提示数、打开诊断、检查配置、对手选择、进入试战；非法草稿仍能保存 |

网格动作：从卡库拖入时生成新的草稿 EntryId，悬浮显示实际占格和合法性；放手仅在合法位置提交。移动已有卡先忽略自身旧占格检查候选位置，失败回原位。右键删除普通卡，主功法只能通过显式切换操作更换。删除父装备后相关招式保留失效引用并显示待绑定阻塞问题，不自动删除子招式，也不让保存重开清除该问题。

更换主功法只替换/选择明确主实例，读取新布局并检查其余卡；无法继续放置的卡进入可见“未放置”列表，不删除、不自动搬格。主功法进度与背包等级是不同概念：本版标准模板仍是等级 1，不把 CurrentPoint 误当背包等级。功法进度不自动解锁子卡，装备绑定不自动添加 FormList 招式；用户通过卡库明确添加并绑定。

详情字段状态：年龄、境界、特质默认在“扩展字段/支持状态”中展示和保留，标注当前未接通；五行亲和若用户模板手填，将被 Soul 生成覆盖，显示提示；道途不根据主功法画成已经写回角色。核心未实现字段不做伪交互。当前 Extra InitStat 在展开区只读保留，首版主编辑器集中处理八维。

撤销范围控制：非法拖动自动回退；切换草稿支持取消；正式保存有上次备份。本版不建设多步 Ctrl+Z 命令栈，以免拖慢首版可用性。

### 9. 草稿试战与旧观察器兼容

“进入试战”的接入目标明确为现有 `scenes/battle/battle_observer.tscn` 场景、`scripts/client/ui/BattleObserverView.cs` 视图及 `BattleObserverSession` 会话。沿用已经有的战场、双方背包、日志、播放/暂停/单步/重开和结算显示，只补充模板输入适配。按钮不能仅导出 JSON、打印日志或跳到另建的演示页面。验收时核对已有界面中的双方名称、卡位和属性来自此次编辑输入。

扩展 `BattleParticipant` 时保持旧 JSON 中只有 `TemplateId/Team` 的读取行为，默认按项目引用解释。个人输入采用显式 `Source=DraftSnapshot`，含完整深拷贝定义与内容哈希；二者不能同时成为有效来源。可以在现有记录上加可选属性，或用向后兼容转换器，旧构造与默认案例不被破坏。

启动流程：

1. 先核对磁盘数据与最近成功加载的编辑目录指纹；不同则提示刷新，重新预检后才能试战。随后将当前编辑文档及对手转换为独立定义/项目引用，执行预检；有阻塞则返回编辑器问题位置。
2. 冻结当前未保存内容也允许试战，原 dirty 标记保持。输入包括双种子、阵营顺序、MaxTicks、TicksPerRow、玩法数据指纹、核心版本和草稿快照身份。
3. 将完整案例写入 `user://TemplateEditor/trials/<session-id>/input.json`；草稿快照以固定序列化方式生成哈希，数组顺序保留，字典键顺序固定。不要让重开依赖可变的个人草稿文件路径。
4. 使用当前 Godot 可执行文件启动 `battle_observer.tscn`，新增 `--observer-case-input=<绝对路径>` 文件输入参数并配合 `--battle-observer`。现有客户端实际使用 `--observer-case=<Base64>`，保留它作为旧入口；草稿试战和重开改用文件路径，不把大 JSON 塞进长命令行。双入口同时出现时报歧义，不猜选。
5. 子进程校验数据身份后，用独立定义调用 `NpcMgr.Assemble`，复用 `Init → PreStart → Start → Tick → GetResult → Cleanup`，开场停 Tick 0。
6. 编辑窗口保持运行且不推进世界；关闭子进程回到编辑器继续编辑。暂不开发实时 IPC 或自动回传战力评分。

重开沿用被冻结的完整案例文件，不重新读取后来改变的草稿。子进程失败信息由其窗口和日志展示，启动失败由编辑器直接提示；不加载默认 A/B 掩盖失败。数据版本变化停止重放，用户需从编辑器重新发起一次新试战。

`GameBootstrap` 模式识别应优先显式参数/当前场景，再考虑默认主场景；不能只因项目默认场景是观察器，就让显式编辑器模式也走错分支。最终默认入口可设为模板编辑器；顶部“战斗观察”打开原默认案例，已有 CLI、原场景直接启动及烟测参数保留。

### 10. 轻量验证与用户验收

验证不是单独的大项目。实施者完成以下有限检查即交付，不为追求覆盖率扩展范围：

1. 一次 `dotnet build Xianxia.Client.csproj`；使用实际 Godot .NET 启动编辑场景检查资源、文本、布局和基本输入。
2. 一个小型非 UI 检查组：重复卡绑定的导出/导入往返；非法草稿保存与正式导出阻断；重复纯校验无实体/RNG 消耗；新增一个内存 Keyword 能筛到。测试数据留在内存或验证目录，不写正式 Data。
3. 若按本方案调整核心共用规则，运行一次已有 `dotnet run --project UnityWorld/Console/UnityWorld.Console.csproj -- --template-tests`；只修本次引起的问题，不顺带跑所有战斗/地图套件。
4. 一次真实界面冒烟：复制现有模板 → 拖入一张重复卡并合法摆放 → 调属性 → 保存/重新打开 → 选对手 → 启动试战到 Tick 0 → 单步一次/短暂播放 → 关闭试战继续编辑。无需跑到固定胜负。

若出现失败，只针对失败修复并复验受影响项；全部通过即停止扩大自动测试。不增加截图像素对比、跨平台/多分辨率矩阵、逐 Tick 全量轨迹比较、长时间稳定性与平衡测试。

给用户的人工清单保持短：两组来源是否清楚、拖放是否顺手、重复卡是否独立、搜索多选是否符合预期、保存重开是否保留、试战是否用当前配置。最多提供一张编辑器截图和一张试战初始截图方便定位，不把截图等同于人工验收。

## Risks / Trade-offs

- [纯校验与运行时规则漂移] → 抽取共用规则并在创建实体前复用，不复制另一套“近似合法性”。保留运行时检查，不承诺静态检查覆盖所有 Lua 错误。
- [Stat 公式和全局单例] → 未注册临时属性块、只读目录及明确依赖边界；对不能可靠计算的项显示不可用，SP 未知阻止通过。
- [年龄/境界/Traits 名存实亡] → 保留原字段、明确支持状态，完整角色初始化另行设计，首版不假装生效。
- [同定义重复与主功法歧义] → 草稿稳定 EntryId、导出统一重建索引；主功法定义当前仍要求唯一，错误直接定位。
- [全屏参考图难以切成资源] → 首阶段生成独立透明单元并明确拉伸边界，不用整图热区替代控件。
- [新 Keyword 没有中文名或脚本未注册] → 原 ID 回退负责可检索性；这不等于获得可战斗保证，兼容诊断与真实试战仍独立执行。
- [输入变化导致旧试战重开不一致] → 冻结快照与指纹，禁止回读活草稿，新进程隔离静态状态。
- [两个窗口略显工具化] → 换取现有核心无需重置静态状态，编辑内容不丢失；同窗口嵌入等后续核心重置能力再考虑。
- [个人库方式尚非正式内容发布] → 导出标准 JSON，用户可以审阅后自行纳入项目；首版不引入正式覆盖/发布审批流程。
- [测试轻量可能遗漏复杂组合] → 确保数据保存、重复绑定、基本装配这些高风险路径，列明限制，优先交可操作版本让用户查看。

## Migration Plan

1. 阶段 A 只新增素材与展示映射；旧素材保留，不覆盖既有图。素材引用以客户端资源路径落盘，不依赖本机临时目录或仅存 `.codex` 的生成输出。
2. 阶段 B 新增纯校验与非 UI 服务，扩展旧案例格式采用可选字段/兼容转换；现有 NPC JSON 无迁移要求，旧案例继续读取。
3. 阶段 C 接入新场景并将其作为便捷默认入口，保留原战斗场景和直接启动方式，更新 README 与人工操作清单。
4. 回退入口时恢复默认战斗场景即可停止使用编辑器，个人库文件保留；回退代码/素材按新增路径处理，不删除用户草稿和原项目数据。未进行正式模板覆盖，因此无需回滚 Data/Npc。
