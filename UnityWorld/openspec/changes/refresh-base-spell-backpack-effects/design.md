# 基础法术的背包效果设计

## Context

扫描时钟分开处理自然推进和行进度消耗。当前的 `AdvanceNaturalTick` 计算双速或半速，`ScanReadyRows` 按当时的进度收集到行角色，再处理行内、拼点和轮末。单卡蓄灵用实际五行记账，`CanAcceptMana` 拒绝中性的 `None`。滑移读取选牌范围给出的目标，再校验整张卡的位置和障碍。战斗卡已有 `CardModifier` 增删机制，冻结则由单独的 `CombatCard.IsFrozen` 向客户端快照投影。

## Goals / Non-Goals

本设计把通用费用补充、扫描暂停和敌方最上方选牌作为可复用能力，Lua 用这些能力表达五张法术的效果。冻结接入卡牌状态管理，观察器用卡牌状态列表表达效果。交付范围以 [提案](proposal.md) 为准。

## Decisions

### 速度效果继续使用两种时间单位

加速调用已有的 `Haste`，持续时间为 10 个真实 Tick。爆燃调用已有的 `Charge`，立即增加 20 个基准 Tick。加速原费用为空，设计采用 **1 金** 作为 1 格金系法术的初始配表值。爆燃沿用配表的 2 格、2 火。两张牌的描述直接写出时间单位。

### 通用蓄灵走卡牌的点亮和支付流程

在战斗卡蓄灵的现有提交路径中识别动作生成的 `None`，只填通用槽。使用顺序和任意剥离沿用卡上充入顺序。格上分配继续使用真实五行的接收校验。通用蓄灵成功提交后派发充入事件，显示和耗灵数据同时记录它的通用身份，五行监听只读取真实颜色。

回旋斩通过 `OnAttack` 校验攻击者阵营。通常在事件发生时给自身补充，仍处于待发时只登记下一次可用的一份，在本卡 `Apply` 重新允许接收时提交。现有直击和配对的攻击事件都先于来源卡的 `Apply`，因此回旋斩自己的攻击也能提供这份蓄灵。结算后的正常扫描负责下一次发动。

### 角色背包持有暂停到期时间

用战斗真实 Tick 作为截止时间。施加当下立即禁止启动新的扫描行，其后的 5 个完整 Tick 停止自然进度与行消耗。多次施加取较晚到期点。加减速计时按真实 Tick 递减，充能仍可以增加账面进度。恢复后按行处理已经积攒的进度。

扫描入批时筛掉暂停角色，开始一行前再次校验。只把成功取走一行进度的角色交给配对、行边界和轮末流程。这样一个较早处理的角色在同批内施加暂停时，后处理的目标不会推进一行，已开始的行仍能正常完成。

### 最上方选择与滑移资格分别判断

在 `APIDomainFunc` 增加按对手实际占格排序的选牌范围，结果由 `SlideCard` 复用。排序先看最上方行，再看外接矩形的左缘，实例编号用于稳定排序。选牌先固定唯一目标，固定主功法、定身、待发和下方障碍由现有滑移入口裁决。这个顺序让玩家能从盘面看出流动会尝试推谁。

### 冻结由卡牌状态驱动末格判定

冻结使用稳定状态 ID，挂在战斗卡的 `CardModifier` 列表，层数上限为 1。使用不会自动到期的策略，由末格处理或显式解冻移除。施加入口先检查卡上冻结记录和现有冻结免疫光环，随机冻结基于同一查询排除已冻结卡。后端移除 `CombatCard.IsFrozen` 后，所有规则从状态列表查冻结。

末格先记录进入判定时是否有冻结，再执行失败的 `OnScanEnd`，最后移除冻结。这让法宝能正确结束激活，并保留原有本行机会和已点亮灵元。主动解冻复用同一个移除入口。现有 Lua 回归中读取 `card.IsFrozen` 的断言迁移到卡牌状态查询。

### 前端从卡牌快照派生冻结

`BattleSnapshotProjector` 为每张卡复制状态值，至少提供稳定状态 ID 和层数，采用稳定顺序。新快照以状态列表作为卡牌状态的同步数据，前端 `CardSnapshot.IsFrozen` 是只读显示属性。画冰框、卡面标签和详情继续读取该属性。

入场表现与最新战斗帧都用同一状态投影，播放时的资源过渡只修改自己的字段。冻结施加和移除时保留表现标记。没有数值修正的冻结条目也要在施加成功时标记；如果同一 Tick 内先施加再移除，战斗帧记录该 Tick 的最终状态。

## Risks / Trade-offs

- 通用蓄灵如果计入真实五行种类数，会误触发多色用灵效果。充入、剥离、支付和表现共同验收一份金加一份通用的组合。
- 暂停可能在同一个扫描批次中途施加。行提交和批次后续处理都应以实际消费的行为依据。
- 眩晕原档案为 2 格、1 土，本次先接通暂停动作与卡牌脚本，使用测试定义验收。正式装配费用继续待定，开放时按现行正式配表规则处理。
- 卡牌状态进入快照会改变新生成的 JSONL 字段。观察器和控制台校验工具用相同的新投影生成结果；历史证据保留原始帧，比较旧帧时应识别双方快照格式。

## Migration Plan

先实现三个独立能力，再接入既有 ID 的卡牌效果。回旋斩、流动完成脚本和装配验收后更新其 JSON 兼容状态。眩晕的正式开放单独随费用确认处理。冻结先接通状态增删与只读投影，再迁移后端判断、前端显示、入场表现和回归样例，最后移除后端布尔属性。核对卡面描述、动作目录和表现后集中跑已记录的战斗回归。
