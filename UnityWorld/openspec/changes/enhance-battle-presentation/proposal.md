# Proposal

## Why

Godot 战斗观察器已经连接真实模拟，但只有 Tick 终态和有限玩法事件，灵元转移、同一步点亮后使用、伤害和卡牌入场等过程无法完整呈现；属性缺少可靠上限，视图大文件也混合了布局、状态、动画及验证职责。需要补齐独立的观察数据，使用户能直接看懂资源、对拼、生效和伤口生成过程。

## What Changes

- 按逻辑 Tick 交付“结束状态快照 + 按顺序排列的表现事件”，保留现有同进程 C# 核心与 Godot 分离；当前不增加网络传输。
- 在核心已完成的操作处记录灵元分配、卡牌使用/点亮复位、待发变化、对拼、实际伤害、卡牌成功入包及实际生效。表现记录独立于玩法事件总线，不触发 Hook、Lua 或卡牌机会，不从日志和两帧差值猜测结果。
- 增加无副作用的当前属性上限读取，显示气血 当前/上限、灵力 当前/上限、SP 占用/角色上限。
- 灵元从真实源格飞入真实目标卡；用灰暗底色到元素亮色的分段动画替代卡面点亮 x/x，Size 2 水卡收到一个灵元时半张亮蓝。保留悬停详情、冻结与满亮等待状态。
- 新增通用卡牌生成入包动画，用于伤口并支持其他战中新卡；成功入包后按真实占格播放，不改变摆放规则。
- 对拼时只移动界面现有两个待发槽中的卡牌内容，使其向中央碰撞；槽底框和背包原卡不动，不另外生成一组独立对撞卡。平局同样碰撞，直击不伪造另一张卡。
- 受击角色头顶显示较大伤害数字；卡牌实际生效时在所属角色头顶显示“卡名 · 生效”，与使用/入槽时点区分。
- 按会话、投影、播放、背包/卡牌、待发、角色提示及验证职责拆分客户端 C# 大文件，补简短中文注释；播放支持暂停收尾、单步、事件去重、积压压缩、结束收尾和重开清理。
- 用户实测追加：消除整 Tick 的动画等待，不同 Tick 和无关动画并行，长名称/伤害淡出不阻塞出招；扫描光线独立读取最新核心进度。同一多格卡的图片与底色连续连接，只保留外轮廓和真实空洞。

## Capabilities

### New Capabilities

- `battle-presentation-stream`: 引擎无关的有序战斗事实记录、Tick 批次交付、来源与生命周期隔离。
- `battle-presentation-playback`: 状态与过程协调的 Godot 表现播放、灵元/点亮、待发槽对撞、卡牌入包、伤害及生效提示。
- `stat-readonly-projection`: 与现有属性规则一致且不写入原状态的属性投影，以及战斗上限显示契约。

### Modified Capabilities

无现有主规格需要改变玩法要求。`combat-backpack-scan`、`combat-contest-scheduling`、`passive-card` 等继续决定实际战斗行为。

`battle-ui-observer` 已实现但尚未同步为主规格。本变更是在其基础上的独立扩展，不重复创建其 session/ui/assets 能力，不修改历史任务勾选。其“核心完全不可修改”“缺过程只能降级”边界，在本轮明确授权的观察接口范围内被扩展；暂停时取消全部瞬态调整为停止逻辑后允许已提交短动画收尾。后续同步归档须保留本扩展的优先关系。

## Impact

- 规划位于 `UnityWorld/openspec/changes/enhance-battle-presentation/`；实际 Godot 客户端仍位于同仓库外层 `scripts/client/`。嵌套规划根不意味着把客户端代码放入后端。
- 核心允许修改 `UnityWorld/Scripts/Game/Domain/Combat/` 中相关操作/观察接口及 `UnityWorld/Scripts/Core/Base/Stat/` 中必要的只读计算实现；实际生效覆盖若需要来源上下文，限于相关 C# 效果执行路径。
- 客户端涉及会话与快照契约、UI 组件、表现队列、`tools/client-observer/` 验证入口及使用说明。新的观察契约采用明确版本，既有输入重放与原始战报继续可用。
- 不改变玩法公式、扫描/事件调度、JSON/内嵌 Lua、原控制台入口、核心工程依赖或原预览场景；不引入 Godot 到核心，不做网络同步、完整事件溯源或存档回滚。
- 本轮复用现有卡图、灵元图标与代码绘制，不生成新图片。动画时长、曲线、颜色等集中在客户端配置。
- 交付需证明观察开关和高频读取不改变逐 Tick 战斗轨迹，并取得实际动画及交互验收证据；本次 propose 仅创建规划，不实施代码。
