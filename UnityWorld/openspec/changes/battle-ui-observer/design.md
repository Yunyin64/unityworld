## Goals / Non-Goals

**Goals:**

- 用现有规则完成真实战斗观察，数据来源、播放时钟和素材路径可追踪。
- 控制台与客户端使用同一案例输入和相同版本的源数据；“重开”重放当前案例，不重新挑一套演示数据。
- 客户端适配器与 Godot 视图分开，界面只能消费值副本，核心只保留原有引擎无关职责。
- 先交付当前模板可验证的观察体验和首批素材；全量定义进入台账，后续素材按确认批次持续补齐。

**Non-Goals:**

- 修改核心代码、JSON/Lua、玩法、事件协议或依赖；发现核心问题不在本变更顺带修复。
- 战中拖放、部署/召回、背包编辑、完整逐格录像、完整角色动作系统、Unity 客户端、发布导出包。
- 用解析日志、重演伤害公式或猜测灵元路径生成结构化战斗事实。
- 首版同进程无缝重开；本版采用新的游戏进程保证静态状态隔离。

## Decisions

### 1. 目录与依赖边界

文档沿用已确认的嵌套 OpenSpec 根；实现位于用户指定的同仓库外层 Godot 项目。根路径不同不代表把代码搬入核心目录。

| 区域 | 计划内容 |
| --- | --- |
| `scripts/client/battle/` | 新增会话控制、读接口适配、值快照、观察记录；具体类名按实现约定，不是现成 API |
| `scripts/client/battle/cases/`、`assets/testing/battle_cases.json` | 引擎无关案例装配适配与案例引用清单，由 Godot 和新增无画面验证入口共同使用；不复制核心模板数值/布局 |
| `scripts/client/ui/` | 新增 Godot 界面、卡片、背包、战报及表现脚本 |
| `scripts/client/GameBootstrap.cs` | 增加观察模式的核心宿主所有权与时钟协调，保留已有核心烟测入口 |
| `scenes/battle/` | 新增真实观察场景，复用预览布局；保留原素材预览场景 |
| `assets/art/cards/` | 首批卡图，文件名使用定义 ID |
| `assets/art/icons/mana/`、`assets/presentation/mana_visuals.json` | 金木水火土五张灵元图标及按元素 ID 的客户端映射 |
| `assets/presentation/card_visuals.json` | 客户端定义 ID → 资源路径、裁切、比例和来源的映射 |
| `docs/art/card_asset_manifest.json` | 分别记录 Card 与灵元资源的素材台账、批次状态、来源、尺寸、提示词和验收结果；五种灵元不计入 88 个 Card 定义 |
| `docs/art/battle_observer_integration.md` | 字段来源、已验证读取白名单、限制及运行验收说明 |
| `tools/client-observer/` | 不依赖 Godot 的适配层验证入口、资源审计脚本；引用现有核心，不把测试加到后端 |
| `project.godot`、`Xianxia.Client.csproj`、`README_GODOT.md` | 仅进行客户端入口、必要编译项和使用说明调整 |

受保护范围是 `UnityWorld/Scripts/`、`UnityWorld/Data/`、核心/控制台工程及现有主规格；本次在其 `openspec/changes/battle-ui-observer/` 下新增规划不属于模拟器改动。常规构建产生的 ignored bin/obj 不作为源文件修改，但不能因此忽略被跟踪文件的变化。

```text
Existing Core <-- lifecycle -- Client Session
      |
      +-- audited reads/events --> Value Snapshot + Observed Records
                                              |
Client Art Catalog ---------------------------+--> Godot Views
```

选择值快照而非控件直连核心：控制访问次数，避免活动集合和 Lua 上下文泄漏，也允许用相同适配器进行无画面验证。界面不计算命中、伤害、资源支付或扫描顺序。

### 2. 会话生命周期与控制时钟

- 观察模式由单一宿主初始化世界，关闭 `GameBootstrap` 的背景 `WorldMgr.Tick`；核心只经 `CombatScene.Tick()` 推进战斗。原 `--core-smoke-test` 模式仍独立按既有流程运行，不能被观察模式误停。
- 默认选择 `console-basic-template` 案例，从现有 `NpcDefineMgr`/`NpcMgr.Assemble` 依次创建 `test_npc_a` 与 `test_npc_b`，调用 Init(12345, participants, 5000)、PreStart、Start；随后在 Tick 0 暂停。参数读取公共案例描述，不在 Godot 控件与验证入口各写一份，不改模板。
- 播放默认 10 Tick/秒，使用客户端时间累积器；每次仅调用完整的无参 Tick。暂停不积攒现实等待时间，继续时不突然补跑暂停期间的时间。
- 单步仅在暂停状态执行一次 Tick，更新快照和记录后继续暂停。倍速不是首版必交项，但设计不将逻辑步频绑死到显示帧。
- 捕获初始化/推进异常，保存原错误，停止推进；`IsFinished` 并不保证存在正常结果，只有正常结束路径才尝试展示 GetResult，缺失结果作为诊断处理。

拒绝直接调用 RunCombat/Run 作为 UI 播放入口：会一次跑完整场，无法暂停或单步。拒绝为了动画把一次 Tick 拆成自定义格间规则。

### 2.1. 既有控制台案例与数据同源

首个可播放案例 `console-basic-template` 对应现有 `CombatTestRunner.RunBasicTest`，保留原控制台工程、入口及测试源码。新增无 Godot 验证入口与 Godot 共用 `scripts/client/battle/cases/` 中的纯 C# 装配适配及 `assets/testing/battle_cases.json`；原控制台仍按原代码运行，不声称它已改为读取该新清单。

| 输入 | 与现有控制台对齐的值/来源 |
| --- | --- |
| worldSeed / combatSeed | 分别记录，默认均为 12345；不能只用一个含糊的 seed 字段 |
| 参战顺序与阵营 | 先装配 test_npc_a 为 TeamA，再装配 test_npc_b 为 TeamB |
| 模板内容 | 直接读取同一版本 `Data/Npc/Test.json` 及其引用的 Card、功法、Lua；A 7 个实例、B 5 个实例，B 的两张射击保持独立 |
| maxTicks / ticksPerRow | 5000 / 现有默认 10，写入输入记录并与源案例核对 |
| 起始调用序列 | World.Initialize → Start → Assemble A → Assemble B → Scene.Init → PreStart → Start；不插入世界 Tick、额外实例创建或展示随机数调用 |
| 数据身份 | caseId、源测试类/方法、模板与阵营有序列表、参数、源代码版本及实际加载 JSON/Lua 相对路径与内容哈希 |

旧控制台从 `AppContext.BaseDirectory/Data` 加载构建复制件，Godot 编辑器当前读取仓库 `UnityWorld/Data`。验证前比较实际加载目录的文件集合与内容哈希，不能仅检查两个模板 ID 相同。清单只保存案例引用和运行参数，角色数值、卡牌位置、效果全部来自源定义，不维护客户端拷贝。

三层对照：先运行**原控制台默认案例**取得实际结束原因、赢家、总 Tick 和可用轨迹；再用**共享案例适配的无画面入口**取得初始快照与逐 Tick 状态；最后比较 **Godot 自动播放、单步与重开当前案例**。原案例只断言 AllDefeated 且赢家非 None，没有固定赢家/总 Tick 常量，本轮不能编造这些结果。对照输出第一处字段差异，不以最终胜负相同替代过程一致。

其他现有回归按以下来源列入案例覆盖表，但不将整个 Run 方法直接包装为可暂停战斗：

| 既有测试 | 样例战斗 seed / 上限 | 首版分类 |
| --- | --- | --- |
| BackpackModelTests、TemplateBackpackTests | 多种局部构造，部分无整场战斗 | 布局、非法输入、回滚、快照隔离等保留原控制台断言 |
| BackpackCombatTests | 4567 / 200 等；FullBattles 为 8765 / 1000 | 手工实例、测试功法、灵元与中途操作，记录待适配原因 |
| BackpackTimingTests | 6001 / 1000 | 充能/速度/跨轮/极端多行；记录完整操作序列需求 |
| EffectMigrationTests | 93471 / 500 | 动态效果、布灵与 Lua 注入；不得仅复制 seed |
| ActivationMigrationTests | 7119 / 2000 | 动态关键词、事件/脚本注入及错误用例，保留专门断言 |

案例选择/信息区只将完成同源映射的案例标为可播放。首版至少交付默认正式模板案例，其余显示来源与未适配原因；以后适配某项时须共用初始构造、按 Tick 排列的操作脚本和断言，不能造一份近似 UI 数据。此分类不删除或改写任何原测试。

### 3. 重开采用新游戏进程

首版按钮标明“重开当前案例（重启观察器）”。客户端保存当前案例完整描述，包括 caseId、worldSeed、combatSeed、有序参与者与阵营、步数配置、数据版本/哈希及适用的操作序列引用；以这些输入启动新的游戏进程，不能硬编码回默认 A/B。新进程实际数据指纹不一致时停止自动播放并提示版本变化，不能宣称同输入重放。进程创建请求成功后停止旧会话、解绑客户端监听、取消动画、调用现有清理/世界结束并退出旧游戏窗口。进程创建请求失败时保留旧窗口并显示错误；创建成功后的初始化错误由新窗口或其会话日志诊断。只启动游戏，不创建新的编辑器或 Codex 任务。

该方案隔离静态 ID 集合、全局单例和旧监听；不引入额外 worker/IPC。验收时比较独立进程的规范化逐 Tick 状态与结果，不能仅比较种子文字。每个进程/会话使用独立日志文件，避免新旧窗口短暂并存时争用原固定 game.log；会话标识不得消耗核心随机序列。MCP 启动的首进程与用户重开的后续进程可能不在同一调试输出通道，后续会话证据使用客户端日志/验证入口补充。

未采用同进程 WorldMgr.End→Initialize：清事件不足以清 `_usedIds`；反射清静态字段违反边界。未采用复制全部私有核心状态作为重开：会引入脆弱的序列化/恢复协议。以后若核心提供正式重置能力再单独讨论。

### 4. 读取白名单及过程降级

候选读取点须在实施的第一组特定验证中确认无副作用；此表不是允许任意 Get 方法的通行证。

| 观察内容 | 现有来源 | 适配约定 |
| --- | --- | --- |
| Tick、结束状态 | CurrentTick、IsFinished、正常结果 | 每次合法推进后读取一次；异常独立处理 |
| HP/MP/护盾/SP | GetHp、GetMp、ShieldValue、GetSp | 复制当前数值；不以血条动画反写数据 |
| 最终上限、动态属性 | 上限 getter 经 Stats.Get 可能更新缓存；其他动态属性 GetStat 可能执行 Lua hook | 验证安全后才使用；否则隐藏不可靠比例条，当前值照常；如展示初始参考必须明示 |
| 布局与灵元 | Backpack.Width/Height、IsValid、Placements、Mana、AssignedTo | 深复制格坐标、元素及列表；只读包装也不能直接传给控件 |
| 扫描与控制效果 | Row、Round、ScanProgress、HasteTicks、SlowTicks、IsFrozen | 保留 decimal 精度；显示行号在客户端统一转换为 1 起始 |
| 卡身份与使用 | Id、DefineId、DisplayName、UseCount、ApplyCount | 实例 ID 管状态，定义 ID 查图；必要时标出本 Tick 使用次数 |
| 当前待发 | PendingSlot 中卡、类型、数值、元素 | 立即复制值，不保存 ContestData/实体引用供动画稍后读取 |
| NPC Buff | GetAllModifiers 后的 ID/层数/期限等已审核字段 | 只投影安全值；不擅自暴露不存在的 CardModifier 查询 |
| 过程 | 本场 TraceLog 增量与已有事件 | 按场景筛选、按 Tick+序号复制；不足字段留空，不解析日志填充结构化状态 |

`Stats.Get` 可能更新原缓存，`GetStat` 可能执行 Lua。需要基准属性时，可在经过审核的 `Stats.Snapshot()` 副本上求值，并标为基础/初始参考；不得宣称它自动等于动态 hook 后的最终值。视图每帧、鼠标 hover、动画循环都只读已构建快照，不再调用核心 getter。

UI 以“当前状态 + 可追溯事件 + 原始战报”为准。平局、伤害具体金额、HP 归零后同 Tick 恢复、灵元格间转移等信息不完整时，不靠最终差值猜测过程。“最近结算”只对载荷充分的记录显示已知字段，其他情况保留最近战报。事件监听只复制、不写 args、不发新事件，退出逐一退订自己注册的监听。

### 5. UI 复用与观察体验

- 新建真实战斗场景，保留旧预览作素材参考；背景、人物、面板可复用。
- 左右背包按快照尺寸和有效格动态生成，卡图不决定形状。当前正式模板为 5×5，不能把测试布局或未来尺寸写死。
- 各自显示扫描行、轮次和行进度；扫描主视觉为横贯有效网格宽度的蓝白光线，按下节约定从上向下移动。灵元使用已确认生成的五行图标，加载失败才回退到名称/元素字样；冻结、待发、主功法、伤口使用独立视觉标记。
- 属性显示真实当前值，黄色标签改成 SP 占用。双方人物仅是客户端形象映射；不得改 NPC 性别、名称或模板配合现有立绘。
- 中央当前待发与历史记录分区；日志使用可滚动区域，增量追加并记录截断状态。顶部原天气/阵法/全局回合没有真实来源的示例内容移除或标为场景装饰。
- 首版包含蓝白扫描线、物品受光与点亮、灵元激活/实际消耗反馈，以及必要条值过渡；不承诺精确伤害飘字或完整动作帧。动画状态带会话身份，退出或新会话不能回流。

### 5.1. 蓝白扫描线与灵元反馈

用户提供的截图用红色横线标记了位置/跨度，要求实际表现为蓝白光线；截图仅参考表现，不能恢复其中的旧 5×6 布局或竖向多格卡规则。

- 每方一条横向细亮白芯、蓝色柔光边缘的光带，裁切在背包网格内；从上方向下扫过，扫完整包后在本方新轮回到顶端。双方使用各自 Row、Round 和 ScanProgress，不使用全局同一时间线。
- 位置由当前行与行内进度相对 TicksPerRow 的比例确定，显示帧可在已知状态之间插值。行进度是时间进度，不将光线与图标的视觉相交当成核心逐格碰撞事件。暂停后光线停止在当前已提交位置；单步只推进一个核心 Tick，再将光线与状态对齐。
- 光带扫到物品区域时允许短暂受光边缘；物品的持续点亮数量/满亮标志只由真实 AssignedTo/LitCount 等快照更新。冻结、资源不足或待发占用时不能因为扫过就显示“已成功使用”。
- 格上灵元被扫过时显示亮起/脉冲；核心确认仍在原格则保留，确认分配/移除才显示消退并更新状态。实际新增卡上资源才增加对应点亮；同 Tick 已使用清零时通过已观察的 Use/Apply/计数变化显示使用反馈，不从最终 0/n 猜成“未发动”。
- 现有接口没有完整 ManaAssigned 记录，不能为画飞行轨迹重新实现最近卡选择算法。无法确认源格与目标对应时采用行级激活、消退与卡片状态反馈，不捏造连线或先后次序。
- 充能造成单 Tick 多行/跨轮时将光线和终态对齐，允许压缩展示过渡，不额外调用 Tick 或逐条补演未观测过程；暂停/重开取消旧过渡。
- 优先用客户端绘制/渐变或 Shader 实现光线，用 Tween/材质参数做脉冲；基础灵元图标是真实生成位图，亮态由同一图标变化生成，避免为亮/暗态多生成五套图片。

### 7. Godot MCP 的使用与证据

- 可用能力已发现：项目/版本读取、场景创建与节点操作、启动编辑器、运行项目、读取调试输出、停止项目等。
- 实施时在外层 projectPath 工作；节点或场景 API 不支持所需控件属性时使用客户端文件编辑，不绕到核心补实现。
- 当前列出的 MCP 没有通用点击或截图接口。运行/调试通过 MCP；画面证据使用客户端 viewport 截图入口或实际可用的交互工具。不能把 run_project 成功当成交互/视觉验收。
- 不批量更新整个项目 UID，不让素材导入改动后端。验证默认 1440×810 和 1600×900 设计尺寸，保留关键初始/扫描/伤口/结果画面及运行日志。

## Risks / Trade-offs

- 静态 ID 与全局监听跨场残留 → 首版新游戏进程重开，窗口会重启；同进程无缝重开延后。
- 控制台输出目录数据滞后、装配顺序漂移 → 对比实际 JSON/Lua 指纹、双种子和调用顺序，重开携带完整案例身份。
- 手工测试包含中途注入，不能直接复用为可播放模板 → 先分类记录；需要适配时共享完整构造/操作/断言，不宣称全部套件已可视化。
- Getter 触发 Lua 或缓存写入 → 审核字段白名单与独立进程对照；不安全动态字段明确降级，禁止每帧查询。
- 单步内包含多次动作 → 只承诺完整 Tick 后状态与已有记录，不宣称精确逐动作回放。
- 光线扫过容易被误当成规则触发 → 受光是表现，点亮/灵元移除以核心观测为准；不修改核心或重算分配路径。
- 没有完整结果/伤害事件 → 只读已知字段及原始战报；不改后端也不在前端补算法。
- 新卡无图、风格不一致 → 有名称的占位与台账；生成后在实际格内检查，保留原件。
- MCP 运行输出不等于视觉成功 → 独立截图/操作证据，记录未能自动验证的项目。
- 内嵌 OpenSpec 根与外层客户端不同 → 明确受影响目录，实施前按本设计核对边界；不新建第二套 openspec。

## Migration Plan

三条工作线可并行：接口读取核对与验证基线；客户端会话和 UI；素材台账和已确认批次。UI 绑定依赖快照契约，首批资源接入依赖实际文件验收，最终验收依赖三线汇合。

保留静态预览及现有烟测入口；先新增可独立运行的观察场景，通过验收后再将默认场景切到观察器并更新 README。回退时切回原预览入口，撤回本变更客户端引用即可；不回滚核心、不删除已有素材或 C# 文件。全量后续图片批次另行确认，本变更首版以 A1/A2 为准。
