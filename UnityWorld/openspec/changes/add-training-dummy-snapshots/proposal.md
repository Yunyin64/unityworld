# 打木桩：按 Tick 比较构筑的输出与消耗

## Why

策划调了一张牌，想看修士是更早打出第一击、更快转完一轮，还是用同样的灵气打出了更多伤害。现有模板对战能跑真实战斗，资源追踪按固定 250 Tick 取余额，终局战报难以回答这些过程问题。

## What Changes

- 提供一份能用正式模板装配流程生成的「木桩」。开场 20 HP、30 MP、SP 占用 1/10。唯一上场卡是专用白板主功法，无战斗效果。木桩不补灵，按普通规则受伤并获得伤口。
- 对指定修士默认打木桩 100 场。固定对手、种子清单和装配顺序，允许同一套测量换成指定的已有对手。
- 快照按条配置。每条指定观察哪一方、读哪个指标、什么时候读。例如「50 Tick 伤害输出」「100 Tick 伤害输出」各自到点后由 LogMgr 暂存一条本场读数。复用已有指标时，添加一行配置就能在新时点采样。
- 每场战斗结束时自动导出一份 UTF-8 Markdown 快照报告，供关掉模拟器后离线分析。单场文件只有一张「条目ID | 值」表。依次写 `seed`、`NpcA`、`NpcB`、选定测项、`FinsihTick`、`Finishreson`。控制台继续显示普通运行日志，快照读数只进入离线报告。
- 默认测项为 `damageOut_50`、`damageOut_100` 和 `firstWoundTick`。前两项到点读取累计输出，后者在首张新增伤口落盘时记下实际 Tick，整场只写一行。循环轮数、资源消耗等可按需加入清单。每条测量都可单独启用、查询和按百场汇总，保留逐场 Markdown 原始读数及未到达的局数。

## Capabilities

### New Capabilities

- `combat-benchmark-snapshots` 定义木桩基准对战、节点快照和可复测的批次报告。

### Modified Capabilities

## Impact

复用 NPC 模板装配、真实战斗 Tick 和现有 PowerShell 模板模拟入口。新增木桩及配套功法定义、测量条目配置与 LogMgr 的离线记录和战后 Markdown 导出。批次 JSON 汇总按场引用已落盘的 `.md`。普通模板装配、背包扫描与伤口结算沿用现行规则。
