# Tasks

## 1. 周主行为与现有行为槽

- [ ] 1.1 在行为实例上表达秒制或周制，调整主槽 Tick、当前行动快照和离位清理，保留旧构造与查询入口。用周 Move 和原有“探索四方”卡交错执行秒 Tick 与世界过周，核对各自由正确时钟推进。
- [ ] 1.2 整理 `NpcSystemBehavior.OnWeek`，先核对位面和成员，再继续已有周行为或跳过秒制主行为，只有主槽空闲才进入新决策。测试只有次要行为时仍能开始周行动，途中、到达和受阻的当周都不再决策。
- [ ] 1.3 扩展 `NpcActionSnapshot` 和 `NpcWeekResult` 的只读表达，保留已有移动字段与失败语义。在结果上验证能区分当前占槽行为、当周完成的行为及可空事件与卡标识，旧移动结果调用方仍能编译。

## 2. 三个决策位置与 Move

- [ ] 2.1 在 NPC 行为系统留出目标点喜好、周主行为选择和短期落脚格选择三个空函数。逐个在函数体中注释输入、留空输出与调用时机，核对三处均无评分、权重、路线或随机实现。
- [ ] 2.2 在调用处构造实际可执行的种类列表并提供可复现的默认抽选；只有选中 Move 后才处理短期目标。沿用按出生序和周序派生的随机数，区分选行为、选格、探索用途。核对六邻与二邻各自都只贡献一个 Move 名额，同种子重放结果一致。
- [ ] 2.3 共用手动与自动 Move 启动校验，保留旧位置查询含自身格，过滤得到合法非自身落脚格。更新只依赖旧 `waited` 的断言，复验指定本格/远格被拒、50/100 跨周锁目标、150 当周到达、途中速度为零保留进度以及目标消失返回受阻。

## 3. 一周的 Explore 和 Work

- [ ] 3.1 增加 `TryStartExplore(id)`、`TryStartWork(id)` 及周工作行为，接入行为工厂和主槽，激活两种原地候选。核对启动不改日期、不动坐标，非空主槽和无效角色被拒，零速或没有合法邻格时这两种行动仍然可用。
- [ ] 3.2 给本格 `EncounterRefs` 接入最小遭遇定义和启动校验，提供事件 ID、有效命中率、可选行为卡 ID。用受控配置覆盖命中率 0、1、未配置与未知引用，能定位无效 ID 和概率，正式地图空表能正常启动。
- [ ] 3.3 让周 Explore 至多判定一个本格事件，复用持卡管理器提交授卡并记录实际结果。核对命中时持卡数只加 1、使用次数为 0；无卡事件只记事件 ID，空表或未命中都能完成，反复查询与完成通知均不重复发卡。
- [ ] 3.4 让周 Work 原地结算工作并释放主槽，在同一必定触发探索事件的格子分别完成 Explore 和 Work，核对周末都为空闲，Work 无本地事件、授卡和收益。核对死亡、离位、暂停位面、源格消失时不会串格或补执行。
