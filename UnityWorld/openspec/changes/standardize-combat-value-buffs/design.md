# 拼点与伤害数值 Buff 设计

## Context

`CombatNpc.AddModifier` 的层数字段是整数。当前按层过期将小于等于 0 视为到期，通用减层也把结果限制为非负。已有拼点强化依赖 Lua 的 `ModifyContest`，运行在待发入槽前。伤害已有来源的 `DamageOut` 和目标的 `DamageIn` 两个修正入口，后续依次结算护甲、坚甲和灵盾。旧伤害定义里仅斩击抗性有对应 Lua。

## Goals / Non-Goals

**Goals**：在现有战斗 Modifier 上表达有符号数值。策划能从动作名称直接辨认受影响角色、结算方向、持续或单次。已有内置脚本的施加调用继续有效。

**Non-Goals**：新增效果集中在拼点、出伤、入伤的固定点数变化。动作强度和持续时间的具体取值沿用当前通用模板作为初始配置。

## Decisions

### 用数据声明匹配范围

在现有战斗 Modifier 定义中声明数值变化的结算阶段、匹配范围与消费时机，由这组明确的配置启用有符号层数。定义加载时能直接检查作用阶段和范围。普通 Modifier 继续从各自配置和脚本取得行为。把 68 种状态的差异写在定义里，运行时按同一套规则读取和相加，可避免为每个状态维护一份脚本。

| 阶段 | 范围键 | 状态 ID 格式 |
|---|---|---|
| 攻击拼点 | `Attack`、`Zhan`、`Ci`、`Da`、`SheJi`、`Jin`、`Mu`、`Shui`、`Huo`、`Tu` | `<范围>_Changed`、`<范围>_Changed_Once` |
| 防御拼点 | `Defend`、`Shield`、`Block`、`Dodge` | 同上 |
| 出伤、入伤 | `All`、`Zhan`、`Ci`、`Da`、`SheJi`、`Jin`、`Mu`、`Shui`、`Huo`、`Tu` | `<范围>_DamageOut_Changed`、`<范围>_DamageIn_Changed`，单次版追加 `_Once` |

拼点状态称为「强化」，造成的伤害称为「伤害提高」，受到的伤害称为「抗性」。单次版用「单次」开头，例如「单次刺击强化」「单次斩击伤害提高」「单次斩击抗性」。动作名描述施加对象和效果方向。

物理与五行分别读取拼点或伤害事件自身的类型。一笔火系刺击同时匹配刺击、火和全范围。斩击抗性沿用按实际伤害分类判断的语义，兼容性验证包含现有无来源斩击入伤。出伤需要伤害来源，目标侧抗性只需有入伤事件。由卡值或法术标签推断伤害分类会把附带伤害误归类，分类以结算数据为准。

### 叠层和消耗遵守原有事件顺序

- 同持有者、同定义、同到期轮仍按现有规则选取叠层实例。叠层保留首次确定的 Tick 期限，续叠时依据定义处理刷新。新定义暂用现行强化的最大层数 99、叠层不刷新。限制层数绝对值时先用较宽的整数累计，再转换回层数字段。
- 有符号实例的零层立即走原移除流程，负层可存活到用掉或计时到期。五行减层、免疫和普通层数过期继续走现有入口。
- 在现有入槽前、出伤和入伤的修正入口，一次读取匹配实例，先求和、再统一钳制，随后消费本次匹配的单次实例。逐个状态钳制会使先施加强化还是先施加弱化改变结果。下次消费使用具体实例，避免误删同定义的其他实例。
- 旧自定义 Lua 修正钩子继续运行。数值 Buff 在对应阶段完成后交还现有流程。伤害若进入该阶段时为 0，本阶段跳过数值 Buff，因此出伤降至 0 后，入伤侧的易伤也不会把它抬回正数。护甲、坚甲、灵盾仍跟在入伤修正之后。

### 动作固定目标、符号和生命周期

八个拼点与八个伤害动作共用 `AddNpcBuff`。各模板只列自己的 Buff 候选，强度以正整数配置，Lua 模板按下表写入符号。持续类保留 `Duration`，沿用现有的 `-1 / 30 / 60 / 90` 候选。单次类模板传 `-1`，由首次匹配消费。直接调用 API 时仍可以给单次状态单独配置有效期。

| 动作含义 | 目标 | 结算 | 层数 | 动作 ID 前缀。持续版直接使用，单次版追加 `_once` |
|---|---|---|---|---|
| 给自己攻击强化 | Self | 攻击拼点 | 正 | `action_self_attack_contest_boost` |
| 给对手攻击弱化 | Target | 攻击拼点 | 负 | `action_target_attack_contest_weaken` |
| 给自己防御强化 | Self | 防御拼点 | 正 | `action_self_defense_contest_boost` |
| 给对手防御弱化 | Target | 防御拼点 | 负 | `action_target_defense_contest_weaken` |
| 给自己伤害提高 | Self | 出伤 | 正 | `action_self_damage_boost` |
| 给对手出伤弱化 | Target | 出伤 | 负 | `action_target_damage_weaken` |
| 给自己伤害抗性 | Self | 入伤 | 负 | `action_self_damage_resist` |
| 给对手易伤 | Target | 入伤 | 正 | `action_target_damage_vulnerability` |

按动作分组可以让选卡时直接看到用途，也把不合法的攻防、符号、目标组合排除在候选之外。例如「给对手单次攻击弱化」选择刺击 2，实际施加 `Ci_Changed_Once` 的 -2 层。

## Risks / Trade-offs

- 同一伤害可匹配全范围、物理和五行三项。全范围动作的覆盖面更大，模板评分可随配卡测试调整。
- 旧脚本可能直接写死 Buff ID。应用与移除入口只映射内置旧 ID，内置按 ID 查询及卡牌数据迁移到新 ID。状态枚举返回新的规范 ID。
- 持续和单次拥有不同 ID。同一个角色持有相反方向的持续和单次效果时，两者在匹配事件上分别贡献，只有匹配的单次实例消费。

## Migration Plan

1. 沿用 `Contest_Improved.json` 和 `Damage_Add.json` 作为配置入口，将定义改为规范 ID。原 28 个 `_Improved` 系列 ID 映射到对应拼点 ID，含旧拼法 `Doge`。
2. 旧 `*_Damage_Add` 映射到同类型的出伤持续版，层数原符号保留。旧 `*_Resist` 映射到同类型的入伤持续版，兼容入口反转层数符号。四种物理类型只映射实际存在的内置旧 ID。
3. 先接通新定义和旧入口兼容，再更新内置卡牌和 (TCA) 动作目录。保留 `AddNpcBuff` 的 Lua 参数签名，一次交付模板与状态定义，避免目录生成引用缺失。
