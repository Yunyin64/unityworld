# 拼点与伤害 Buff 的配卡动作

## MODIFIED Requirements

### Requirement: 新基础机制提供可复用的 TCA 节点

配置和接口索引 SHALL 提供拼点变化与伤害变化动作，以及装备属性、亲和、延迟收益、卸力、护甲、坚甲、灵盾、法宝供能、四向滑移、位置存在与计数、消耗比较的可用节点。胜负、邻卡使用、被位移和全场位移 SHALL 能通过公开事件及对应条件表达。

#### Scenario: 通过通用施加 Buff 选用拼点强化

- **WHEN** 策划选择攻击类型、防御类型、五行攻击、全攻击或全防御强化的持续版或单次版
- **THEN** 从对应的己方强化动作中选范围和时机，模板通过 `AddNpcBuff` 施加对应 ID，Buff 在匹配拼点生成时生效

#### Scenario: 通过防御动作施加卸力

- **WHEN** 策划为角色施加卸力 3
- **THEN** 选择防御动作 `AddDeflection` 并配置 3 点，该动作施加 3 层 `Deflection` Buff。对应 Lua 在角色下一次与敌方攻击配对时生效

#### Scenario: 组合邻卡使用与延迟加盾

- **WHEN** 策划配置右侧火法成功使用时，为本方在下一轮开始获得 2 灵盾
- **THEN** 可组合使用发布的触发、位置条件和延迟效果来执行，无需重写扫描、轮时钟或护盾扣减

## ADDED Requirements

### Requirement: 配卡目录提供八个拼点变化动作

原 `action_add_npc_buff` 的配卡入口 SHALL 由八个拼点 Action 替代。八项覆盖己方攻击强化、对手攻击弱化、己方防御强化、对手防御弱化，每项各有持续版和单次版。每个 Action SHALL 固定目标与符号，允许配置正整数强度，并仅列出对应攻击或防御范围及生命周期的 Buff ID。运行时仍通过现有 `AddNpcBuff` 施加。

#### Scenario: 给对手下次攻击弱化

- **WHEN** 策划在「给对手单次攻击弱化」中选刺击、强度 2
- **THEN** 生成的调用对 `Target` 施加 `Ci_Changed_Once` 的 -2 层。防御 Buff 不属于该动作的候选

#### Scenario: 给自己持续防御强化

- **WHEN** 策划在「给自己持续防御强化」中选格挡、强度 3
- **THEN** 生成的调用对 `Self` 施加 `Block_Changed` 的 +3 层。单次版和攻击 Buff 不属于该动作的候选

### Requirement: 配卡目录提供八个伤害变化动作

配卡目录 SHALL 提供八个伤害 Action，覆盖己方增伤、对手出伤削弱、己方伤害抵抗、对手易伤，每项各有持续版和单次版。每个 Action SHALL 固定目标、出伤或入伤和符号，允许配置正整数强度，并仅列出对应方向和生命周期的十种伤害范围。运行时仍通过现有 `AddNpcBuff` 施加。

#### Scenario: 伤害方向和符号随动作固定

- **WHEN** 策划对同一伤害范围分别选己方增伤、对手出伤削弱、己方抵抗和对手易伤，强度均为 2
- **THEN** 分别生成己方出伤 +2、对手出伤 -2、己方入伤 -2、对手入伤 +2

#### Scenario: 下次伤害抵抗

- **WHEN** 策划在「给自己单次伤害抗性」中选火、强度 2
- **THEN** 生成的调用对 `Self` 施加火入伤单次版 -2 层。出伤和持续版均不在候选中

### Requirement: 现有内置状态 ID 可兼容施加

既有内置拼点强化、物理增伤和抗性的 ID SHALL 兼容至对应的新定义，保留原有正向强化、增伤或抗性的调用含义。兼容 ID 不计入新定义和新动作的候选。脚本使用原有 `AddNpcBuff` 参数签名时，SHALL 能继续施加现有状态。

#### Scenario: 旧脚本施加下次刺击强化

- **WHEN** 旧 Lua 用 `Ci_Improved_Once` 施加 +2 层
- **THEN** 角色获得 `Ci_Changed_Once` 的 +2 层，按下次匹配拼点规则生效
