# Proposal

## Why

探索界面是玩家长时间停留的核心界面，也是以后各种功能的入口。现在地图生成已经有了，客户端也有模板编辑器和战斗观察器，但还缺少一个以当前角色和局部地图为中心、能实际打开给人看的探索界面。

这次先把素材和 UI 做好。真实移动、世界周历另做；别为了演示界面顺手改后端玩法，也别把前端预览当成真实游戏运行。

## What Changes

- 新增独立 Godot 探索场景。地图是主画面，人物放左上，地点信息放左中，日期和当前月相只在上方中央显示一份。采用贴边的游戏 HUD，背景用灰色雾气，保留现有纸面、墨绿控件和克制的铜边画风。
- 局部地图显示当前角色周围的真实地图数据。六边格改为平顶，上下压缩，支持缩放、选格和回到角色；这些操作不推进世界时间。
- 红圈的三块区域只留空间：人物下方的构筑／背包入口、右侧人物状态、底部行为／事件／推进／自动行动区。本次不显示标题、按钮、卡片、假数据或“预留”字样，也不接入现有编辑器。
- **先生成和整理可用素材，再做前端界面。** 地形素材要覆盖现有类型，角色和面板能复用就复用。完整效果图只作构图参考，不能整张贴进游戏冒充 UI。
- 用户已允许新增 `Data/Stat/NpcExplorationStat.json`：`ExploreActionSpeed` 默认 50，`ExploreDisplayRadius` 默认 5，沿用现有 Stat 的默认值和修正机制，不新建属性系统。其余后端源码、玩法数据和世界规则不在本次修改范围。
- 用明确标注的预览状态展示日期、角色位置和移动阶段，地图内容仍来自现有生成结果。真实周推进和移动另做；后续自动行动只保留客户端接入边界，本次不实现决策或执行器。
- 验收以用户看界面为主。只做必要的素材检查、一次构建、短几何检查和实际启动操作，不安排大规模回归、批量地图重测或长时间自动录制。

**数字例子：** 默认半径 5 圈，内陆位置最多显示 `1 + 3 × 5 × 6 = 91` 格；缩放到 125% 仍是这些格。预览中的邻格距离为 100，速度为每周 50：经过第一周仍在原格，第二周才展示到达。这些状态不表示本次已实现真实移动。

## Capabilities

### New Capabilities

- `exploration-ui`: 探索核心界面的布局、纯留白区域、单份日期月相、明确的预览模式、独立宿主和后端缺口处理。
- `exploration-map-view`: 真实地图的局部只读投影、平顶压缩显示、角色跟随、缩放、选格与地点详情。
- `exploration-stats`: 用现有属性 JSON 定义探索速度和显示半径，并向客户端提供一致的最终值。
- `exploration-visual-assets`: 探索背景、地形和 HUD 素材的独立资源、类型映射、复用与生成顺序。

### Modified Capabilities

无。消费现有 `tile-mgr`、地形和地图生成能力，不改变它们的规则。`improve-world-hydrology` 尚未归档的增量已对应当前河／湖／海数据；本次按当前数据读取，不顺带同步或改写那项变更。

## Impact

- 代码项目是仓库根目录的 Godot 客户端；OpenSpec 位于其下的 `UnityWorld/openspec/`。预计新增 `scenes/exploration/`、`scripts/client/exploration/`、`scripts/client/ui/exploration/`，必要时调整现有 `scripts/client/GameBootstrap.cs` 的宿主识别。
- 美术资源放在 `assets/art/exploration/`，展示映射放在 `assets/presentation/exploration_visuals.json`；已有角色和九宫格素材保持原文件不变。
- 唯一明确获准的核心数据新增是 `UnityWorld/Data/Stat/NpcExplorationStat.json`。不修改 `UnityWorld/Scripts/`、Lua、地图定义、战斗规则或现有核心工程。
- 默认 F5 入口暂时继续使用模板编辑器，探索场景用独立场景／明确参数启动。更新启动说明，让用户能直接打开检查。
- 实施时写必要注释，特别说明旧宿主分支为什么改变；交付时逐项说明改动过的原文件。
- 若现有只读接口或宿主生命周期挡住接入，先报告具体位置、缺少什么和最小改法，等待用户决定后再扩大后端范围。其他不依赖该缺口的素材和 UI 工作可以继续。
- 本次只生成提案、设计、规格和任务，不实施代码或生产素材。详细边界和参考图见 `design.md`。
