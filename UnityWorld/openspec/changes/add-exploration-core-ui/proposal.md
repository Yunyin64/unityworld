# Proposal

## Why

探索是玩家查看周边和决定下一步去哪里的核心界面。项目已经有真实大陆、世界历法、NPC 落地与按周移动，玩家需要在 Godot 里选一格、确认前往，并看到同一个角色实际走到那里。

## What Changes

- **先素材，再前端。** 准备灰雾、地形表现、人物和 HUD 资源，按当前 26 个地形 ID 建立可加载映射。保留仙侠绘景、米黄纸面、墨绿控件与轻薄铜边。
- 平顶、纵向压缩的六边地图铺满窗口，HUD 浮在地图上。左上显示受控角色，左中显示选中地点，上方中央只显示一份核心日期。普通周显示当期月相，新年和除夕显示节日名。
- 点击可见格先查看详情。空闲时再点已选合法邻格启程，核心接受后立即结算第一周。默认自动按间隔逐周走完这段已确认的路，抵达、失败或进度停滞就停止。手动模式由右下「继续」一次提交一周。途中点地图只查看，模式随时可切换。
- 构筑／背包、右侧人物状态及底部行为／事件区保留未来 HUD 位置。缩放、自动／手动切换和仅手动显示的「继续」锚定窗口右下。人物和地点面板贴左，日期栏置顶居中，随窗口实际宽高调整。[用户标注](references/user-blank-regions.png)
- Godot 通过已有工程引用调用同进程的 C# 核心。出生与位置、候选格、视野、速度、日期和到达结果都来自同一个真实会话。已交付的探索属性文件由后端维护。
- 以真实角色检查自动走到目的地、手动逐周继续、途中模式切换及窗口改宽后的控件位置。

**数字例子。** 默认速度 50、邻格距离 100。再点已选目的地后进入一月新月，人物留在原格，进度 50/100。自动模式延时走到上弦并停止；手动模式按一次「继续」后到达。内陆半径 5 显示 91 格，缩放到 125% 仍查询同一范围。

## Capabilities

### New Capabilities

- `exploration-ui` — 独立探索宿主、受控角色、日期和 HUD 布局、确认目的地、自动与手动逐周续行及错误反馈。
- `exploration-map-view` — 将后端局部地块、合法候选与已到达位置投影成可缩放、可选格的平顶地图。
- `exploration-visual-assets` — 探索美术的生成顺序、类型映射、资源复用和降级显示。

### Modified Capabilities

本次消费现行 `tile-mgr`、地形和水文能力。历法归 [add-world-calendar](../add-world-calendar/proposal.md)，世界周结算、落地、移动和 `exploration-stats` 归 [add-npc-weekly-movement](../add-npc-weekly-movement/proposal.md)。UI 的规格只定义玩家可见行为与客户端接入。

## Impact

- 在仓库根目录的 Godot 客户端增加探索素材、独立场景与会话，预计调整现有 `scripts/client/GameBootstrap.cs` 的模式识别和启动说明。现有模板编辑器继续作为 F5 入口。
- 首版会话拟使用固定种子 12345 并生成一名真实 NPC，将其 ID 绑定为当前角色。已有青衣剑修素材作为这名角色的客户端外观。运行中所有周操作由同一会话执行。
- **已知后端边界。** 核心把自身格列入空闲候选，但显式移动入口只接受邻格。空闲时直接过周会触发核心随机选择。首版点击本格用于查看。以后若需要玩家保证原地停留一周，先向用户报告所需后端指令及影响。
- 实施时在改动的宿主分支、坐标投影和周操作边界写必要注释，交付时列出改过的原文件和原因。具体接入、素材和人工检查步骤见 [design.md](design.md) 和 [tasks.md](tasks.md)。
