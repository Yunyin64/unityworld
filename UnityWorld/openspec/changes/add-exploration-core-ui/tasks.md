# Tasks

先完成第 1 组素材，接着做客户端宿主与真实角色接入，再做地图、HUD、选格和手动行走。验收时在同一个游戏窗口走完一段真实行程。未勾选的条目是待实施的探索客户端工作。

依赖 `add-world-calendar` 与 `add-npc-weekly-movement` 的现有实现。属性文件 `UnityWorld/Data/Stat/NpcExplorationStat.json` 及对应规格由后端负责。若要支持玩家主动指定本格等待一周，先报告所需指令和影响。现阶段本格用于查看。

## 1. 先生成和整理素材

- [ ] 1.1 按 `design.md` 的参考图优先级建立 `docs/art/exploration_asset_manifest.md`，列清新增、复用和不做的素材；写统一画风提示词，覆盖灰雾、平顶压缩地图、轻薄 HUD。完成检查：清单能逐项对应本期可见区域，三处留白没有按钮、卡片、状态面板或带字素材任务。
- [ ] 1.2 使用 imagegen 生成低对比灰雾背景，落盘到 `assets/art/exploration/backgrounds/gray_fog.png`；完成检查：打开图片看一遍，无蓝色山峰壁纸、人物、文字或预画地图，记录实际尺寸和来源。
- [ ] 1.3 按平野／高地与林木两组生成可共用的地面基底、必要的树木叠件，覆盖设计表中的 9 个类型；完成检查：图片均落入 `assets/art/exploration/terrain/`，光向和画风一致，透明叠件没有白边，类型映射可明确区分。
- [ ] 1.4 制作丘陵／山地、干旱和边界素材，覆盖对应 12 个类型；完成检查：雪山、火山、丹霞、沙漠、戈壁和长城等有可辨特征，山石高度不遮挡邻格，所有最终资源路径写入清单。
- [ ] 1.5 制作水域与岸地素材，覆盖 `river / lake / ocean / coast / wetland`；完成检查：河、湖、海可辨认，素材没有预画虚假的跨格连接和方向箭头，没有把湖心或宽河侧格做成陆地。
- [ ] 1.6 整理角色与头像裁切，优先复用 `jade_swordsman.png` 和已有九宫格；必要时生成探索专用轻薄面板，原图保持不变。完成检查：立绘与头像都能独立显示，九宫格缩小后边饰不过重，新增资源不覆盖原编辑器／战斗素材。
- [ ] 1.7 完成 `assets/presentation/exploration_visuals.json` 和素材清单，逐项映射当前 26 个地形 ID，注明共享基底、叠件、裁切、稳定变体和缺图降级。完成检查：引用路径都存在，基本图片检查通过，文字／选中边／月相没有烘焙进素材；这一步通过后才进入后续前端代码任务。

## 2. 接探索宿主、真实角色和地图查询

- [ ] 2.1 新增独立探索场景和 `--exploration` 模式，在原 `GameBootstrap.cs` 的宿主识别、互斥和物理帧分支旁注释原因。由探索会话初始化、启动并释放自己持有的世界。用 F6 或明确命令进入场景，等待期间日期稳定，并核对默认 F5、观察器和现有烟测模式的启动行为。
- [ ] 2.2 默认以种子 12345 在主位面用 `NpcSystem.Spawn(new BirthContext())` 创建并落地一名真实 NPC，持有返回的 ID。用角色自己的身份数据、位置查询及明确绑定的视觉资源生成左上人物与地图标记。核对注册、落地结果及失败提示，确认头像和地图标记指向同一 NPC。
- [ ] 2.3 从现有位置与行为系统读取 `GetPosition`、`GetVisibleTiles`、`GetMoveCandidates`、`GetAction`、行动速度和显示半径，从 `WorldTime.CurrentDate` 读日期。记录只读来源和刷新时机。检查默认速度 50、半径 5、内陆 91 格以及候选受阻过滤，确认属性数据和旧属性计算由现有核心提供。

## 3. 做前端地图和手动行走

- [ ] 3.1 实现平顶格与统一纵向压缩。地面、水域端点、人物脚点、选中边和鼠标命中共用投影及逆变换，写清 Axial 坐标和点击角落的处理。用短检查验证六邻、纵向系数 0.65、125% 缩放后的命中和边界裁切。
- [ ] 3.2 按真实可见地块绘制素材、地区／地标和水文，人物保持正常比例。选中地点与角色已到达位置分别保存。检查视野内格子数量、河湖海、无中心线水格、跨格重叠区的稳定外观，以及缺图时真实名称和符号。
- [ ] 3.3 组装灰雾背景、左上人物、左中地点、上中唯一日期。普通周显示一个当前月相，新年和除夕显示节日名。核对三处留白没有控件、热点和焦点，日期和缩放控件都在允许区域。
- [ ] 3.4 单击可见格查看地点，滚轮／按钮缩放，中键拖动，回到角色时对准实际位置。地点栏展示真实名称、距离及可计算的预计耗时。检查远格、自身格和阻挡格可查看，操作前后的日期与位置相同。
- [ ] 3.5 在**地点栏**接入确认前往。提交前核对当前 NPC、位面、可见范围和最新合法邻格，`TryStartMove` 成功后调用一次 `WorldMgr.AdvanceWeek()`。操作文案明确消耗一周。核对默认首周在原格 50/100，拒绝提交的日期不变。
- [ ] 3.6 途中在**同一地点栏**继续锁定行程一周。独立查看其他地点时仍绑定原目标。按受控 ID 读取 `WorldWeekResult` 和动作快照，处理当周变速、受阻、角色缺失、预检异常及部分提交。检查一次输入只提交一次，`Complete=false` 停止行走输入，查明实际结果后再刷新角色与镜头。
- [ ] 3.7 更新 `README_GODOT.md`、`scripts/client/README.md` 或其链接的短使用说明，给出实际场景命令、查看与确认的差别、地点栏续行及三处留白。检查命令可复制使用，按用户要求在交付清单列出原文件和改动原因。

## 4. 轻量集成检查和用户目视验收

- [ ] 4.1 构建一次 `dotnet build Xianxia.Client.csproj`，在真实探索场景从新年开始，用默认角色单击一个合法邻格、地点栏确认前往、再继续一周。核对原格 50/100 与新月、到达／空闲与上弦。控制台演示作为核心基线，Godot 输入是否接通以本次实际操作为准。
- [ ] 4.2 在同次操作查看近格／远格、缩放、拖动和回到角色，检查 1440×810 与 1600×900 的留白、角色比例及单份日期。截取至多两张有代表性的画面。顺手确认模板编辑器和战斗观察器原入口能打开。
- [ ] 4.3 把可直接运行的命令、受控角色的操作路径、已检查结果、遗留的手动等待接口问题及原文件改动说明交给用户，供其自行判断素材密度、格子压缩和界面观感。
