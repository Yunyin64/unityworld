# Design

## Context

动机与本次范围见 [proposal.md](proposal.md)。本文按“先讲规则，再给数字例子”的顺序，把能直接开工的设计说清楚。

### 最新决定

- 这是探索阶段的核心界面，以后很多功能都从这里进入。布局和组件需要能扩展，但这次别把以后要做的功能全画出来。
- 用户最后圈掉的地方只留白：构筑／背包入口、右侧人物状态、底部行为／事件／推进／自动行动。不是灰掉按钮，也不是写“预留”，就是空着。
- 用户已确认这次先做素材和 UI。真实移动、世界周历另做，日期和角色位置可以使用明确标注的预览状态。
- 用户明确允许新增独立属性 JSON，沿用现有机制。除这个数据文件外，先不改后端；遇到卡点先通知用户。
- 用户要求先素材、再前端。之前讨论中的“先做移动后端”不再是这次的任务顺序。
- 测试少而够用，最后让用户自己看画面。不要用大量自动验证替代实际观感。

## Goals / Non-Goals

**Goals:**

- 把真实地图数据、预览角色／时间输入和 Godot 显示分开，之后换成真实探索会话时能复用地图和 HUD。
- 让素材、地块投影、点击命中和 HUD 布局各有明确归属，避免全部堆在一个场景脚本里。
- 保留未来功能的布局位置与组合点，但不提前建立未定的功能模块、业务接口或界面按钮。
- 用户拿到工程后可以直接打开一个默认预览，再打开途中、到达状态对照效果。

**Non-Goals:**

- 不实现世界周结算、真实角色逐格移动、行动队列、自动策略、遇敌、探索迷雾或存档。
- 不实现构筑／背包入口、右侧状态面板、底部行为事件栏，也不保留不可见的点击热点。
- 不改变世界生成、河湖海数据、Lua、战斗、NPC 生长／修炼或元气时间语义。
- 不把 UI 预览设计成第二套可运行的玩法后端，不新增通用插件框架或全局 Manager。
- 不承诺这次完成正式游戏启动流程、发布包或所有分辨率适配；先支持现有桌面窗口。

## Decisions

### 1. 先完成素材，再进入前端实现

**规则：** 先把界面真正需要的图片和复用映射准备好，检查能加载、能裁切、大小合适，再开始场景和控件实现。不能先用整屏效果图铺底，后面再补资源。用户自己看最终效果，不新增“每张素材必须先获批准”的中间门槛。

顺序为：资源清单与统一提示词 → 灰雾与地形素材 → HUD／角色复用整理 → 基本素材检查 → 属性 JSON 和客户端只读适配 → Godot UI → 轻量检查与用户验收。

**数字例子：** 素材映射需要覆盖当前 26 个地形 ID，但不要求生成 26 张互不相关的大图。平原、草原和盆地可以共用地面基底，通过明确映射和配色区分；河、湖、海必须能看出区别。

采用这个顺序，是为了避免界面做好后才发现角色边缘、地形视角和面板比例完全不合。暂不采用“先写整套交互再用占位图替换”的方式。

### 2. 美术拆成独立资源，不拆效果图里的界面文字

**规则：** 生成位图时使用 imagegen；地形与背景、角色与地图、控件底图与文字分开。标题、属性、日期和月相由 UI 绘制，生成图片不带字。已有角色优先复用，地图地面压缩不影响人物纵横比。

| 类别 | 计划输出或复用 | 具体要求 |
| --- | --- | --- |
| 灰雾背景 | `assets/art/exploration/backgrounds/gray_fog.png` | 低对比中性灰，无蓝色山峰、花哨景观、文字、人物、格子或面板；首版静态即可 |
| 地形基底与叠件 | `assets/art/exploration/terrain/` | 统一俯视／低斜视角和光向；不带格边、金框、坐标、角色或地标名称；地面纹理可铺满后由六边形裁剪，树石叠件需要干净透明边 |
| 轻薄 HUD | 优先引用 `assets/art/ui/template_editor/panel_frame.png` | 通过探索专属九宫格显示边距减轻角饰；确实不合适再生成 `assets/art/exploration/ui/panel_frame.png`，不覆盖原图 |
| 人物与头像 | `assets/art/characters/jade_swordsman.png` | 分别复用现有立绘和头像裁切；不从整屏截图抠角色，不重做人物设定，不制作移动动作序列 |
| 地点缩略图 | 由选中地形的同一素材组合显示 | 不为了每格详情再生成一张假风景；有真实地标就加对应名称，未知地标先用通用标记 |
| 当前月相、选择边和操作符号 | Godot 简单图形、文字或已有图标 | 月相只画当前一档；高亮和缩放符号无需生成大套位图 |

**尺寸例子：** 背景以约 2048×1152 为生成目标；地形基底／透明叠件可用 512 或 1024 像素源图，实际格内按显示尺寸采样。尺寸是制作起点，可按清晰度调整，不作为新增的玩法限制。

生成提示词要固定已有仙侠绘景和白发青衣角色的风格：低饱和、地形可辨、光向统一。灰雾专门用背景提示词，不能把人物、山水壁纸或完整地图混进去。背景使用不透明输出，树石等独立叠件要求真实 alpha。

### 3. 地形按族制作，按真实 ID 完整映射

**规则：** `assets/presentation/exploration_visuals.json` 保存客户端展示映射，不修改 `TileDefines` 的玩法字段。每种地形都必须有明确表现路径；共享资源也要列出自己的条目。

| 素材批次 | 必须覆盖的地形 ID | 表现重点 |
| --- | --- | --- |
| 平野与高地 | `plain`, `grassland`, `basin`, `alpine_meadow`, `plateau` | 草密度、地色和低矮地势差异 |
| 林木 | `forest`, `bamboo_forest`, `rainforest`, `forest_mountain` | 常规林木、竹、密林和山地组合，避免整片树挡住角色 |
| 丘陵与山地 | `hill`, `loess_hill`, `mountain`, `barren_mountain`, `karst`, `red_cliff`, `snow_mountain`, `volcano` | 岩色、植被、雪和火山特征；山体不要高到遮住邻格 |
| 干旱地形 | `desert`, `gobi`, `dry_valley` | 沙、碎石和干谷纹理区分 |
| 水域与岸地 | `river`, `lake`, `ocean`, `coast`, `wetland` | 河湖海分开；水面、岸地和湿地可以组合，连接关系依真实数据 |
| 世界边界 | `great_wall` | 克制的长城／阻隔地形标识，不依赖新增建筑系统 |

映射至少记录资源路径、必要裁切、地面或叠件分类、显示比例、变体规则和缺图降级。变体按世界种子、位面和格坐标稳定选择，镜头动了不能重新随机。地形出现哪些、在哪里、是否能走，仍由真实数据决定。

**数字例子：** 两种地形可以引用同一张草地基底，但 `plain` 与 `alpine_meadow` 保留不同条目、名称和配色。重新打开同一种子地图，某个格子仍选同一绘景变体。

河段端点用真实六邻方向投影；湖面和宽河侧格即使没有中心线也仍是水格。不要拿一张画好了整条河的装饰图跨格覆盖真实地图。未知合法类型或缺图时显示该类型的 `Color + DisplayName/Symbol` 并记录缺项；首批已知 26 类不能靠这个降级长期冒充素材完成。

素材阶段另交一份简短清单，计划放 `docs/art/exploration_asset_manifest.md`：生成／复用来源、最终路径、提示词、尺寸、透明和裁切信息、基本目视结果。不要写大型生成审计系统。

### 4. 灰雾铺底，三块空白作为布局边界

**规则：** 地图不用大外框，HUD 紧凑贴边。人物左上，地点左中，唯一日期在上中，缩放与回到角色靠地图边缘。三块未来功能区只有布局安全范围，不绘制面板，不放“预留”字样。不要把被取消的进度条或行为按钮换个位置塞回来。

| 区域 | 本期显示 | 本期交互 |
| --- | --- | --- |
| 左上人物 | 头像、姓名、已知身份；预览输入明确是示例 | 本次无人物管理入口 |
| 人物下方留白 | 灰雾背景 | 无构筑／背包按钮、提示或焦点 |
| 左中地点 | 选中格名称／类型、已有地区或地标、位置、通行和预计耗时 | 由选格更新；不是进入地点或执行行为按钮 |
| 上方中央时间 | 当前周、一个当前月相、小“预览”标识 | 不放暂停／播放／推进按钮 |
| 中央地图 | 局部格子、当前角色、选中格和候选范围 | 选格、拖动、缩放 |
| 地图右侧留白 | 灰雾背景 | 无人物状态和移动进度面板 |
| 地图边缘控件 | 缩放比例、缩小、放大、回到角色 | 只改镜头 |
| 底部留白 | 灰雾背景 | 无行为卡、事件槽、继续行路和自动行动按钮 |

**布局例子：** 1600×900 下，左侧信息列约 240～270 像素，顶部日期高约 50 像素，底部留白约 120～150 像素，右侧保留约 220 像素。地图在剩余区域适配；到 1440×810 时按可用面积调整间距，不能把文字挤到地图上。这些值是布局起点，用户看效果后可以调。

用少量独立的布局区域组织场景。空白区域可以有命名的布局计算结果，但不创建按钮、Tooltip、焦点节点；辅助 Control 使用忽略鼠标的设置。地图绘制和拖动裁切在自己的有效视区内，不能用地图侵占保留区。

未来功能可以在组合层接入这些区域。这次不做插件注册、动态菜单系统或空业务管理器，避免把未知玩法提前定死。

### 5. 平顶与纵向压缩只发生在客户端投影

**规则：** 继续使用核心的 Axial `Q/R` 和六邻坐标，前端用平顶公式投影。水文连接、角色脚点、选格边和鼠标逆变换共用同一组参数。底图可以压缩，人物、图标和文字不跟着压扁。

设普通六边形边长为 `a`，纵向系数为 `c`，相对角色中心坐标为 `q/r`：

```text
x = 1.5 * a * q
y = sqrt(3) * a * (r + q / 2) * c
```

再应用镜头平移和缩放。点击先撤销平移、缩放和纵向压缩，再计算小数 Axial 坐标并按 cube rounding 取格；用实际六边形边界处理角落命中，不能用重叠的矩形点击框。方向编号仍使用核心数组，通过邻格投影得到屏幕端点，不能把原注释里的“右／右下”直接当新屏幕方向。

**数字例子：** `a=42`、`c=0.65` 时，单格宽约 84 像素、高约 47 像素，顶边和底边水平。界面放大到 125% 后，显示约为 105×59 像素；逻辑相邻距离仍为 1，路程示意仍为 100。

纵向系数放探索表现配置，先用 0.65；可以在不改规格的前提下按用户观感微调。没有必要旋转或重生成整个世界，更不能修改核心 `TileId.Directions` 来迎合 UI。

### 6. 显示范围、镜头和选中格分别保存

**规则：** 显示范围跟当前角色位置和半径走；镜头可以在这个范围内观察，选中格只负责地点详情。选远格不移动角色，缩小地图也不揭露更远的世界。本版没有探索迷雾，范围内数据完整显示，灰雾只在范围外。

默认支持鼠标点选、滚轮或按钮缩放、按住中键拖动画布、回到角色。控件输入不穿透为地图点击。缩放建议范围为 50%～200%，按钮每次 25%；这些是表现参数，不是角色属性，也不改变查询半径。

**数字例子：** 半径 5 时，内陆最多 91 格；半径 6 时最多 127 格。选中距角色 3 格的山地只更新地点详情，金边候选范围仍只对应当前格和六邻格。放大到 125% 后还是相同的一组地块。

金边表示本格和六邻的候选范围，不保证每格都能走。只读通行提示取当前地块／地形定义允许的移动方式和阻挡信息；不明确的情况标为未知，不在客户端实现另一套移动规则。远格可以查看，但不显示可执行的直达承诺。

半径过大时按真实位面边界查询或遍历实际格集合，不按外部半径分配平方级空数组。局部网格随角色位置或有效半径改变才重建；拖动、缩放不触发世界生成。

### 7. 两项数值放独立 JSON，复用 Stat 只读值

**规则：** 唯一获准的核心数据新增是 `UnityWorld/Data/Stat/NpcExplorationStat.json`。沿用 `StatDefineMgr` 目录加载，无需改加载器。两个属性使用 `Type=Npc`、`BaseType=Derived`、空 `ExtraBase`，让 `DefaultValue` 作为底值参与现有修正；不引入新的属性枚举或 Manager。

| ID | 显示名 | 默认值 | 下限／上限 | 用途 |
| --- | --- | --- | --- | --- |
| `ExploreActionSpeed` | 行动速度 | 50 | 0／无额外上限 | 距离／周，只读预计耗时与后续动作接入 |
| `ExploreDisplayRadius` | 显示半径 | 5 | 0／无额外上限 | 地图查询圈数，最终值向下取整 |

定义可以包含清楚的 `Description`、`Category=探索` 和显示格式；JSON 保持合法，不加注释语法。数值含义的注释放在投影代码及说明里。

真实角色存在时通过其 `StatBlock.GetReadOnly` 读取。预览角色没有真实 NPC 身份时，用客户端独立属性块读取同一份定义；不用新造 NPC 或修改 NPC 数值来获得 50 和 5。定义存在性、源配置有限性和结果有限性分别检查，不能用 `GetReadOnly` 的 fallback 参数掩盖定义没加载。

**数字例子：** 默认半径 5，加值 1 后为 6，显示最多 127 格；最终值 5.9 取 5 圈；0 只显示中心。速度 50 时，相邻距离 100 的预计时长为 2 周；正速度的预计整周数取 `ceil(100 / speed)`，速度 0 显示不可计算，自身停留提示固定 1 周。

这里计算的是地点详情的预计值，不是实际行动执行器。地形现有 `MovementCost` 本次不自动乘入前述距离例子；这项未来规则需要与正式移动后端一起决定。

### 8. 真实地图与预览人物状态分开输入

**规则：** 地图必须来自已有世界生成与只读查询；演示日期、人物位置和阶段保存在客户端明确的预览输入中。世界初始化失败就显示问题，不用随机画一张假地图兜底。预览切换不调用 `WorldMgr.Tick`、`WorldTime.Advance`、`PlaneMgr.MoveNpc`，也不直接写 `NpcPositionData`。

建议新增以下客户端小组件，名称可以依现有风格微调：

| 位置 | 职责 |
| --- | --- |
| `scripts/client/exploration/ExplorationPreviewSession.cs` | 独立会话生命周期、预览输入、地图读取，持有自己创建的世界 |
| `ExplorationSnapshot.cs` | 面向 UI 的值数据，包含角色视角、局部地块、选中信息和预览日期，不暴露可写领域对象 |
| `ExplorationPreviewCases.cs` | 解析初始／途中／到达预览，用同一输入构造明确的视觉状态 |
| `ExplorationStatProjection.cs` | 定义检查、只读属性值、半径转换和预计时长 |
| `scripts/client/ui/exploration/ExplorationView.cs` | 组合地图、HUD 和留白布局 |
| `ExplorationMapView.cs` | 局部格子、统一投影、渲染与命中、镜头与选择 |
| `ExplorationHud.cs` | 左上人物、左中地点、上中唯一时间和预览标识 |
| `ExplorationSkin.cs` | 独立素材配置、九宫格、字体与表现参数 |
| `scenes/exploration/exploration_view.tscn` | 可直接运行的探索场景 |

不要拆成大量只转发参数的类，也不要把所有对象做成全局单例。上述职责可以合理合并，但只读来源、预览输入和显示边界必须清楚。

地图使用现有 `WorldMgr.Initialize` 和所需的正常初始化入口建立一次结果；默认种子沿用项目常用的 12345。预览出发格按真实数据在地图中部确定：优先接近中心且有有效步行邻格的陆地，平局按稳定坐标顺序选择；目标取一个真实相邻可步行格。三种预览重用同一选择算法、种子和配置；不把“林间小径”强写成真实地块名称。

如后续有真实受控 NPC，可由外部会话显式提供 NPC ID 和位置投影。本版不建立控制权系统，也不把点击头像或选地块解释成换角色。

### 9. 三个固定预览代替实际行动循环

**规则：** 本次用可分别启动的静态状态看 UI，不提供“下一周”执行功能。预览本身保持停住，宿主帧率、鼠标操作和等待时间都不推进周数。默认案例使用已经讨论过的 50 速度、100 距离的示意，不宣称这些状态由游戏模拟跑出来。

| 启动案例 | 预览已过周数 | 地图角色位置 | 预览阶段数据 | 屏幕日期 |
| --- | --- | --- | --- | --- |
| `initial` | 0 | 出发格 | idle | 第 1 周 · 新月 |
| `moving` | 1 | 仍在出发格 | move，示例进度 50/100 | 第 2 周 · 上弦 |
| `arrived` | 2 | 相邻目标格 | idle，示例动作完成 | 第 3 周 · 满月 |

阶段和进度可以写入开发日志或预览快照，但本期不为它们恢复右侧状态面板、底部行动条，也不搬到头像旁变相显示。屏幕只以角色落格、选中目的地和日期呈现区别，并始终显示小“预览”标识。

月相是从输入周序号推导的纯显示：`[新月, 上弦, 满月, 下弦][elapsedWeeks % 4]`；画面周数为 `elapsedWeeks + 1`。上弦用右半亮、下弦用左半亮；只显示一个当前月相。不引入真实月长、年份、季节或秒到周的换算。

**数字例子：** 同样已经走过一周，途中预览把人物留在出发格，不做两格之间的插值位移。到达预览才把标记换到目标格。世界自己的时间和 NPC 位置始终没变。

这些固定案例只演示默认数值下的画面关系。修改属性 JSON 后，显示半径和地点预计时长读取新值，但固定案例不能被解释为新数值下的实际模拟结果；如需演示不同数值的动作阶段，使用明确标注的独立预览输入，不偷改真实属性去迎合案例。

未来接入手动或自动行动时，接在会话外部的命令提供方，再把真实结果作为同一显示输入送入。这里只保留组合边界，不实现队列、自动决策或新的时钟。

### 10. 显式探索宿主，不改变默认编辑器入口

**规则：** 为探索预览新增明确的客户端宿主分支。`GameBootstrap` 识别后停止自己的物理帧 Tick，由探索会话初始化和释放自己持有的世界。不要同时让 Bootstrap 和探索会话初始化两次，也不要反射清理核心静态状态来支持混用。

保留“显式模式 → 请求场景 → 默认场景”的现有优先级。探索与 World／Observer／TemplateEditor 互斥；非法案例名直接报错，不能回落到 World。默认 F5 仍进模板编辑器；用户可选探索场景按 F6，或用明确命令启动。

**启动例子：** 在仓库根目录执行，`godot` 替换为本机 Godot .NET 路径：

```powershell
godot --path . res://scenes/exploration/exploration_view.tscn -- --exploration-preview=initial
godot --path . res://scenes/exploration/exploration_view.tscn -- --exploration-preview=moving
godot --path . res://scenes/exploration/exploration_view.tscn -- --exploration-preview=arrived
```

启动生成地图只做一次。不要在每帧、选格或缩放时重新生成世界。若现有初始化确实造成无法接受的接入问题，按下节报告，不顺手优化核心生成器。

### 12. 轻量验收，用户看效果

**规则：** 开发方只确认能用、没明显错位和没越过范围。不要为本次 UI 搭一套大型测试平台，已有历史回归不全部重跑。失败或后续修改影响同一检查项时，再重跑相关项。

最小检查集：

1. 素材路径、透明边、裁切、九宫格和 26 类映射看一遍；确认河湖海能区分。
2. 执行一次 `dotnet build Xianxia.Client.csproj`，区分原有警告和本次错误。
3. 做一个短几何／属性检查，覆盖平顶方向、半径 5 的 91 格、压缩缩放后的命中、读取默认属性和一次半径加值。可以利用已有测试方式或小检查脚本，不复制生产算法来制造无意义通过。
4. 实际打开探索，选近格／远格、缩放、拖动、回到角色。分别打开三个预览，不通过产品按钮推进。
5. 在 1440×810 和 1600×900 看布局：头像、地点、唯一月相、三块留白和地图都不互相挤占。留最多两张有代表性的截图供用户对照。
6. 轻点确认原模板编辑器和战斗观察器仍能按原方式启动，不跑长战斗或完整数值回归。

用户验收主要看：地图舒服不舒服、格子是否横边朝上并压得合适、角色是否好找、地点详情是否易读、空白够不够以后放功能。用户反馈再调，不把自动截图当作审美通过。

## Risks / Trade-offs

- [真实后端还没接，预览容易被看成游戏完成] → 常驻小“预览”标识，固定案例单独启动，交付明确不含真实周推进和移动。
- [旧效果图上的按钮被重新做回来] → 用户留白标注高于效果图；素材清单、场景树和人工检查都排除三处可见内容及透明热点。
- [平顶改变了视觉方向，河段或点击错位] → 使用同一 Axial 投影与逆变换，方向端点从真实邻格计算，短检查覆盖压缩和缩放。
- [素材生成数量膨胀] → 按族共用素材、按 ID 完整映射；角色与面板优先复用，不生成未实现功能的装饰素材。
- [新属性读取被写成另一套公式] → 使用现有只读最终值；只新增定义，缺值明确报告，不硬编码或修改核心 Stat。
- [探索误入默认自动 Tick] → 新宿主模式显式互斥；初始化和释放归一个会话，查看行为不调用世界推进。
- [旧文档与当前实现不同] → 以当前代码、数据和本提案的明确范围为准；不顺带改其他 OpenSpec 变更。
- [轻量检查覆盖有限] → 如实交付已检查内容与后端边界，给用户直接启动入口；不宣称完整玩法或长期运行已经验收。

## Migration Plan

这是新增客户端场景和资源，不迁移存档或现有世界数据。

实施顺序按任务清单走：先资源，再独立属性定义与只读预览适配，再界面，最后少量检查和用户验收。默认编辑器入口不切换。所有新增素材落在项目路径，生成工具缓存只保留来源副本，运行时不依赖缓存路径。

回退时移除本次新增场景／资源引用和宿主分支，撤回独立探索属性文件；原编辑器、战斗场景、世界规则和已有美术仍保持原用途。不要删除用户其他未提交改动。
