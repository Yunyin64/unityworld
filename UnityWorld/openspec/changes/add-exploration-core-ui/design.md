# Design

## Context

玩家从自己的角色所在格查看周边，在左中地点栏确认一个可步行的邻格。核心接受这一目的地后，客户端请求世界结算一周。若人物仍在途中，玩家再次确认续行才能经过下一周。目标、位置、进度和日期都来自这一个真实运行的世界。[提案](proposal.md)

本设计依据 2026-11-09 的代码。文件路径相对仓库根目录 `C:\Unity\Game\unityworld`，OpenSpec 根目录是其中的 `UnityWorld`。

| 现有能力 | 本次接入点 |
| --- | --- |
| `project.godot`、`scripts/client/GameBootstrap.cs` | F5 进入模板编辑器。探索通过单独的 Godot 场景和宿主模式启动，拥有自己的世界生命周期。 |
| `Xianxia.Client.csproj` | .NET 8 客户端已通过 ProjectReference 引用核心，并编译 `scripts/client/**/*.cs`。 |
| `WorldMgr`、`WorldTime`、`WorldDate` | 生成大陆，初始化时间。`WorldMgr.AdvanceWeek()` 统一结算日期与各位面成员。`WorldTime.CurrentDate` 提供日期及可空月相。 |
| `Plane.NpcSystem.Spawn`、`NpcMgr` | 在合法地块生成并注册 NPC，返回实际实体。探索会话持有本次返回的角色 ID。世界初始化本身只准备地图和系统。 |
| `NpcSystemPosition`、`NpcSystemBehavior` | 查询位置、视野、移动候选、行动速度和动作，显式启动真实邻格移动。 |
| `Plane.TileSystem`、`TileId`、`Tile` | 查询真实地块与步行能力。轴坐标和六邻方向也用于水文端点，绘制和命中统一使用客户端平顶投影。 |
| `UnityWorld/Data/Stat/NpcExplorationStat.json` | 现行 `ExploreActionSpeed` 和 `ExploreDisplayRadius` 分别默认 50 和 5。位置系统从 NPC 属性块读取最终值并处理半径取整。 |
| `UnityWorld/Data/TileDefines/`、`assets/presentation/template_editor_visuals.json` | 26 个地形 ID 需要展示映射。角色、头像、材质、字体可从现有资源复用。 |

本变更维护 `exploration-ui`、`exploration-map-view` 和 `exploration-visual-assets`。日期语义归 [add-world-calendar](../add-world-calendar/proposal.md)，NPC 落地、移动、世界周结算及 `exploration-stats` 归 [add-npc-weekly-movement](../add-npc-weekly-movement/proposal.md)。水系按当前大陆的 `river / lake / ocean` 数据绘制。[已有水文设计](../improve-world-hydrology/design.md)

## Goals / Non-Goals

首版完成一个玩家能直接打开的桌面探索窗口。它在同一会话内完成角色出生、查看、确定目的地、结算首周、确认续行与到达。界面尺寸以 1600×900 与 1440×810 为验收范围。构筑／背包、右侧人物状态和底部行为／事件／推进／自动行动均留白。遇敌、存档、自动行动、全局控制权、多角色切换和玩家指定原地待机留待各自需求确定。

## Decisions

### 1. 素材先于前端

先准备灰雾背景、地形基底与叠件、HUD 和角色映射，核对路径、透明边、显示尺寸及裁切。素材基本检查通过便开始探索会话和界面开发，无逐张审批环节。其后接入已有世界接口、搭建地图与地点栏，最终以一次真实行程检查操作及视觉效果。

### 2. 美术拆成独立资源，不拆效果图里的界面文字

**规则：** 生成位图时使用 imagegen；地形与背景、角色与地图、控件底图与文字分开。标题、属性、日期和月相由 UI 绘制，生成图片不带字。已有角色优先复用，地图地面压缩不影响人物纵横比。

| 类别 | 计划输出或复用 | 具体要求 |
| --- | --- | --- |
| 灰雾背景 | `assets/art/exploration/backgrounds/gray_fog.png` | 低对比中性灰，无蓝色山峰、花哨景观、文字、人物、格子或面板；首版静态即可 |
| 地形基底与叠件 | `assets/art/exploration/terrain/` | 统一俯视／低斜视角和光向；不带格边、金框、坐标、角色或地标名称；地面纹理可铺满后由六边形裁剪，树石叠件需要干净透明边 |
| 轻薄 HUD | 优先引用 `assets/art/ui/template_editor/panel_frame.png` | 通过探索专属九宫格显示边距减轻角饰；确实不合适再生成 `assets/art/exploration/ui/panel_frame.png`，不覆盖原图 |
| 人物与头像 | `assets/art/characters/jade_swordsman.png` | 分别复用现有立绘和头像裁切；不从整屏截图抠角色，不重做人物设定，不制作移动动作序列 |
| 地点缩略图 | 由选中地形的同一素材组合显示 | 不为了每格详情再生成一张假风景；有真实地标就加对应名称，未知地标先用通用标记 |
| 当前月相、选择边和操作符号 | Godot 简单图形、文字或已有图标 | 月相只画当前一档；高亮和缩放符号无需生成大套位图 |

**尺寸例子：** 背景以约 2048×1152 为生成目标；地形基底／透明叠件可用 512 或 1024 像素源图，实际格内按显示尺寸采样。尺寸是制作起点，可按清晰度调整，不作为新增的玩法限制。

生成提示词要固定已有仙侠绘景和白发青衣角色的风格：低饱和、地形可辨、光向统一。灰雾专门用背景提示词，不能把人物、山水壁纸或完整地图混进去。背景使用不透明输出，树石等独立叠件要求真实 alpha。

### 3. 地形按族制作，按真实 ID 完整映射

**规则：** `assets/presentation/exploration_visuals.json` 保存客户端展示映射，不修改 `TileDefines` 的玩法字段。每种地形都必须有明确表现路径；共享资源也要列出自己的条目。

| 素材批次 | 必须覆盖的地形 ID | 表现重点 |
| --- | --- | --- |
| 平野与高地 | `plain`, `grassland`, `basin`, `alpine_meadow`, `plateau` | 草密度、地色和低矮地势差异 |
| 林木 | `forest`, `bamboo_forest`, `rainforest`, `forest_mountain` | 常规林木、竹、密林和山地组合，避免整片树挡住角色 |
| 丘陵与山地 | `hill`, `loess_hill`, `mountain`, `barren_mountain`, `karst`, `red_cliff`, `snow_mountain`, `volcano` | 岩色、植被、雪和火山特征；山体不要高到遮住邻格 |
| 干旱地形 | `desert`, `gobi`, `dry_valley` | 沙、碎石和干谷纹理区分 |
| 水域与岸地 | `river`, `lake`, `ocean`, `coast`, `wetland` | 河湖海分开；水面、岸地和湿地可以组合，连接关系依真实数据 |
| 世界边界 | `great_wall` | 克制的长城／阻隔地形标识，不依赖新增建筑系统 |

映射至少记录资源路径、必要裁切、地面或叠件分类、显示比例、变体规则和缺图降级。变体按世界种子、位面和格坐标稳定选择，镜头动了不能重新随机。地形出现哪些、在哪里、是否能走，仍由真实数据决定。

**数字例子：** 两种地形可以引用同一张草地基底，但 `plain` 与 `alpine_meadow` 保留不同条目、名称和配色。重新打开同一种子地图，某个格子仍选同一绘景变体。

河段端点用真实六邻方向投影；湖面和宽河侧格即使没有中心线也仍是水格。不要拿一张画好了整条河的装饰图跨格覆盖真实地图。未知合法类型或缺图时显示该类型的 `Color + DisplayName/Symbol` 并记录缺项；首批已知 26 类不能靠这个降级长期冒充素材完成。

素材阶段另交一份简短清单，计划放 `docs/art/exploration_asset_manifest.md`：生成／复用来源、最终路径、提示词、尺寸、透明和裁切信息、基本目视结果。不要写大型生成审计系统。

### 4. 贴边布局与地点栏

| 区域 | 显示与交互 |
| --- | --- |
| 左上 | 受控角色的头像、`npc.GetName()` 与可用身份。青衣剑修立绘及头像由探索会话显式绑定。姓名来自核心，出生上下文未提供姓名时使用“修士 #实体 ID”作为识别文字。 |
| 人物下方 | 为构筑／背包留下灰雾背景。 |
| 左中 | 选中格真实名称／类型、缩略图、坐标、地区／地标、通行信息。空闲时对合法邻格提供“启程并推进一周”，途中显示锁定目标名称／坐标与“继续前往该目标 · 一周”。 |
| 上方中央 | 唯一日期栏。普通周显示年月与当期月相，特殊周显示年份与“新年”或“除夕”。 |
| 中央地图 | 显示实际局部地块、受控角色、选中格与核心候选。支持点选、拖动、缩放。 |
| 地图边缘 | 缩小、比例、放大、回到角色，仅作用于镜头。 |
| 右侧与底部 | 分别为人物状态及行为／事件／推进／自动行动保留灰雾背景。 |

1600×900 下，左侧信息列约 240～270 像素，顶部日期高约 50 像素，底部留白约 120～150 像素，右侧约 220 像素。地图在剩余面积适配，1440×810 按实际可用尺寸收紧间距。地点栏的目标和周操作收在左中现有区域。三处留白只参与布局计算，地图视区在其外裁切。若需要辅助 Control，设为忽略鼠标、不可聚焦且不注册 Tooltip，使留白完全没有热点。

### 5. 平顶投影、点击和镜头

保留核心轴坐标 `Q/R` 及方向序号。用相对角色的 `q/r`、六边形边长 `a` 和纵向系数 `c` 得到地面中心，再施加镜头平移与缩放。

```text
x = 1.5 * a * q
y = sqrt(3) * a * (r + q / 2) * c
```

鼠标点击先撤销平移、缩放和压缩，再反算分数轴坐标并做 cube rounding。边缘按实际六边形计算命中。地形填充、六邻边、水流端点、角色脚点用同一组变换。人物、文字、操作图标按正常纵横比绘制。核心方向注释曾按尖顶图解释屏幕方位，水流直接投影实际邻格以正确连接两端。

初值 `a=42`、`c=0.65`，格子约 84×47 像素，顶底边水平。放大至 125% 后约 105×59 像素。滚轮／按钮可按 25% 调整，建议范围 50%～200%。按住中键拖动地图，“回到角色”恢复镜头中心。场景中的 HUD 吃掉自己的点击，地图输入限定在可交互视区。

受控角色实际位置决定视野中心，镜头与详情选择独立保存。缩放、拖动、切换查看地点只影响显示。首周角色仍在原格，地图据此保持原中心。核心完成到达后，镜头跟随新坐标，换入新位置的局部地块；旧选择已离开范围时改选角色所在格。

### 6. 探索宿主与真实角色

在 `scripts/client/GameBootstrap.cs` 为探索设显式宿主模式。保留现有 CoreSmokeTest 的最高优先级，随后沿用显式参数、请求场景、默认场景的判定顺序，探索与模板编辑器、战斗观察、普通 World 等互斥。场景名也可识别此模式，便于 F6 直接运行。冲突参数报错。探索宿主关闭 Bootstrap 的物理帧 Tick，并把初始化与释放交给探索场景的一份会话。当前 F5 入口为模板编辑器。仓库根目录的启动命令为：

```powershell
godot --path . res://scenes/exploration/exploration_view.tscn -- --exploration
```

1. 客户端使用宿主已有的数据目录解析规则。首版种子 12345。独立会话调用 `WorldMgr.Initialize(seed, dataRoot)`，成功后记录世界归属，再调用 `WorldMgr.Start()`。初始化发现其他宿主已持有世界时显示诊断。启动未完成时也只释放本会话成功创建的世界。
2. 在 `PlaneMgr.Instance.MainPlane` 上调用一次 `plane.NpcSystem.Spawn(new BirthContext())`。这个入口完成实体出生、注册和合法落地。首版生成一人，会话绑定返回的 `npc.Id`。显示身份与全部后续命令都使用该 ID。地图资源、模板编辑器的模板 ID 和视觉资源 key 各自只用于各自用途。
3. 首次读取位置、动作、局部地块与日期。检索失败或角色已解除位面归属时，显示错误并停用该角色的操作。鼠标、物理帧、渲染帧以及停留窗口均只处理显示。退出时解除本会话回调并调用 `WorldMgr.End()`。
4. 游戏会话与核心通过现有项目引用在同一进程内调用。控制台演示已经使用真实出生及全世界过周，供核对 API 使用方式。[控制台示例](../../../Console/NpcMovementConsole.cs)

### 7. 刷新当前角色与地图

| 信息 | 核心读取与 UI 用法 |
| --- | --- |
| 角色与位置 | `NpcMgr.Instance.GetById(id)` 取得角色，`PositionSystem.GetPosition(id)` 取得已落地位置副本和位面 ID。核心位置决定脚点。 |
| 可见地块 | `PositionSystem.GetVisibleTiles(id)` 已按实际位置、最终半径和位面边界筛选，返回独立副本。用其坐标、`TypeId`、`RegionId`、`LandMarkId`、水域及来源查询实际定义，形成视图。即使地块不可步行，选中它也能查看。 |
| 显示半径与速度 | `GetDisplayRadius(npc)` 已取整，`GetActionSpeed(npc)` 返回经修正的速度。默认 5 圈在内陆为 91 格，6 圈为 127 格，边缘按返回集合显示。未知或无效值显示诊断。 |
| 通行与候选 | 地形步行信息取 `plane.TileSystem.CanWalk(tile.Id)`，地形允许方式可取 `GetMovementModes(tile)`。当前角色合法候选取 `GetMoveCandidates(id)`，将返回集合与可见地块相交，去掉自身格后以金边提示可确认的邻格。自身格由人物标记区分。忙碌和途中候选可能为空，继续原行程依据动作快照。 |
| 动作与目标 | `BehaviorSystem.GetAction(id)` 给出 `State / CurrentTile / From / Target / Progress / TotalDistance`。途中锁定目标另作标记，地点选择可移到其他可见格。 |
| 日期与结果 | `WorldTime.CurrentDate` 始终提供当前日期。周结算后读取 `WorldWeekResult` 及其中与该 ID 相同的 `NpcWeekResult`，再刷新动作、位置和候选。 |

用受控角色当前位置、实际位面和显示半径作为局部地图刷新依据，等待新周结果或位置变化才重新查询，鼠标移过、缩放或平移沿用已取数据。对当前可出发邻格可显示预计整周数 `ceil(MoveBehavior.AdjacentDistance / speed)`。途中预计剩余整周按锁定目标的剩余路程及当前正速度计算。速度为零或数据无效时不计算耗时。到达以核心返回结果为准。现行统一邻格距离为 100，地形 `MovementCost` 不参与该计算。地形变体按世界种子、位面和坐标稳定选择，重叠可见格保持原绘景。

### 8. 左中地点栏的手动行走

每次确认最多结算全世界一周。地图选格只切换详情，动作命令来自地点栏。

| 核心状态、玩家输入 | 会话处理 | 屏幕反馈 |
| --- | --- | --- |
| `idle`，选本格、不可通行格或非相邻格 | 展示地点详情，提供查看和镜头操作。当前格虽可能出现在候选中，`TryStartMove` 只接受实际邻格。 | 本格可标注“当前位置”，其他格按实际信息提示距离与通行。 |
| `idle`，在地点栏确认合法邻格 | 临提交重新读取动作和候选，要求选中目标与角色相邻且不同于当前位置。仅在 `TryStartMove(id, selectedTile)` 成功后，立即调用一次 `WorldMgr.AdvanceWeek()`。 | 展示本周后的核心日期、实际位置和动作。若目标已失效或提交失败，刷新原因，日期不因这次拒绝而变化。 |
| `move`，继续一周 | 在提交前重新读取 `GetAction(id)`，确认仍在移动且锁定目标与操作指向相同，直接结算一次 `WorldMgr.AdvanceWeek()`。 | 按 `Target` 指明即将继续的目的地，注明该次操作会经过一周。玩家即便点选另一格查看详情，续行仍指向既有目标。 |
| 到达或受阻 | 根据该 NPC 的 `NpcWeekResult.Kind / Reason` 和最新位置、动作刷新。 | `arrived` 后显示实际新位置，`blocked` 等情况保留核心当时的位置并说明本周结果。成功经过一周与人物成功抵达分别判断。 |
| `busy`、未落地、角色已失效或会话故障 | 阻止新的行走指令并显示可定位原因。 | 允许查看仍可用的地图和诊断。 |

每次过周都是全世界结算。其他已落地成员由后端按同一周处理。核心存在空闲 NPC 随机选择停留或邻格移动的行为，`TryStartMove(id, currentTile)` 又会拒绝当前格。因此本格只提供查看，空闲时没有独立的“等待一周”。若将来需要玩家保证原地停留，需单独讨论后端显式待机入口。

**输入一致性。** 两个操作共用会话级提交标记，从读取最新动作开始，到结果处理和 HUD 替换结束后释放。地点栏一次有效激活只消费一次；忽略按键自动重复和鼠标双击的第二击，防止“前往”刷新成“继续”时同一手势跨过第二周。处理中的点击、回调和失效旧按钮都不能发出另一笔命令。连续走两周需要两次独立的明确确认。

### 9. 日期、动作与失败处理

顶部显示一次 `WorldTime.CurrentDate`。普通周以其年份、月份、天干地支和实际 `MoonPhase` 绘制一份日期与当期月相。使用 `GetDisplayName()` 或核心日期格式化，图形与文字指向同一值。新年和除夕的 `Month`、`MoonPhase` 等特殊周字段为空，直接显示年份和节日名。

| 已过周数 | 核心日期示例 | 默认速度 50 下两周行程的角色位置 |
| --- | --- | --- |
| 0 | 4000（庚）年 新年 | 出生格，空闲 |
| 1 | 4000（庚）年 1（寅）月 新月 | 确认前往一次后仍在出发格，`move`，进度 50/100 |
| 2 | 4000（庚）年 1（寅）月 上弦 | 明确继续一次后到达真实邻格，`idle` |
| 49 | 4000（庚）年 除夕 | 年末日期示例 |
| 50 | 4001（辛）年 新年 | 次年日期示例 |

速度来自当前 NPC，若首周即可到达，直接显示到达，无必经“途中”表现。`WorldMgr.AdvanceWeek()` 返回后再读取 NPC 的终态。若监听通知，整周刷新使用 `WorldMgr.WeekCompleted` 成功通知，失败仍检查命令返回值。单纯日期变化时 NPC 可能尚未完成结算。

- `TryStartMove` 拒绝时不调过周。若已接受移动，而 `AdvanceWeek()` 在日期提交前抛错，世界日期仍可能是原周，此时角色已有真实 `move` 且进度可为 0。重新查询日期、目标和动作，保留已开始的行程并显示错误。排除故障后玩家从地点栏明确续行，使用现有目标。
- 若返回 `Complete=false`，日期已提交，可能只有部分 NPC 结算成功。显示 `After`、实际可获取的位置和 `Error`，停止本会话继续行走，允许关闭后重新打开。该周不能自动重试或回滚到旧画面。
- `Complete=true` 表示世界遍历完成；个别角色仍可能 `blocked / busy / skipped / invalid_state`。从本 NPC 的 `Kind / Reason` 给出行走反馈，并按得到的动作决定后续可操作性。客户端不补跑失败周、不直接改 `NpcPositionData` 或行为进度。

## Risks / Trade-offs

- 同一地点栏同时承担地块查看与续行。途中须把正在查看的地点与按钮所指的锁定目的地写清，尤其在玩家改选后。
- 小尺寸压缩格容易在角落误选，凸出的树石可能挡住人物。格面命中复用地面多边形，叠件和立绘只参与绘制。
- 真实出生可能靠近地图边界。可见数量按返回集合核对，邻格资格每次提交前复核。
- 单次世界周可能已经提交或只完成部分成员。根据 `WorldWeekResult.Complete` 和该 NPC 的实际结果分别处置；保留错误来源，避免重复结算。

## Migration Plan

先生成独立素材并校验映射，再接入真实探索会话、地图和地点栏。完成有限的集成检查后交给用户直接验收。默认编辑器和独立战斗观察继续使用各自入口，现有存档没有迁移步骤。若回退客户端功能，只撤回本次新增的客户端文件、资源引用、宿主分支和对应说明。
