# Design

## Context

Godot 项目在仓库根，核心和 OpenSpec 在 `UnityWorld/`。目前 F5 进入角色模板编辑器。`GameBootstrap` 在启动时判定一次宿主，未识别的场景会启动后台世界。地图、模板和战斗三个正式 `.tscn` 只保存根节点，运行时由 C# 创建面板、按钮和文字。旧战斗素材预览保存了完整节点树，正式战斗会读取其中的部分美术资源。

模板试战已经能把未保存草稿冻结为 `BattleCase`，在新游戏进程打开观察器。`BattleObserverSession` 独占本进程的 `WorldMgr`，在开场及每个成功的逻辑步提交值快照。核心 `Rng.NewId()` 使用进程级的已用 ID 集合。在一个进程里重新初始化世界时，重复的 ID 会引起重抽。这决定了同一输入重开时如何隔离模拟。需求动机见 [proposal.md](proposal.md)。

## Goals / Non-Goals

让制作人员用 Godot 编辑器调整真实布局，让调用代码用一份战斗输入选择显示窗口。首页、工具页面、详情浮层和模拟各自管理自己创建的资源。已有模板格式、玩法数据、地图行动和战斗规则继续作为数据来源。本次止于界面组织和测试入口。地图遇敌、存档恢复、战果回写和新增玩法交互留在范围外。

## Decisions

### 首页负责导航，场景负责自己的会话

默认启动进入轻量首页，只显示「地图测试」「角色模板编辑器」。两个按钮都在当前 Godot 窗口打开工具，工具提供明确的「返回首页」。首页使用无世界宿主。旧战斗素材预览保留现有路径与启动行为，不参与导航改造。地图进入时才创建探索会话，模板页按需加载目录。首页不预热地图或观察器。

启动入口先处理显式的核心烟测和内部模拟进程，再解析 `--` 后的用户模式及输入，随后检查 Godot 实际请求的场景路径，最后才用项目默认场景。保留原烟测优先级、显式模式冲突诊断、`--world` 和原核心物理 Tick。直接指定地图、模板（含原别名）、观察器或观察案例时，切到对应场景后再初始化一次。保留文件和旧 Base64 形式的案例输入、验证、截图参数。F6 运行正式场景走该场景的宿主，直接运行旧预览仍进入预览。首页内切换复用相同路由，将目标宿主交给新页面。不能继续依赖 autoload 启动时记录的模式，否则目标页的 `_Ready` 会提前返回。

地图返回时停止自动续周计时，清除待提交动作，释放探索会话，由其调用一次 `WorldMgr.End()`，继续使用应用级 UI 倍率。下次打开按现有规则开始一次新测试。模板返回和关闭窗口复用现有的草稿离开确认。选择「取消」或保存失败就留在现场。成功保存或明确放弃才离开。模板页退出时恢复原 `SceneTree.AutoAcceptQuit`。试战是另一条操作路径，它保留当前页、未保存标记、选中项和原草稿。快速重复点击期间只允许一个页面切换在途。

### 分辨率与界面倍率

可见主窗口默认使用 1920×1080。窗口禁用随分辨率自动拉伸，根窗口的内容倍率由玩家设置。首页滑块、Ctrl 加号／减号和 Ctrl+0 共用同一设置，保存到用户目录。独立试战启动时读取，原窗口重新取得焦点时同步。普通 Godot 对话框使用自身的内容尺寸，嵌入窗口继承根视口变换。

首页、地图和两套工具用控件锚点布局。固定按钮、字号、卡格及边距只受手动倍率影响，列表、背景和可滚动工作区使用剩余空间。常规宽度下分别保持左、右、顶、底和中心锚点；放不下时优先使用局部滚动或换行，极小工作区可整页滚动。比如 100% 时 240 像素控件在 1920 和 1280 宽的窗口中都是 240 像素，手动调为 125% 后才变成 300 像素。

### 三个正式界面在 2D 编辑器里就能改

把固定控件和挂载位置直接保存进已有场景或可打开的子场景。页面 C# 获取命名节点、连接信号、绑定真实数据，动态列表在各自容器里增删子项。早先考虑过保留 C# 搭建器、另做编辑器预览图。那会留下两套位置和点击范围，拖动预览无法验证实际效果。

| 场景 | 编辑器中直接调整 | 运行时更新 |
| --- | --- | --- |
| 地图测试 | 铺满视口的地图区域、人物与日期栏、地点面板、行程按钮、右下缩放组和返回键 | 地块与角色、镜头、缩放、可走邻格和周进度 |
| 角色模板编辑器 | 模板列表、背包底板、卡库及筛选、人物详情、底部操作栏。背包和人物详情各有可实例化子组件的具名挂载位 | 目录内容、卡牌占格、拖放预览、选中项、校验和草稿 |
| 战斗模拟 | 双方背包、人物及状态栏、待发槽、战报、播放操作、反馈与动画锚点 | 双方真实布局、实例及 Buff、快照、播放控制、扫描与表现事件 |

各局部组件使用自己的坐标系。排序、伸缩的区域交给 Container，需要自由摆放的区域使用带锚点的 Control。移动面板时，按钮命中区随实际节点走。背包按组件当前尺寸和快照格子计算绘制与点击。灵元起止格、待发牌、头顶文字和伤害数字取对应节点的实际变换，再换算到表现层。地图保留真实六边形投影及输入规则，HUD 的可点击区域接收输入，透明装饰放行。动态绘制、列表生成可留在 C#，固定边框和按钮只维护一份。旧 `battle_assets_preview.tscn` 继续作为素材来源和可直接运行的静态预览，正式页面不执行它的示例脚本。

受宽度约束的字段用等字数的中文样文在编辑器中占位。比如七字姓名栏直接显示「这里显示七个字」，共七个汉字，用实际字体检查字号和留白。每个字段按自己的容量设置。数值和多行介绍用相应数据形状预览。图片位置放现有素材或中性占位框。运行时加载真实图片，缺图时保留名称与既有缺图反馈。页面第一次绑定即用真实值覆盖样文。名称为空时优先显示已有定义 ID，两个来源都缺失时显示清楚的缺失标记。实际名称超长时，紧凑栏按控件宽度省略，详情可换行显示全名，源名称保留完整。初始化失败或条目为空时展示诊断或空态，避免示例文字出现在运行画面里。

### 详情按种类复用，悬浮层归当前窗口

把卡牌和 Buff 的布局分别存成 `CardTip.tscn`、`BuffTip.tscn`，都能独立打开调字号、间距、图片和折行。每个可见窗口有自己的悬浮层，同一时刻展示当前命中的一个详情。通过本窗口视口坐标放置，遇边换侧并收进可见区。浮层的只读内容允许鼠标穿过，离开、开始拖拽、切页、来源消失或关闭窗口时撤下。新的悬浮对象顶替旧对象。技术上也可用每个控件自己的 Godot 原生 tooltip。统一浮层更容易处理自绘背包中同一控件内换格、边缘避让和换页清理，普通操作说明仍可用原生 tooltip。

模板卡库和背包将当前定义或草稿条目绑定给卡牌详情。战斗背包通过实际命中格找到卡实例，补充该实例真实的点亮、冻结或使用信息。两份相同定义的卡各取自己的实例。保留空格说明、拖拽有效性与放置错误反馈。战斗人物身上的每一条实际 Buff 分别有可命中的条目，用当次快照的实例标识、定义 ID、名称、层数和已有时间信息绑定 Buff 详情。没有 Buff 时没有条目。移除后同步关闭旧提示。缺失的描述、图片或时长按可用字段降级，界面不推算法术效果或虚构叠层。

### 同一场战斗可选择显示在哪个窗口

公开调用只需要 `OpenBattle(BattleCase, displayMode)`，支持 `CurrentWindow`、`NewWindow`。入口复制并校验案例，统一取得数据根、当前调用页面和日志位置，再用既有的输入、装配、快照、表现播放器和观察界面。打开方式属于客户端调用参数。模板页照旧验证并冻结双方，显式传 `NewWindow`。其「战斗观察」若打开默认案例，也复用入口并新开窗口。首页仍只有两个工具入口。`CurrentWindow` 由开发验收宿主调用，保留给后续调用方。

**新窗口。** 沿用当前游戏可执行文件、显式观察场景和冻结的输入文件，支持编辑器与导出版本。独立窗口负责自己的观察会话、时钟和日志。重开携带同一完整输入，在新观察进程就绪流程中校验核心与数据版本。创建进程失败时在旧窗口留下诊断与暂停现场。关闭独立观察器不影响原模板编辑窗口和草稿。

**当前窗口。** 由导航层保留调用页面实例，暂时停它的输入与处理，在原窗口显示同一个战斗视图，战斗结束或用户离开后恢复来源和焦点。独占核心的观察会话放在同一游戏可执行文件启动的 `--headless` 子进程中。该进程在内部启动分支直接驱动原 `BattleObserverSession`，仅加载内部无画面宿主入口，不实例化业务视图，也不创建第二个世界。这样同一窗口可以安全重开，也不需要改核心静态 ID 或将调用现场写成存档。

同窗父子之间用一条本机私有命名管道。每次启动使用独立管道名和冻结输入，双方确认会话身份。父端发送播放、暂停、单步和关闭，子端是唯一战斗时钟。父端只负责绘制和推进表现动画。子端实际装配成功后确认输入版本并发送第零步。每个成功逻辑步沿用 `BattlePresentationFrame` 传递快照、事件及其序号，附本步新增战报，另传播放状态、结束或原始诊断。观察进程用独立目录保存冻结输入、核心日志、逐步表现和战报。现有验证模式继续记录逐 Tick 对照帧。管道与普通控制台输出分开。按顺序提交、仅在暂停已确认且前一单步命令已完成时接受下一次单步，一次单步只提交一个完整 Tick。父端按会话和序号接收。断线及缺帧给出诊断，失败步的部分信息只作诊断。

同窗重开先暂停旧战斗，冻结当前会话已确认的完整案例，用新的后台进程装配该输入。新进程回传真实 Tick 0 后才切换显示，释放已暂停的旧进程和回调、清空旧表现与战报，并启用新会话操作。创建或装配失败时留下旧窗口的暂停现场与诊断，父窗口和来源页始终保留。启动失败、版本不符或运行异常时，保留最后一次已确认的快照和原始原因，可返回来源页。正常离开和父端退出时关闭管道、终止本次拥有的 worker、释放订阅。worker 发现父端断开也自行退出，超时才终止本次记录的子进程。新窗口重开明确提示将重启观察窗口，同窗重开明确提示仅重开当前战斗。

## Risks / Trade-offs

- **布局迁移后点击或动画偏移** → 在编辑器移动一个实际控件并运行，检查它的新命中位置和动画落点。用默认 1920×1080、1280×720 和超宽窗口复核，再改变手动 UI 倍率。
- **同窗通道增加延迟或串入上一场的消息** → 使用会话标识、逐步提交、增量记录和命令确认，读取管道不阻塞 Godot 主线程。与独立观察器对照冻结输入、逐步状态和结果，特别检查暂停和连续重开。
- **切页破坏草稿或留下世界、窗口设置** → 草稿的保存、放弃与取消仍由模板页处理。导航只在成功离开后更换页面。逐次往返检查窗口关闭、缩放、世界所有权和计时器。

## Migration Plan

1. 保留现有场景路径和 CLI，先记录直接启动地图、模板、真实观察器、素材预览和核心烟测的基线。准备模板未保存草稿，以及一个能展示真实卡牌和 Buff 的观察输入或已有测试夹具。
2. 分页迁移固定布局，逐页删掉相应的 C# 搭建逻辑。先在 Godot 2D 编辑器打开三个正式场景和两份详情场景，改变局部布局后实际运行。用鼠标检查地图缩放与移动、模板选择及拖放、战斗控制和动画，并检查长名、空值和窗口四边的悬浮。可在临时场景副本中保存验收用的拖动改动。
3. 接通首页和路由，实测 F5、F6、显式 CLI、`--core-smoke-test`。从首页反复往返两个工具。模板分别走保存、放弃、取消的返回路径，再用未保存草稿新窗试战并关闭，核对草稿状态。确认旧预览和直接观察器仍能独立启动。
4. 用开发验收宿主在同一窗口调用真实战斗入口。对同一冻结案例分别自动播放、单步、连续重开和中途返回。核对第零步、逐 Tick 状态与记录、最终结果，检查父窗口保留且关闭后无残留 worker。覆盖创建失败、子进程断开和指纹不符，核对诊断与返回。可见窗口数量和编辑器拖动、点击效果需实际运行确认。
5. 需要回退时按提交边界撤回首页路由、同窗观察或单页布局，恢复原先的默认模板场景和独立观察器启动方式。沿用原草稿目录、格式和显式离开确认。回退前先关闭测试会话，通过编辑器处理待保存草稿，不清空用户文件。
