# Spec Delta

## ADDED Requirements

### Requirement: 调用方指定战斗显示方式

任意客户端调用方 SHALL 能向同一入口提交一份完整战斗输入和「当前窗口」或「新窗口」参数。两种方式 SHALL 使用同一战斗界面、真实模拟和输入校验，按同一份已冻结案例开场并暂停在 Tick 0。窗口参数属于展示选项，不参与案例身份、种子或结果计算。

#### Scenario: 同输入走两种方式

- **WHEN** 测试调用方分别用两种模式提交相同的非默认冻结案例并单步推进
- **THEN** 当前窗口模式不产生第二个可见游戏窗口；新窗口模式出现独立游戏窗口。两边的参与者、种子、初始快照、逐 Tick 的结果和记录可按现有基线比较。

#### Scenario: 角色模板编辑器发起试战

- **WHEN** 用户带着尚未保存的修改通过模板预检并点「试战」
- **THEN** 编辑器固定以新窗口运行冻结后的真实案例。关闭试战后原窗口、草稿、未保存标记和选中项仍在；启动失败也不会隐式保存草稿。

#### Scenario: 从同窗口战斗返回

- **WHEN** 调用方以当前窗口打开战斗，随后用户退出战斗
- **THEN** 在同一窗口恢复原调用页面和已有状态；战斗期间来源页不接收该次战斗的输入，也不会在后台推进自己的模拟。退出、取消或初始化失败后都能返回调用方，只清理该次战斗资源。

## MODIFIED Requirements

### Requirement: 同输入重开隔离静态状态

重开 SHALL 用当前案例 ID、双种子、有序参与者、步数配置、数据与核心版本及适用操作序列启动全新的观察模拟进程。独立战斗窗口明示并重启该窗口；当前窗口只重建隔离的模拟会话，保留可见窗口和原调用页。旧会话 SHALL 停止推进、释放观察资源后退出，不重置为另一默认案例、不反射清核心静态字段或改变种子规避问题。

#### Scenario: 多次重开
- **WHEN** 用户连续执行重开当前案例
- **THEN** 每次从新进程按同一案例完整输入重建相同初始状态，逐步状态和结果一致，没有旧战报或旧动画混入

#### Scenario: 重开时源数据已经变化
- **WHEN** 新会话实际加载数据与当前案例记录的数据指纹不一致
- **THEN** 提示数据版本变化并暂停，不静默宣称已重放相同输入

#### Scenario: 新进程创建请求失败
- **WHEN** 无法创建新的观察器进程
- **THEN** 旧观察器显示错误并保持停止或暂停，不继续旧战斗冒充已重开

#### Scenario: 新进程初始化失败
- **WHEN** 新进程已创建但加载数据或初始化会话失败
- **THEN** 新会话显示或记录自己的初始化诊断，不把进程创建成功当成战斗已就绪

#### Scenario: 同窗口重开期间旧会话仍有消息

- **WHEN** 原窗口内重开当前案例，旧会话的记录或动画晚于新会话到达
- **THEN** 可见窗口保持原位，使用原冻结案例重建 Tick 0。显示、日志和输入只归属其对应会话，返回仍能回到最初调用方。

#### Scenario: 同窗口模拟意外中止

- **WHEN** 后台模拟在加载过程或单步时意外退出
- **THEN** 界面停止推进，保留已确认的最后状态并显示诊断，可以返回；未确认的步骤不会记为成功，退出后不残留该次模拟进程。
