# Spec Delta

## Purpose

让维护者直接在 Godot 2D 编辑器中查看并调整正式 UI 的层级、位置和设计容量。在没有运行模拟或加载业务数据时也能辨认页面结构，保存后的布局在真实操作中生效。

## ADDED Requirements

### Requirement: 三个正式场景的固定布局可以直接编辑

地图测试、角色模板编辑器和战斗观察器 SHALL 在各自的现有主场景中保存可视、可选中、可编辑的固定布局节点或可打开的子场景。无需运行游戏即可检查锚点、尺寸、内边距、框架和按钮。运行时数据填充与绘制 SHALL 使用这些节点给出的实际区域。

#### Scenario: 打开三个场景进行检查

- **WHEN** 在 2D 编辑器中逐个打开现有地图、角色模板和战斗观察器的场景文件
- **THEN** 地图页可辨认地图范围、人物栏、日期、地点与行程控件；模板页可辨认模板列表、背包、卡库、详情及试战操作；战斗页可辨认双方角色、背包、待发槽、播放控制及战报。三页均可选中相应固定区域或进入子场景编辑。

#### Scenario: 改布局后实际生效

- **WHEN** 将一个背包区域向右移动 40 像素后保存并运行，在默认窗口和设计基准尺寸下检查
- **THEN** 背包、格子、跨格卡面、点击和悬浮命中按新区域对齐。模板拖放命中新位置；战斗扫描、飞行及受击等引用被移动区域的效果使用实际节点坐标，旧位置不残留热区。

### Requirement: 编辑预览使用能检查容量的占位内容

编辑态动态文本 SHALL 使用正式字体、字号、边距，填入与设计容量相符的可读中文样文。图片区使用已有固定美术或中性占位框、剪影。静态操作文案可直接显示。运行态名称、描述、数值和实例美术 SHALL 由 C# 根据目录、草稿或快照赋值，数据缺失按对应界面既有规则降级。预览容量不改变业务数据允许的字符数。

#### Scenario: 七字标题框

- **WHEN** 设计容量为单行七个汉字的动态标题尚未绑定数据，维护者打开对应场景
- **THEN** 标题显示「这里显示七个字」，可以直接检查最后一个字的裁切、对齐与留白。不会把节点名、ID 或虚构角色名当作编辑样文。

#### Scenario: 名称和图片独立绑定

- **WHEN** 运行时绑定了一张有真实名称但没有配图的卡
- **THEN** 对应界面保留真实名称、布局与已有缺图反馈，设计样文不会显示给玩家。未来装入更长的真实名称时按该控件的换行或省略规则显示，数据原文完整保留。

### Requirement: 详情模块具有可识别的挂载位置

正式页面 SHALL 为实际使用的背包和人物详情保留可在场景树中定位的容器，并为临时详情预留上层挂载位置。挂载位置允许以后实例化独立 UI，未打开的模块不得占用点击或遮挡已有内容。

#### Scenario: 查看挂载位置并正常操作页面

- **WHEN** 在编辑器检查模板页的背包与人物详情区，再运行并在没有临时详情时拖动卡牌
- **THEN** 维护者能在场景树中定位相应区域，玩家仍能按实际格子摆放卡牌。地图页既有留白不因此出现空窗口或被拦截的地图点击。

### Requirement: 游戏窗口尺寸与手动界面倍率独立

可见游戏窗口 SHALL 默认以 1920×1080 打开。调整窗口大小只改变可用空间，固定控件的屏幕像素尺寸与同侧边距 SHALL 由显式 UI 倍率决定。边缘面板跟随各自锚点，内容区空间不足时允许换行或滚动。首页可调整倍率，其他正式页面也可通过快捷键调整。独立试战和重开使用同一套设置。

#### Scenario: 在宽窗和窄窗检查同一组件

- **WHEN** 100% 倍率下把窗口从 1920×1080 改成 1280×720，再改成 2560×1080
- **THEN** 原本宽 240 像素的固定控件均宽 240 像素。左上和右下控件分别保留对应边距，点击落在实际绘制位置，滚动可以到达超出可视范围的工作内容。

#### Scenario: 手动放大并从模板发起新窗试战

- **WHEN** 在当前工具选择 125% 并从已调整大小的模板编辑器进入试战
- **THEN** 原本宽 240 像素的固定控件显示为 300 像素。独立试战按 1920×1080 打开并继承该设置；回到首页仍能看到实际倍率，恢复 100% 后尺寸回到原值。
