# Proposal

## Why

Godot 目前按 F5 直接进角色模板编辑器。地图、模板和战斗三个正式场景各只保存一个根节点，调一个面板的位置也要找 C# 再运行项目。测试人员需要一个只有常用工具的首页，做 UI 的人也需要直接在 2D 编辑器里检查和修改真实布局。

## What Changes

- F5 打开测试首页，只列「地图测试」和「角色模板编辑器」。点击其中任一入口在当前窗口切换，两个工具内均可返回同一窗口的首页。继续支持直接运行场景和现有命令行验证方式。
- 可见游戏窗口默认以 1920×1080 打开。窗口大小与手动 UI 倍率分别控制，固定控件沿各自锚点放置，缩小窗口后仍能操作。
- 把三个正式场景的固定布局、样式和命中区域保存为可编辑节点或子场景。C# 填入名称、图片、数值和动态条目。限长文本按字段设计容量预览，例如七字栏显示「这里显示七个字」。
- 卡牌详情和 Buff 详情分别使用可独立编辑的 `CardTip.tscn`、`BuffTip.tscn`。所在窗口提供悬浮层。背包、人物详情预留可实例化组件的挂载位置。
- 战斗模拟成为调用方可复用的客户端入口。打开方式与案例数据分开，同一输入可以在当前窗口展示，也可以新开窗口。角色模板编辑器显式选择新窗口，保留草稿。
- 区分两种模式的重开行为。独立窗口沿用现有重启方式，当前窗口重开仅更换战斗模拟会话。旧战斗素材预览排除在首页与场景改造范围之外。

## Capabilities

### New Capabilities

- `client-test-home` — 客户端默认测试首页、两个工具入口和直接启动兼容。
- `client-ui-layouts` — Godot 编辑器中可见、可调的正式布局、设计容量占位和模块挂载。
- `client-detail-tips` — 两种独立详情场景、真实数据绑定、同一窗口内的悬浮和避边。

### Modified Capabilities

- `battle-observer-session` — 增加参数化战斗入口，区分可见窗口和模拟进程的生命周期，保持重开可复现。
- `battle-observer-ui` — 重开文案和动作对应实际打开方式，当前窗口保留调用现场。

## Impact

涉及仓库根的 `project.godot`、`scenes/`、`scripts/client/`、客户端启动文档和现有观察器验证工具。继续使用既有 `BattleCase`、值快照、观察会话和模板预检；模板试战沿用 `template-trial-session` 的新进程与冻结输入约定。玩法规则、JSON/Lua 内容及地图遇敌功能均在本提案范围之外。
