# Proposal

## Why

创世独立地标当前先按全图密度抽格，再按地标权重选类型，策划很难直接表达总量、逐格命中率和强制保底。地区已摆好的主地标与附加地标、水文和地形应成为首批补位的输入。

## What Changes

- **BREAKING** 统一重构地标定义、项目 JSON、读取与校验、地图生成、地标编辑器和开发工具。删除地标的 `SchemaVersion`、`SpawnWeight` 及由新条件替代的三个放置字段。地块和地区使用各自现有的定义字段。
- 创建通用 C# 类型 `InitialPlacement`，把固定坐标、四个数量与概率字段、最小间距和四类选址条件集中到这个对象。
- 先确定可以放多少，超过上限才抽总目标，再补 `NeedCount`。四个字段可单配、可组合，地区与绝对坐标已经落下的实例计入总数。
- 地形、地标和标签条件在 JSON 内写。`ExtraCondition` 保存文本，留待后续接入 Lua。
- 地区的 `AllowInitialLandMarks` 默认开启。关掉后普通生成和保底只跳过该地区的空格。
- `DrawType` 与 `IsHide` 放在定义顶层。绘制方式控制外观，隐藏字段控制玩家和 NPC 能获得的观察信息。
- 地标编辑器可在原 ID 下保存已有定义，更新对应源文件中的记录。新建和复制使用独立的导出流程。

## Capabilities

### New Capabilities

- `landmark-editor` 正式记录当前地标编辑器与本次重构后的资料格式、交互和导出要求。

### Modified Capabilities

- `landmark-system` 规定创世配置与选址、字段删改、绝对坐标计数和隐藏地标的观察边界。
- `world-generation` 规定首批地标的阶段、数量算法、保底、间距和诊断。
- `exploration-map-view` 规定可见地标的绘制方式与同格信息过滤。
- `region-system` 确立地区已编排地标参与创世数量与条件查询，以及地区空格的开关。
- `region-template-editor` 编辑地区创世地标开关，复用可见地标的显示方式。

## Impact

影响地标定义与配置集、地图目录、创世补位、地图预览和诊断、地标编辑器、探索视图与 NPC 地标观察。世界发布、地区成组地标与元气快照按现有阶段工作。本次需求范围止于首批生成及相关观察与配置。
