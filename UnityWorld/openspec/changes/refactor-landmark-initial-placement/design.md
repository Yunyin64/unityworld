# Design

## Context

创世合成结果已在每格存储地形、水文、地区及主地标与附加地标。目前独立散布使用地图级密度和定义级权重。新的机会数和目标数以地图合成结果为输入。产品规则和对照例见 [创世地标生成需求](../../../Docs/世界/创世地标生成需求.md)。

## Goals / Non-Goals

首批地标补位要用统一的确定性流程处理数量、概率、前置、间距和保底。定义和编辑器表达相同的数据。后续游戏事件产生地标时由各自业务使用已有放置入口。

## Decisions

1. **配置边界。** `LandMarkDefine.InitialPlacement` 是可选的 `InitialPlacement` 通用 C# 类型。固定位置与创世字段集中在其中。四个数值使用可缺省表示，读取时区分没填和显式的 0。表现、隐藏、唯一性与元气仍在地标定义顶层。一次性改写仓库地标定义和相关编辑、生成、校验、工具及测试。前序 `add-landmark-editor-and-2d-art` 记录上一版本编辑器，当前正式地标编辑要求由本变更同步。
2. **计数来源。** 在水系修整后从候选地图全部已规划地标索引建立计数和占位。包含地区主地标、附加项与绝对坐标。独立生成和保底扫描基础填充及开启 `AllowInitialLandMarks` 的地区空格。地区开关默认开启，固定地区同样适用。作者地标保持原布局，作为总数、间距和邻近查询输入。
3. **数量算法。** 对每个参与定义稳定筛选并抽签，按地形可放和既有间距得到可放集合。可有总数未超上限时采用实际数。超上限才抽总数并选取子集，区间下限考虑已放实例。单填 `NeedCount` 时直接从作者已放数量补足。合用普通散布字段时，先得出正常总量再补保底。补位先保留普通选址条件再放宽。世界种子驱动候选洗牌、机会抽签和可重现冲突处理。
4. **条件与预留字段。** 用确定的字符串语法检查稳定 ID、正式标签、排除、近邻和显式顺序。固有作者位置先进入上下文。同批地标依赖先排序，循环提前报错。`ExtraCondition` 原样读写。只读创世上下文及 Lua 执行留待后续工作。地图预览与正式创建采用同一个入口。抽签与落位由 C# 生成阶段完成。
5. **诊断与发布。** 输出作者、条件、概率、间距、正常目标和保底原因。软下限的差额是成功结果信息。作者超上限或保底无法完成的候选失败使用现有有限重试和事务边界。只在全部位置确定并通过审计后创建实体和快照。
6. **感知与显示。** 过滤玩家和 NPC 的地标观察入口。在上下文组装时按过滤结果选主显示和同格计数。作者编辑器仍可读取全部配置。2D 通过 `DrawType` 选择画法和素材入口，缺图只在图标模式执行字标回退。
7. **已有定义的保存。** 地图目录记录每个地标的源文件。编辑器打开记录时保留源内容，校验通过后更新该文件中的同 ID 记录。保存只校验字段和引用。各张地图的落点容量由创世确认。发现源文件变化时保留草稿。导入新图片时先发布独立资源，再提交定义。
8. **保底与普通定义的竞争。** 有保底缺口的地标定义优先落位，前置依赖先完成。同级用种子顺序。作者布局、地区开关、占位、唯一性、间距和数量上限继续约束保底。缺口诊断记录本轮阻止继续落位的约束。

## Risks / Trade-offs

- 概率通过数随种子变动，最终落点还受间距和竞争约束。诊断分别保留各阶段计数。
- 强行补位可越过普通选址条件，仍尊重地区开关。只有允许放宽地点条件的内容才应配置 `NeedCount`。
- 过窄的空间或唯一性可让保底不可满足，统一由候选失败和有限重选处理。
- 当前地图配方里的随机地标需要逐项明确新的数量或概率，地标旧权重无法直接换算成一条稳定的逐格概率。
