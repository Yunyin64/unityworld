## 2D 图片资源约定

- 可替换的 2D 图片放在各内容包的 `src`，当前 Godot 入口支持 PNG。配置填写 `cards/card_jin_slash.png` 这类逻辑地址，`src/` 可省略。安装包将外部 `src` 放在可执行文件旁，保持目录结构。
- Core 的 `AssetMgr` 按随包资源、安装根 `src`、已启用 Mod 的 `src` 预载。同路径以后挂载的可用资源生效。引擎适配层提供读取方式。新增 2D 资源入口要沿用这条链。
- 卡图用展示映射按牌 ID 找图片，NPC 外观由 Game 按槽位装配。两条入口都从客户端的共享纹理缓存取图。外部骨架部件在 `Data/Appearance` 声明插槽、兼容骨架、图片地址和位置。一个组件对应一个槽，前发与后发独立配置。
- 2D 骨架上要换装或转动的部件，按插槽独立绘制完整形状，也要画出静止时被盖住的接头。出图后先看独立部件，再看近、远侧层级和关节转动。图集工具只处理已分开的图及透明边距。
- 前端在同一个资源版本中共享解码后的纹理。带状态的卡面、演员等实例可借用全局池，归还时解绑图片、事件和状态。初始数量为 0，空闲保留量取并发峰值，可按类型设硬上限。
- 2D 展示加载失败要能定位来源和地址。卡图用卡名回退，外观按槽走可用候选或基础皮肤。3D 资源按自己的加载和渲染方案维护。
