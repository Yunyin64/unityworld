# Task 3 — 机制组合的实现

# TCA 框架：游戏效果的原子化拆解

## 核心思想

任何一条游戏效果，无论多复杂，都可以拆成三个原子层：

```
T（Trigger）→ C（Condition）→ A（Action）
什么时候触发    取什么值/判断什么条件    执行什么动作
```

## T — Trigger（触发器）

**回答：什么时候？**

Trigger 是一个**瞬间事件**——游戏世界中某件事发生了，敲响了一个铃。它本身不做任何判断和计算。

例：`当你使用武器时`、`当触发灼烧时`、`每场战斗开始时`、`当敌人使用物品时`

## C — Condition（条件/取值器）

**回答：满足什么条件？取什么值？**

这是框架中**最关键的一层**。C 不只是"是/否"的判断门槛，它是一个**函数**：输入当前游戏状态，输出一个值，传递给 Action 使用。

三种形态，本质统一：

| 形态 | 例子 | 返回值 |
|------|------|--------|
| **布尔型** | 如果敌人有护盾 | true / false |
| **计数型** | 每有一件相邻工具 | 0, 1, 2, 3... |
| **取值型** | 等量于最大生命值的10% | 具体数值 |

**关键**：当返回值为 0 时，就等于 false，Action 不执行或等于无效。三种形态只是同一个函数的不同表达。

## A — Action（动作）

**回答：做什么？**

Action 是真正**改变游戏状态**的操作。它接收 C 传来的值作为参数。

例：`造成{C}伤害`、`获得{C}护盾`、`+1多重释放 ×{C}`、`摧毁敌人物品`

## 组装示例

**"当你使用武器时，每有一件相邻工具，此物品+1多重释放"**
```
T: 当你使用武器时
C: 相邻工具数量 → 返回 0/1/2（0=不触发）
A: +1多重释放 × C的返回值
```

**"触发灼烧时，造成灼烧，等量于护盾值的20%"**
```
T: 触发灼烧时
C: 护盾值 × 20% → 返回数值
A: 造成{C}灼烧
```

**"如果敌人有护盾，此物品造成三倍伤害"**
```
T: 被动/持续
C: 敌人是否有护盾 → true/false
A: 伤害×3
```

简单效果的 C 可以省略（等于固定值/永远true）：
```
"使用时造成50伤害" → T:使用时  C:(50)  A:造成伤害
```

## 为什么要用 TCA

| 场景 | 价值 |
|------|------|
| **设计新效果** | T×C×A 排列组合，系统性穷举，不靠灵感 |
| **避免重复** | 两条效果文字不同，TCA拆开后完全一样=重复 |
| **精确调参** | 效果太强，能定位是T太容易触发、C返回值太高、还是A效果太猛 |
| **程序实现** | 只需三套系统（事件监听/条件计算/动作执行），所有效果都是配置组合 

> TCA 就是把任何效果拆成"什么时候（T）→ 取什么值（C）→ 做什么（A）"，其中 C 是一个返回值的函数，返回 0 就等于不执行——它是连接触发和动作的计算桥梁。

## 目标

根据 Task 2 输出的 `意象/物品→机制Tag` 对应列表，将多个机制进行**组合设计**，产出有趣的复合玩法效果词条。TCA 框架仅在内部思考时用于验证效果合理性，不在最终输出中展示。

重点：
- 让 2–3 个机制互相耦合产生涌现玩法
- 效果描述像玩家读到的物品词条一样直观
- 分"抽象组合"和"物品组合"两个区块

## 约束

- **严格使用 Task 1/2 的产出**：
  - 抽象组合的来源意象必须是 Task 1 列出的意象
  - 物品组合的物品名必须是 Task 1 列出的具象物品原名，不得创造新物品名、不得衍生/合成新名称
  - 机制 Tag 必须是 Task 2 中已映射出的机制（即 Task 2 输出中出现过的）

## 步骤

1. **选取组合种子**：从 Task 2 的映射结果中，挑选 2–3 个意象或物品形成一组，优先选择：
   - 同一意象映射到的不同机制（天然有主题关联）
   - 不同意象但机制之间有"前后手"关系（如一个产生资源、另一个消耗资源）
   - 物品与意象跨类搭配

2. **构思复合效果**：对每组组合，写出一句自然语言的物品词条效果描述，要求：
   - 读起来像一条完整的游戏内文字说明
   - 内含明确的触发条件和逻辑
   - 数值多用X来表示

3. **内部验证（不输出）**：用 TCA 在内部拆解每条效果，确认逻辑通顺、可实现，但不展示给用户。

## 输出格式

分为"抽象组合"和"物品组合"两个区块，格式为：

```
抽象组合：
- [来源意象(可多个用+连接)] | [对应机制Tag列表] | [效果词条]
- ...

物品组合：
- [物品名] | [对应机制Tag列表] | [效果词条]
- ...
```

### 效果复杂度覆盖

每个区块中的效果词条应**覆盖不同复杂度层次**，从简到繁自然排列：
- **基础效果**（2–3条）：组合依然是 2–3 个意象/机制，但效果词条写得简洁直白，一句话看懂，不含复杂条件联动或数值公式
- **进阶效果**（5–7条）：效果词条包含条件触发、数值联动、前后手关系等复杂表达

**判断原则**：根据意象/物品组合本身的"基础程度"来自行判断效果应该多简单或多复杂。不需要显式标注哪条是基础哪条是进阶。

注意：
- 组合种子始终是 2–3 个意象/机制的耦合，不因效果简单而减少组合数
- 每条一行，紧凑不换行
- 机制 Tag 用顿号分隔
- 效果词条控制在一句话内
- 每个区块总计 7–10 条

## 示例
主题：虎

（假设 Task 1 具象物品为：虎骨、虎皮、虎符、虎爪、虎眼石、捕虎笼、虎鞭）

抽象组合：
- 凶猛+撕咬 | 斩、异常 | 斩击，附加撕裂
- 敏捷+独行 | 加速、被动 | 被动：战斗开始时，相邻卡的加速X
- 独行+凶猛 | 被动、斩 | 被动：卡组中每少一张同类卡牌，相邻卡斩击+X
- 威慑+咆哮 | 异常、减速 | 使用时对敌方全场施加减速X
- 敏捷+凶猛 | 加速、直击 | 打击。被动：此卡就绪时若对手无就绪卡，立即直击
- 撕咬+威慑 | 斩、冻结 | 斩击。获胜时，敌方一张冷却中的卡牌冻结X
- 王者+独行 | 增益、被动、斩 | 若你场上仅有此一张装备，获得护盾X，并斩击X

物品组合：
- 虎皮 | 护盾、被动 | 被动：每场战斗开始获得护盾X

- 虎眼 | 被动、神识 | 被动：神识每X点，此卡上方卡加速X
