# 纳音五行卡牌设计 · 第二版

**本版删除全部流派专属资源、附着标记和独立形态。** 不需要积攒灯油、种子、藏珠等新东西。三十种纳音的差异改由现有拼点、HP/MP、护盾、五行状态、灵元分布、卡牌大小、位置和施法次序表现。每张法术以一个主效果配一个条件或附效为主。

本版验证：31个文件、30功法和150法术保持，180个卡牌ID全部沿用；描述最长34字，每卡补充规则最多3条。费用/占格/引用/来源检查、当前C#类型反序列化均通过。DataManager已读回全部30个卡牌文件，与磁盘新版一致；本次重设计之外的127个游戏数据JSON哈希未变。未编写Lua或修改游戏代码。

文件与数量保持不变：`../Practice/GongFa/NayinWuxing.json` 含30个修炼功法；30个 `Nayin*.json` 各含同 ID 的功法战斗卡与5张法术，共30功法、150法术。已有ID、修炼节点和引用关系保留。全部为 Pending 设计稿，不含Lua，不可据此宣称已实现。

## 共用规则

- 每轮指己方完整背包扫描，双方独立。施法只统计成功Use，不把点亮、拼点结算或附加效果再算一次。读取本轮/上一张法术记录及首次触发次数只是通用条件，不是新的可积攒或消费资源。
- 单槽、每行最多一次扫描Use、Size水平横条和费用合计等于Size仍有效。补灵、引灵和位置变化不直接赠送发动机会。普通攻击/防御产生待发拼点；持久护盾单独增减。
- 小卡/单格卡指Size1，大卡/多格卡指Size至少2。几何相邻指占格正交共边，多格卡按实例去重；同行/同列按实际占格。最早/靠前默认扫描顺序：上行、左列、实例ID。空格须有效、无卡、无未分配灵元；背包外不算空格。
- 五行归属按法术ManaCost中的非零元素；混合费用可属于多种。上一次法术指此前最近的成功Use，本次判条件后才更新历史。没有历史时相关条件不满足。功法卡、派生效果不计入法术历史。
- 临时“下次拼点”加值默认持续到己方下一轮结束，只作用于一次成功入槽的新拼点，同名来源不叠加；明确写当前待发的效果只改该条记录。无合适附加目标时基础效果照常执行。每轮触发上限由同名功法共享。
- 引灵只搬运背包已有且目标仍需要的匹配灵元，目标须非待发、可接收；不凭空点亮，不二次收费。改色只作用未分配格上灵元，不改变数量；Convert仍是格上灵元1:1回收MP，不是改色。Draw受MP和空格限制。
- 普通伤害与附加伤害照常经过持久护盾；“命中本体”指实际扣HP。治疗/MP回复不超过最大值。消耗护盾不等于消耗防御拼点；附加效果无合法目标时不预扣其资源。具体卡牌明确的顺序/消耗条件优先。
- 冻结跳过下一次完整扫描后解除，不取消已有待发拼点；加速/减速影响整包，时长写真实Tick，10Tick=1秒。移卡必须整条横形合法，不覆盖卡或灵元，不移动固定主功法或待发来源卡，不补扫已过格。
- 现有五行状态沿用原语义。尤其**灼烧不是持续伤害**：抽灵时清除自身正面五行Buff；中毒在抽灵时添加负面五行Buff。再生、浩瀚、心火、载德等也沿用当前数据与Lua，不为纳音另定义一套。
- 同一根事件中，每个同名被动最多响应一次；触发式附加收益不反复触发自己的来源。没有新的私有资源或专属状态说明书；特殊规则以各卡最多三条补充说明为限。

## 数据与代码边界

`Design.EffectPlan` 只记录设计，不是可执行脚本。ExistingAPI 表示底层已有同名API，不代表本卡的条件、监听与组合已实现；ExistingCore 表示已有核心能力；SharedExtension 表示需要补充的通用操作。几何选择、短时拼点加值、调整当前待发、灵元搬运/改色等可供所有流派复用，不再每系发明一套Action。没有新关键词、状态配置或Lua文件。

代码核对范围（路径相对UnityWorld）：`Scripts/Game/Data/Defines/CardDefine.cs`、`Scripts/Game/Data/Defines/Practice/CultivationDefine.cs`、`Scripts/Core/Base/DefineMgrBase.cs`、`Scripts/Game/Domain/Combat/CombatNpc/CombatNpcScan.cs`、`CombatNpcFunc.cs`、`Scripts/Game/Domain/!Global/API/Combat/Action/`；当前装配兼容检查由 `Scripts/Game/Domain/Object/Npc/Data/NpcTemplateValidation.cs` 执行。Card和Practice/GongFa仍是各自目录顶层加载，同ID绑定。
