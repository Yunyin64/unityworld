## 四、功法系统

### 4.1 核心概念

功法是修炼体系的核心。功法不是"技能书"，功法是一条用修炼点数丈量的道路，路上埋着一个个等你解锁的宝藏。

功法有两种来源：
- 手配功法：策划手写的经典传承，是世界中"已存在的道途案例"
- 生成功法：由 Tag 系统按语义规则涌现出来的新功法（未来实现）

两者共存，数据结构统一。

### 4.2 功法的结构

一本功法由以下部分组成：

**基础信息**
- ID / DisplayName / Desc
- PathType：所属道途类型（决定 NPC 的道途）
- RealmLevel：适应境界等级（标识功法设计目标境界，不是硬性可用性限制）
- MaxPoint：修炼点数上限
- Completeness：完整度（0~1，影响节点分布密度）
- Tags：与 Tag 系统关联

**节点序列（CultivationPoint）**
功法是一系列节点的组合。修炼点数到达某个节点的阈值后，解锁对应的奖励。

```
天火决（灵修·练气级功法，MaxPoint=500，完整度=高）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  0                                              500（满）
  │════════╤═══════════╤═══════════╤════════╤═════│
  │        │           │           │        │     │
  │       50          100         200      400   500
  │    Card:运火术  BehaviorCard:  Card:火球术  Mod:  Card:
  │                 收集火种               火亲和  群体点燃
  │
  └─ 核心效果（装备为核心功法时常驻）：
     "根据战斗中获得的火元气数量，每5个提高1点法术强度"
```

**节点类型（四种）**
1. Card：战斗卡牌，解锁后创建一个 Card 实例加入 NPC 的候选卡池（CardPool）
2. BehaviorCard：行为卡牌，世界行为（如"收集火种"）
3. Modifier：属性修正（如"火亲和+X"）
4. Story：叙事事件（手配为主，当前生成管线未通）

**核心效果（CoreEffect）**
装备为核心功法时激活的常驻效果。一般非常强大且复杂。仅装备为核心功法时才生效。

### 4.3 完整度

完整度影响功法节点分布的密度。这是一个非常重要的体验设计参数。

**高完整度功法**（如 0.85）：
- 节点密集，前期就有东西用
- 例如：<0, 50, 100, 200, 400, 500>
- 修炼体验：一路有收获，平滑成长

**低完整度功法**（如 0.3）：
- 节点稀疏，前期可能很长一段时间没有收获
- 例如：<0, 300, 500>
- 修炼体验：漫长空窗期，但后期可能很强

**关键规则**：NPC 可以装备高级功法。功法的 RealmLevel 只是代表"适应标准"，不代表可用性。但如果一个练气期 NPC 拿了一本低完整度的筑基功法修炼，可能整个练气期（0~500点）都在空窗期——体验极差。NPC 会优先选择完整度高的功法。

### 4.4 NPC 与功法的关系

```
┌──────────────────────────────────┐
│ 核心功法（1本，定义道途）          │
│ "天火决" [灵修] ← 道途 = 灵修     │
│  当前修炼点数: 237/500            │
│  已解锁: 运火术、收集火种、火球术   │
│  核心效果: ✅ 已激活              │
└──────────────────────────────────┘
        │
┌───────┴──────────────────────────┐
│ 副功法（多本，一般同道途类型）      │
│                                  │
│ "焚天诀" [灵修] 进度: 80/300      │
│  已解锁: Card"引燃"              │
│  核心效果: ❌ 未激活（非核心）     │
│                                  │
│ "炎灵心法" [灵修] 进度: 0/200     │
│  还没开始修炼                     │
└──────────────────────────────────┘
        │
        ▼
┌──────────────────────────────────┐
│ 候选卡池 CardPool（只增长）       │
│  = 核心功法解锁的 Card 实例       │
│  + 副功法解锁的 Card 实例         │
│  + 其他来源的 Card 实例           │
│  ※ Card 是实例，同一 DefineID     │
│    可存在多份                     │
└──────────────────────────────────┘
        │
        │ 选卡策略（当前：随机）
        │ 约束：Cost 总和 ≤ SP
        ▼
┌──────────────────────────────────┐
│ 战斗卡组 BattleDeck（按需构建）   │
│  = 从 CardPool 中选出的子集       │
│  + 战斗中临时塞入的伤势卡         │
│  ※ 伤势卡不进入 CardPool         │
└──────────────────────────────────┘
```

**核心规则：**
- NPC 选择第一本核心功法，该功法的道途类型就是 NPC 的道途类型
- NPC 可以同时拥有多本功法（核心 1 本 + 副功法 N 本），默认只能同类型
- NPC 有"当前修行功法"属性，由 AI 决策修哪本。一次只修一本，修满了自然换
- 核心功法激活 CoreEffect，副功法只提供节点奖励
- NPC 所有功法解锁的 Card 实例 + 其他来源的 Card 实例 → 构成候选卡池（CardPool）
- CardPool 只增长（获得新卡就加入），战斗时从中选取子集组成战斗卡组（BattleDeck）
- Card 是实例化对象，同一 DefineID 可存在多份（多本功法可能解锁同一张卡）
- 伤势卡在战斗中临时塞入 BattleDeck，不进入 CardPool

### 4.6 卡组构建：从 CardPool 到 BattleDeck

NPC 进入战斗前，需要从候选卡池（CardPool）中选取卡牌组成战斗卡组（BattleDeck）。

**构建流程：**
1. 读取 NPC 的 SP 上限（= 5 + ψ 意调整值）
2. 读取 NPC 当前持有的伤势卡（战后持续存在的，自动包含）
3. 计算剩余可用 SP = SP 上限 - 伤势卡 Cost 总和
4. 通过选卡策略，从 CardPool 中选取卡牌，直到 Cost 总和 ≤ 剩余可用 SP
5. 确定卡牌排列顺序
6. 输出 BattleDeck = 伤势卡 + 选出的卡牌（按排列顺序）

**选卡策略（可替换）：**

当前阶段使用**随机策略**：从 CardPool 中随机选卡，逐张加入直到 SP 用满或无法再加。

未来实现**实战水平策略**：
- NPC 生成 K 种随机卡组方案
- 每种方案与"标准模型"虚拟 NPC 对战 N 轮
- 选战斗表现最优的方案
- K 和 N 本身是 NPC 属性（SimulationDepth），代表 NPC 的推演能力/战斗智慧
- 推演次数越多，NPC 本质上战力越强——这是修为的体现

**卡牌排序：**
- 排序是构建决策的一部分，影响待发槽挤出顺序等战斗行为
- 当前阶段：随机排序
- 玩家操纵的 NPC：玩家在 UI 中手动排列
- 未来 AI：实战水平模拟时同时优化排序

**伤势卡规则：**
- 伤势卡在战斗中 HP 清零时临时塞入 BattleDeck
- 伤势卡不进入 CardPool（不是 NPC "拥有"的卡）
- 战后伤势卡持续存在，下次构建 BattleDeck 时自动包含并优先占用 SP

### 4.7 功法技术说明

- 功法定义使用 CultivationDefine（继承 DefineBase），从 CultivationDefines.json 加载
- 节点类型使用 CultivationPointType 枚举（Card / BehaviorCard / Modifier / Story）
- CultivationMgr 负责运行时管理（NPC 功法持有、修炼进度、节点解锁）
- 生成功法逻辑未来由 CultivationMgr 实现，Tag 驱动
