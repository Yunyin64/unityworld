## 设计背景

CardOverview.md 中的 Base 卡覆盖了"原子能力"和"数值基础"：
基础攻击、基础防御/盾、回血、回蓝、加速/减速、冻结、破甲、燃烧等。

本文档记录的是 Base 卡之上的第二层机制——
它们不是独立的卡，而是可以附加在卡上、或作为卡效果使用的机制模块。
每一个都是一个"原子机制"，可以和 Base 能力自由组合。

## 一、数值操控类

> 本节中的状态类效果（护甲、XX强化、易伤、虚弱）底层由 Modifier 系统承载。
> 详见 → 战斗/战斗_Modifier系统.txt（ModifierDefine 体系、四大组成部分、映射表）

### 护甲
  给 NPC 附加护甲层数。
  拥有护甲时，受到的伤害先减去护甲值。

  示例效果：+1 护甲

### XX强化
  对符合条件的卡的拼点数值进行强化。
  "XX"指元素或其他筛选条件。

  示例效果：火强化1 → 己方所有火系攻击卡的拼点数值 +1

### 易伤X
  给敌方挂上"易伤"状态。
  敌方下一次受到的伤害增加 X 点。

  示例效果：易伤2 → 敌方下次受到伤害时额外承受 2 点

### 虚弱X
  给敌方挂上"虚弱"状态。
  敌方下一次出手的拼点数值减少 X 点。

  示例效果：虚弱3 → 敌方下一张进入待发槽的卡，点数 -3

## 二、状态控制类

> 本节中的状态类效果（眩晕）底层由 Modifier 系统承载。
> 详见 → 战斗/战斗_Modifier系统.txt

### 眩晕
  直接停止敌方所有卡的 CD 推进，持续一定时间。
  眩晕期间敌方无法出卡。

  属于最强硬控，需要严格限制（高 CD / 高消耗 / 苛刻触发条件）。

---

## 三、卡组操作类

### 疗伤
  从己方卡组中移除一张伤势卡。

  直接对抗"伤势压缩 SP"的核心机制。
  疗伤卡自身的 Size 和消耗需要谨慎定价，
  太便宜会架空伤势系统的压力。

### 位移
  直接修改敌方卡组中卡牌的排布顺序。默认是放到最下方。

  在本系统中卡的位置影响 CD 触发顺序、
  加速/木灵等"对上方卡"效果的目标、以及挤出直击的对象。
  位移通过改变排列来破坏对方的节奏规划。

## 四、Keyword Effect（关键词效果）

### 设计身份

  Keyword Effect 是一种特殊的 Effect。
  它与普通 TCA Effect 共存于 CardData.Effects[] 列表中，
  共享 Score 和 Tags 字段，参与卡牌随机生成的分数预算。

  与 TCA Effect 的区别：
    TCA Effect = Trigger + Condition + Action[]，完全数据驱动
    Keyword Effect = KeywordId + KeywordParams，引擎硬编码执行

  Keyword 标记 IsKeyword=true，不使用 Trigger/Condition/Actions 字段。
  引擎按 KeywordId 分发到专用代码路径。

  Keyword 的本质：修饰卡牌在系统中的存在方式、生命周期、
  或与其他卡牌的引用关系——这些无法用"在某时机做某事"的 TCA 模式表达。

  判定标准：如果一个效果可以用 Trigger+Condition+Action 组合出来，
  它就不应该是 Keyword，而应该是普通 TCA Effect。

### 介入时机分类

  Keyword 在结算管线的外围起作用，按介入时机分为五类：

  | 类别 | 时机 | Keyword |
  |------|------|---------|
  | 初始化修饰 | 战斗开始装载卡组时 | Initial, Sluggish |
  | 预处理修饰 | CD到达、TCA结算之前 | Weapon, Overcharge |
  | 流程改写 | 改变攻防卡的槽位行为 | Rush, Fortify |
  | 后处理修饰 | 使用完成后 | Consume, Ammo |
  | 被动拦截 | 被其他效果选中时 | Anchored |

### ── 初始化修饰类 ──────────────────────────────────

### 初始 (Initial)
  战斗开始时 CD 设为 0（已满），第一个 Tick 即可触发。
  介入时机：初始化。无参数。

### 迟缓 (Sluggish)
  战斗开始时，首次 CD 翻倍。后续 CD 循环恢复正常值。
  介入时机：初始化。无参数。
  适用于：高数值但需要慢热的卡。

### ── 预处理修饰类 ──────────────────────────────────

### 武器 (Weapon)
  CD 到达后、TCA 结算之前介入。
  在卡组中向上搜索，找到第一张带武器 Tag 的法宝卡（CardType=FaBao），
  提取其属性（元素类型、物理类型），
  填入该卡 TCA Effect 的 Action Context 中的空位字段。
  找不到武器卡时，空位保持为 None/无属性。

  介入时机：预处理。无参数。

  注意：<武器> 标记在使用武器的招式卡上，表示"我需要引用一把武器"。
  武器卡本身是普通法宝卡，不需要 Keyword 标记。

  示例：
    剑斩：Effects = [Keyword("Weapon"), TCA(OnUse→Attack(None,"Zhan",3))]
    卡组上方有赤铁剑（火属性法宝）
    → 结算前补全 → Attack("Huo","Zhan",3)

### 超载 (Overcharge)
  CD 到达后、TCA 结算之前介入。
  检查灵元池中与该卡攻击元素相同的剩余灵元，
  每消耗 ManaPerPoint 个灵元，拼点数值 +1，最多额外 +MaxExtra。

  介入时机：预处理。参数：ManaPerPoint(int), MaxExtra(int)。
  适用于：能用灵元"充能"的高弹性卡。

### ── 流程改写类 ──────────────────────────────────

### 速攻 (Rush)
  CD 到达后，跳过待发槽机制，直接作为直击打向对方本体（全额伤害）。
  介入时机：流程改写。无参数。
  本质：放弃对拼的攻防博弈，换取确定性伤害输出。

### 坚守 (Fortify)
  在待发槽中时，不会被后续 CD 到达的卡挤出。
  如果新卡要入槽但槽中有坚守卡，新卡直接直击对方。
  介入时机：流程改写。无参数。
  本质：锁住待发槽，迫使对手必须出卡来对拼。

### ── 后处理修饰类 ──────────────────────────────────

### 弹药 (Ammo)
  卡牌在战斗中总共可使用 X 次。
  用完后进入休眠状态，不再参与 CD 循环，但保留在卡组中占用 Size。
  可被「装填」类 Action 恢复弹药，重新参与 CD。

  介入时机：后处理。参数：Uses(int)。
  适用于：法球、投掷物、召唤类。

### 消耗 (Consume)
  卡牌在战斗中总共可使用 X 次。
  用完后直接从卡组中移除，释放其占用的 Size。

  与弹药的关键区别：用完即消失，Size 归还。
  介入时机：后处理。参数：Uses(int)。
  适用于：丹药、符箓等一次性物品。
  隐含博弈：带消耗卡 = 前期多一张牌的强度，后期多一格 SP 的生存空间。

### ── 被动拦截类 ──────────────────────────────────

### 锁位 (Anchored)
  被位移 Action 选中时，位移无效化，卡牌位置不变。
  介入时机：被动拦截。无参数。
  本质：对抗位移策略的防御性 Keyword。

## 五、条件解锁类

### 任务
  卡牌携带一个隐藏的"达成条件"。
  在战斗中满足条件后，解锁卡牌的额外效果。

  示例条件：
    - 触发 X 次攻击
    - 赢得 X 次对拼
    - 对敌施加 X 层燃烧
    - 消耗特定灵元
    - HP 低于某阈值

  任务完成后点亮的额外效果，可以是上述任何机制原子的组合。
  适合表达"卡的觉醒"——一场战斗内从弱到强的成长弧线。

## 附：数值框架备忘

在讨论这些机制时，确认了以下数值基础共识：

  1 tick = 1 秒

  基础攻击牌（Size1 / 单元素1消耗 / 无附效）：
    PPS（每秒拼点值）≈ 1.0
    即 攻击值 ≈ CD

  基础防牌（Block）：
    PPS ≈ 1.25~1.35
    防牌不推进胜势，赢了差值浪费，所以单位值需高于攻击牌

  基础盾牌（Shield）：
    PPS ≈ 1.15~1.25
    盾赢了溢出加血，有上行收益，所以单位值略低于纯防，
    但配合更高消耗和更长 CD 来约束

  高伤牌的非线性价值：
    同类型攻击"赢家通吃"机制 → 高数值有翻转溢价
    高伤触发的伤势卡更重 → 单次爆发有额外 SP 压缩价值
    护甲机制会削弱高伤的有效值 → 三者构成天然制衡
