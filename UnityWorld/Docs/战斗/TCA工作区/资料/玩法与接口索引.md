Ready 和 Pending 是 JSON 里的策划说明。事件以战斗中的实际派发为准，动作以 Lua 和 C# 的实现为准。Pending 条目的缺口见[现有 TCA](现有TCA.md)。

A、B 可引用本页列出的玩法资料、接口方法、包装和样例。C# 格操作用于估算可复用的底层能力。Lua 表示卡脚本中已有入口。旧接口和失败用例只作核对证据，正式能力状态见节点目录。

### 指定格换位

`FindPlacement(card, replaceMana)` 找自动摆放位置，`Insert(card, replaceMana)` 按该结果插入新卡并更新布局和卡数据，伤口路径可替代灵元。`DealFieldChange` 执行入场和移除队列，会动卡的蓄灵及生命周期。战前 `PlaceBackpackCard(cardId, x, y)` 用 1 起始坐标，复制验证后提交战前布局，在战斗快照中不走这个编辑入口。 [CombatBackpack.FindPlacement、Insert、RemoveCard](../../../../Scripts/Game/Domain/Combat/CombatBackpack/CombatBackpackFunc.cs) · [CombatNpc.DealFieldChange](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcCardFunc.cs) · [NpcSystemBackpack.PlaceCard](../../../../Scripts/Game/Domain/Object/Npc/Systems/NpcSystemBackpack.cs)

**指定格换位缺少战斗布局的原子操作。** C 需要核对两张卡以目标格为锚点时的完整形状、有效格、交叠/占用，以及固定主功法、待发卡、保留蓄灵和扫描边界的规则。比如 2 格横卡移去 1 格卡的右边界锚点会出界，整次交换应由新规则决定并保证失败不留下半套布局。旧 `Displace/Deploy/Recall` 立即拒绝。纳音设计提出了禁动固定和待发卡、禁止覆盖灵元、已过格不补扫，供 C 评审时追溯。 [纳音设计共用规则](../../../../Data/Card/NayinDesign.md) · [待迁移动作](现有TCA.md#a--动作模板及入口)

四向滑移使用 `SlideCard(ctx,"Self","Right")`。卡滑到边缘、无效格或其他卡之前。经过的灵元保留，终点覆盖的灵元让位。固定主功法和待发来源卡原地不动。动作在上下文写入实际移动卡数 MovedCount，成功派发 OnCardDisplaced，可用 `WasCardDisplaced(ctx,self.m_Self)` 判断本卡被移动。 [滑移实现](../../../../Scripts/Game/Domain/Combat/CombatBackpack/CombatBackpackFunc.cs)

## 独立轮次与消耗

- `OnRoundStart` 和 `OnRoundEnd` 由各自的背包触发，Caster 是走到边界的角色，Round 从 1 开始。Buff 的轮期限包含施加当轮。[轮次结算](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcRoundFunc.cs)
- 在被动的 `OnUse` 内使用 `WasCardUsedOnSide(ctx,self.m_Self,"Right","FaShu")`。命中后可以立刻登记下一轮灵盾。比较依据是实际发动时的占格，即使该次效果已经移动了卡。 [使用事件与位置条件](../../../../Data/Condition/ConditionTemplate_Spatial.json)
- 消耗卡配置普通关键词 `Consume` 和正数 `StackMax`。新卡起始次数为上限，成功主动发动扣一次。零次事件使用 `OnExhausted`，经过 `Flexible` 最后一次结算移除时还会收到 `OnLeave` 或 `OnCardLeave`。准备使用 `Preparation`，实战结算后补满。零次卡保留在持有列表并退出战前选择。 [消耗条件](../../../../Data/Condition/ConditionTemplate_Consume.json)
