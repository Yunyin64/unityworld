## 第 01 轮复核

原始抽样 100 条，`T+A` 27、`T+C+A` 13、`C+A` 27、`A` 33。 [抽样记录](抽样记录/第01轮.txt)

| 抽到的组合 | 判断 |
| --- | --- |
| 防御侧结算且本卡被位移时，自疗 | 防御事件没有位移事件的上下文，条件恒假。主结算时检查本方对拼落败也有同类问题。 |
| 本方轮末时，生成木系射击拼点 | 轮末缺本卡新一轮发动的 `Contest` 授权，写入应当被拒绝。 |
| 左侧伤势卡发动后，降低配对 B 的盾拼点 | 卡牌发动事件缺配对双方数据，伤势卡通常又是被动。 |
| 本卡发动，给敌方由本卡产生的攻击拼点加值 | 己方本卡与敌方拼点的来源范围互斥，即使对方已有拼点也改不到。 |
| 随机选一张敌卡后，让己方获得刺击强化 | 目标没被动作消费，随机敌卡可读成「敌方至少有一张场上卡」。若这只是无意义的存在条件，应在成卡时略过此组合。 |
| 场序相邻卡存在时，随机冻己方一张卡 | 两个卡目标范围相互独立。随机目标有可能是本卡或无关卡，独立效果也缺少自冻的补偿。 |
| 给敌方所有卡的数量上限加值 | [最大数量读点](../../../../Scripts/Game/Domain/Combat/CombatCard/CombatCardDataAmount.cs#L12) 先判断 `IsAmount`。普通卡未必有效，且独立效果在帮敌方。 |
| 自己耗尽且存在共边卡时，给敌方加盾 | 耗尽时机有价值，独立卡缺少承受惩罚的回报。给敌方治疗、补 MP、提供法宝供能也归入这类。 |
| 此卡离场时，由此卡监听离场广播并对敌方造成伤害 | 移除入口先调用本卡 `OnLeave` 并结束实例，再广播 `OnCardLeave`。可改由另一张场上卡监听友方离场。 [移除流程](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcCardFunc.cs#L157) |

无效组合、错目标和可自循环在成卡环节处理。直接给盾、给锐意或清伤都能结算，是否需要这些基础卡留给设计评审。

## 第 02 轮复核

成卡模式仍按 JSON 权重抽。先抽 T，再按事件约束抽 C，最后在至少有一组合法参数的 A 中抽模板。抽完 A 才从其合法参数组合中等概率取值。无效方向、收益方向和事件回路由脚本判断，不用分数挑卡。 [抽样记录](抽样记录/第02轮.txt)

后续轮增加了一项定性约束。全场冻结仅在本卡主效果或本卡耗尽时作为独立候选。常驻监听反复冻结全场留给原始抽样和人工设计。

| 抽到的组合 | 判断 |
| --- | --- |
| 己方 MP 改变，若下方有法宝，则使上侧共边卡向下滑 | 上侧目标因共边而必然紧贴参照卡。向下的第一步撞参照卡，效果没有位移。应排除前往参照卡的滑移方向。向左推下侧邻卡还有空间选择。 [连续滑移实现](../../../../Scripts/Game/Domain/Combat/CombatBackpack/CombatBackpackFunc.cs#L27) |
| 己方成功补灵后，先随机选一张己方卡，再治疗自己 | 随机选出的卡没有进入角色治疗。成卡时限制通用选卡器必须把结果给动作，否则直接写无条件或改用有决策意义的存在条件。 |
| 卡牌位移后，使本卡对应装备的防御增加至战斗结束 | 只有装备或已经绑定装备的招式能命中对应实例。普通法宝不能单靠 `Self` 获得装备写点。 [装备实例查找](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcEquipmentFunc.cs#L51) |
| 一张术牌结算后，选所有敌卡再恢复己方 HP | 对方场上通常必有主功法，条件难以制造机会或限制。功能上能成立，作为独立牌缺乏区分。 |
| 轮首阶段过去后，取得只持续当轮的法宝供能 | 当前轮供能已经结束，到下次轮首前效果会被移除。轮首监听在供能之前，因此「轮首时给本轮供能」成立。随机成卡选择覆盖未来轮首的期限。 [轮首顺序](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcRoundFunc.cs#L29) |

## 第 03 轮复核

本轮验证了通用选卡必须把结果给动作的规则，也检查起效后可能没有玩法读点的属性。 [抽样记录](抽样记录/第03轮.txt)

| 抽到的组合 | 判断 |
| --- | --- |
| 选相邻卡，使其对应的装备速度提高 X，持续 X 轮 | 装备快照确实增速，但当前招式只解包 `spd`，扫描也只读背包自身进度。将「速度」从装备数值模板的可选参数移出。接口仍可为以后有速度读点的内容使用。 [装备快照](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcEquipmentFunc.cs#L27) · [剑刺使用攻防数据](../../../../Data/Card/Lua/card_form_jian_ci.lua#L5) |
| 本方轮首，若来源卡右侧有伤势则治疗 | 事件没有来源卡。需要明确检查的是这张被动卡的右侧。可用监听卡构造检查用上下文。 [轮首事件](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcRoundFunc.cs#L37) |
| 友方卡位移，数「来源卡」右侧伤势来决定是否伤敌 | 位移发起卡和实际被移动卡可能不同。 设计时固定参照为监听卡或 `MovedCard`，否则玩家无法从卡面知道要摆哪张。计数若只做大于零判断，应写成「有伤势」。 [位移事件字段](../../../../Scripts/Game/Domain/!Global/API/Combat/Action/CombatBaseAction.cs#L24) |
| 己方攻击侧结算后，把己方全场卡一起向左滑 | 动作按顺序逐张提交，不是整盘同时移动。若玩法要求保留全阵形，需要独立的原子操作。普通滑移可以明确只查侧边卡，或接受阻隔和顺序。 [逐张移动](../../../../Scripts/Game/Domain/!Global/API/Combat/Action/CombatBaseAction.cs#L19) |
| 友方卡位移且左侧有招式时，冻结敌方全场 | 全场冻结是合法动作。若可在每行重复触发，可能压掉对方全部发动机会。试玩需限制触发频率或改成冻结一张。此轮落选。 |
| 主结算时检查剩余消耗次数为零，再施加出血 | 可以实现。消耗在本次主效果前提交，最后一次仍完整结算。卡面写「最后一次发动」即可。 [扣次与调用顺序](../../../../Scripts/Game/Domain/Combat/CombatCard/CombatCard.cs#L184) |

## 第 04 轮复核

回到 [原始抽样](抽样记录/第04轮.txt) 看成卡模式过滤掉了什么，再核对正式接口中的参数消费。

| 抽到的组合 | 判断 |
| --- | --- |
| 对拼分出胜负就按百分比提升气血 | 气血是基础属性，默认和成长值按 `AddValue` 加在百分比之后。生命上限的公式另有缓存，改气血也不能保证当场重算它。随机模板直接选战斗有读点的「生命上限」，用平加。回归验证了增加上限和后续治疗。 [属性求值](../../../../Scripts/Core/Base/Stat/StatEntry.cs#L141) · [治疗读点](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcFunc.cs#L75) |
| 主结算提高本卡对应装备的防御 | 牌本身要有装备数据，或是能找到父装备的招式。这个构筑前提并非任意法术都满足，因此继续保留在原始抽样，由设计明确承载者。 |
| 己方作为防御侧结算，本卡剩余消耗不少于 X 时获得再生 | 可以作为明确的消耗品防御卡。必须让本卡生成防御拼点并限定本卡是这次防御来源；普通独立监听没有这个保证。因此保留在原始模式，设计稿写明承载方式。 |
| 自己扣除 HP 时为敌方治疗 | 有复合代价或反向互动才可能有价值。作为我方一张独立牌默认挡掉。 |
| 随机选一张敌卡再让动作使用「选中」 | 普通选卡原来只返回名单，动作从 `CardTargets` 读不到它。现已和空间选择器对齐，在同一个上下文内登记选中列表。回归检查再次修改 Lua 返回列表也不会改变选中目标，空结果会清掉旧目标。 [选卡实现](../../../../Scripts/Game/Domain/!Global/API/Combat/Condition/CombatBaseCondition.cs#L115) |

## 第 05 轮复核

本轮重点看随机目标和跨卡联动。 [抽样记录](抽样记录/第05轮.txt)

| 抽到的组合 | 判断 |
| --- | --- |
| 己方防御侧结算后，随机让一张敌方卡向下滑 | 原动作先从全场随机一张，抽到固定功法就白费，即使另有可滑卡。已改为在战斗种子控制的随机次序中寻找可滑卡，成功一次就结束。目标域若用「选中」，仍按选中的具体卡尝试。 [随机滑移](../../../../Scripts/Game/Domain/!Global/API/Combat/Action/CombatBaseAction.cs#L16) |
| 随机选取敌方一张场上卡，降低该卡下次实际对拼点数 | 可能选中不会参与对拼的固定功法或被动卡。条件已经成功，但登记可能一直没有消费机会。若玩法承诺一定可兑现，需要一个能只选会生成拼点的卡的条件。 |
| 此卡耗剩 X 次时，提高己方生命上限 | 初始消耗必须高于门槛，因为主效果读到的是本次扣次后的值。成卡时把首次有效次数和初始消耗绑定。 |
| 己方卡滑移后回收土灵元，另一张卡在 MP 改变后让邻卡滑移 | 单卡都不立即调用自己的事件，搭在一起会串成事件回路。实际受可回收土灵元、MP 空缺和合法位置限制。正式搭配测试应包含可重复位移加供灵的第三张牌，检查同一事件链中是否需限定每个效果的触发次数。 |
| 己方卡结算后选中己方全场卡并整体上移 | 「全场卡逐张移动」和「阵位整体平移」的差异会明显改变玩家预期。成卡保留逐张规则时，卡面直接写「依次滑移」。 |

## 第 06 轮复核

本轮重点检查能命中目标，但效果永远没有消费机会的组合。 [抽样记录](抽样记录/第06轮.txt)

| 抽到的组合 | 判断 |
| --- | --- |
| 此卡旁边有伤势，登记本卡下一次刺击对拼提高 X | 如果此卡的唯一效果就是登记加值，它不会自己生成刺击。成卡模式去掉单效果「来源卡是本卡」选项，已有攻防拼点的卡仍可手配这种后续强化。 |
| 选取下方共边法术，提高它们对应装备的防御 | 法术主类不会因此获得绑定装备。针对选中卡的装备动作只考虑有机会是装备本身或绑定招式的关键词。 |
| 此卡是消耗卡，就给自己载德 | 「剩余次数至少为零」对正常消耗卡本身恒真，只剩关键词前置。整理卡面时合并为普通的消耗卡结算效果。 |
| 每次本方轮首为场序相邻卡登记一次下次对拼加值 | 当一轮没有匹配配对，下一轮可能仍未到期。后续登记可以叠加。设计保留把加值攒给一张重牌的可能，评审时应查看一次性爆发是否失控。 |

## 第 07 轮复核

回看 [原始抽样](抽样记录/第07轮.txt) 的反向收益和长期叠加。

| 抽到的组合 | 判断 |
| --- | --- |
| 己方攻击侧结算后，令敌方立即补灵 | 敌方格里有空位时会扣 MP，也会送给对方可用灵元。没有成功落格便不扣 MP。这可以是有代价的特殊互换，不能当作稳定的削 MP。 [补灵结算](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcManaFunc.cs#L57) |
| 此卡被位移时施加出血，但 T 为空 | 位移条件只有位移事件才有意义。给它一个实际位移触发即可得到「被推着反咬」的玩法。原样留在问题记录。 |
| MP 改变后再发起火系打击拼点 | 事件发生时可能已有待发，强行入槽会绕开逐行发动额度。保留现有 `Contest` 授权边界。 |
| 每次对拼都获得整场的土系法宝供能 | 合法，且可用法宝的激活窗约束入口。供能会累积，批内抽到这一条的价值是养多件土法宝，风险是单件很快补满。卡面需清楚说明「可累积」，后续据试战决定是否限量。 |
| 上侧共边招式存在时，获得卸力 | 这条位置条件有空间意义。反过来，要求「邻接被动发动」常见配置很难满足，因为被动不会走主动发动。成卡模式应排除方位发动条件里的被动参数。 |

## 第 08 轮复核

本轮区分前置事件直接改变当前结算，以及只为下一次登记效果。 [抽样记录](抽样记录/第08轮.txt)

| 抽到的组合 | 判断 |
| --- | --- |
| 友方轮末直击时，破敌方灵盾 | 直击事件发生在伤害进入队列之前。这个效果能作用于本次直击，顺序不需要另造「攻击前」触发。 [直击顺序](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcFunc.cs#L184) |
| 友方卡位移后，降低敌方选中卡的下一次格挡 | 己方造成位移和敌方参与对拼是不同时间。登记锁定选卡，直击不消费；描述含「实际对拼」，免得玩家以为会覆盖下一次发牌。 |
| 友方成功补灵后，让左侧卡继续向左滑 | 触发时灵元已经放置。滑移停在有灵元的格子会让终点覆盖灵元让位，可能把刚抽的灵元挤掉。可作为布局代价保留。 |
| MP 改变且左邻有被动时，获得浩瀚 | 浩瀚在另一处基础补灵前回 MP，可能再叠一层。本身不递归触发基础补灵，但会形成跨轮的正反馈。与上限、效果次数和激活周期一起评估。 |
| 对拼随机选敌卡，降低它未来的装备攻击 | 若随机命中普通卡，装备实例查找不会命中。要保证每次有效，需在选择阶段限定有装备读点的目标。定向选招式可以满足这个要求。 |

## 第 09 轮复核

在[原始抽样](抽样记录/第09轮.txt)中同时出现了「改当前拼点」和「读已经分出的胜负」。这两类可用窗口不同。

| 抽到的组合 | 判断 |
| --- | --- |
| 比较拼点时检查己方已经获胜，再添出血 | 比较前尚无胜者。要读胜负，使用胜差事件。 |
| 己方落败后获得浩瀚 | 组合有效。胜差事件的 Caster 是赢家。若只过滤 Caster 等于卡牌拥有者，会漏掉败方。先用败方条件认出本方，再给主人加状态。 |
| 对拼开始时，降低敌方当前攻击拼点 | 合法且可立即改变胜负。多人战要找 `ContestA`、`ContestB` 中与本方配对的参战者，再写该方当前拼点。使用当下普通敌方目标会有选错人的风险。 [配对字段](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcFunc.cs#L252) |
| 胜差事件中再生成金系打击拼点 | 此时已结算的是前一次动作。尝试新建待发会被卡牌的发动授权拦住。要追击需另设有资格的新发动或已有后继动作。 |
| 选择相邻卡后获得自身生命上限 | 相邻列表可明确用作「至少存在一张相邻卡」条件。写为「给相邻卡加生命上限」会把角色属性误当卡属性。 |

## 第 10 轮复核

本轮从 [成卡候选](抽样记录/第10轮.txt) 核对了对拼事件内的生效先后，以及高频控制。

| 抽到的组合 | 判断 |
| --- | --- |
| 对拼比较前获得卸力 | 本次配对先消费已有卸力，再派发对拼事件。新获卸力留给下次攻击配对。若要改当前拼点，用修改拼点动作。 [消费顺序](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcFunc.cs#L24) |
| 上侧有共边被动时，在对拼开始登记下次闪避加值 | 当前比点的下一次加值已消费完，登记可自然跨到后继配对。卡面需要写「之后下一次」，避免正在进行的闪避自己吃到这项收益。 |
| 对拼比较前让下侧邻卡向下滑 | 正在待发的卡会被滑移拒绝，可以用这一点安排备用牌的位置。写明动作只影响可滑邻卡。 |
| 本方每轮末冻结敌方全场 | 连续扫描轮可以锁掉对方几乎全部发动窗口。这属于要评审的控制强度。成卡前可改成限定目标域或给触发安排可见耗费。 |
| 扣除 HP 后，选相邻卡提高其装备攻击 | 伤害事件早于 HP 清零后的伤势插入。若这一下刚产生伤势，选卡仍按当时的旧场序。 [受伤结算顺序](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpc.cs#L138) |

## 第 11 轮复核

本轮关注状态变化触发的收益怎样在界面上表达清楚。 [抽样记录](抽样记录/第11轮.txt)

| 抽到的组合 | 判断 |
| --- | --- |
| 己方基础补灵前，提高水亲和 | 对当次抽灵生效，因为先派发基础补灵事件，再按亲和抽取。若触发写成「成功补灵后」，效果将影响后续批次。 [补灵入口](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcManaFunc.cs#L45) |
