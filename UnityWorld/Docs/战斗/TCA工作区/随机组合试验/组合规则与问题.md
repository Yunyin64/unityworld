# TCA 组合规则与问题

**审卡时，先看效果能否兑现，再看触发会不会失控，最后核对卡面。** 61 轮抽样里，反复出现的是触发时机对不上、目标没找对。能正常结算的效果里，优先实测反复冻结、跨卡连锁和多次叠加。

## P0　成卡前先排除失效和错结算

| 具体组合 | 处理 |
| --- | --- |
| **「轮首生成格挡」「治疗后发出射击」** | **已解决。**「攻击」「防御」都是 `Contest`，权重各为 2。成卡时只允许空触发的 `A` 或 `C+A`，等本卡正常发动后生成攻防拼点。轮首或治疗事件直接调用时会警告并跳过。 [动作模板](../../../../Data/Action/ActionTemplate_Contest.json) · [轮首格挡示例](逐轮复核记录.md#第-31-轮复核) |
| **「开始对拼时，若已获胜就提高本次拼点」** | **已解决。** 比较前可改当前拼点。分出胜负后才能判断输赢，此时仍可影响尚未扣除的护甲、灵盾和伤害。方向上的牌是否发动，要跟随发动事件的占格快照。「本卡被移动」要跟随滑移事件。候选已限制这些条件各自对应的触发。 [条件实现](../../../../Scripts/Game/Domain/!Global/API/Combat/Condition/CombatBaseCondition.cs) · [对拼结算](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcFunc.cs#L247) |
| **「己方牌被推后给盾」** | **已解决。** 背包提交位移后发出「卡牌被位移时」，`Self` 是被移动牌的主人。移的是他人的牌时，再发出「移动他人卡牌时」，`Self` 是位移发起者。若卡牌只响应己方牌被推，还要核对事件主语与监听牌的主人。 [位移提交](../../../../Scripts/Game/Domain/Combat/CombatBackpack/CombatBackpackFunc.cs#L59) |
| **「随机选一张敌卡，再让己方回血」「直接改选中牌的装备」** | **已解决。** 选卡后，动作必须使用选中的牌。动作需要选中的牌时，必须先选卡。只想判断方位时，用「右侧有共边功法」一类条件。 [抽样规则](../../../../tools/sample_tca.py#L246) |
| **「上侧必须有共边招式，同时本卡向上滑」** | 第一格被条件牌堵住。把本卡推向确定被占据的一侧，或把共边卡推向本卡，这两类确定撞挡的组合已拦截。多张卡同向滑移仍可能部分成功。 [示例](抽样记录/第37轮.txt) |
| **「加装备速度」「给普通战斗卡加数量上限」「提升气血就当场加血」** | 当前牌池需要有实际读取点。装备模板保留攻击和防御，数量上限暂留原始抽样。试验中的加生命模板直接平加生命上限，增加的是后续可恢复空间。 [原始复核](逐轮复核记录.md#第-03-轮复核) · [属性示例](抽样记录/第04轮.txt) |
| **「补灵成功就补灵」「友方牌离场就清伤」** | 候选拦截这类直接反馈。运行时同一张牌在同一条事件链里，对同内容的事件最多响应一次。同帧两次独立结算可以各自触发，事件广播和链预算照常运行。 [事件派发](../../../../Scripts/Game/Domain/Combat/CombatScene/CombatSceneEvents.cs) |

**已修的底层问题**　普通选卡会把结果交给动作。随机推一张敌卡会从确实能滑的牌里找目标。**冻结**只考虑未冻结且未耗尽的主动卡。敌方直伤会带上伤害来源，回归中 3 点直伤遇到 2 点护甲只扣 1 点 HP，出血自伤仍保留护甲。 [选卡](../../../../Scripts/Game/Domain/!Global/API/Combat/Condition/CombatBaseCondition.cs#L116) · [滑移与直伤](../../../../Scripts/Game/Domain/!Global/API/Combat/Action/CombatBaseAction.cs) · [冻结](../../../../Scripts/Game/Domain/!Global/API/Combat/Action/CombatCDAction.cs#L34) · [伤害回归](../../../../Scripts/Tests/TcaAlignmentTests.cs#L316)

## P1　进正式卡池前优先测这四类

| 风险 | 先看什么 |
| --- | --- |
| **对手长期动不了** | 「每次发动就冻结敌方全场」可能连续盖住敌方的扫描机会。候选把全场冻结限在本卡主效果或耗尽。单张冻结配合多张连续滑移也会扩大覆盖。减速倍率固定，同类反复施加会把时间累长。先测对手实际失去多少次发动机会。 [冻结示例](抽样记录/第55轮.txt) |
| **多张牌互相续事件** | 「滑移后把水灵元回收成 MP」接「MP 变化后再滑移」，能绕回第一张牌。实际停止取决于格上灵元、MP 空缺和滑路。再加补灵或反向滑移，会改变停止条件。先测三张一起上阵时能否自然停下。 [组合示例](抽样记录/第45轮.txt) |
| **攒到一次爆发或永久滚大** | 「每次 MP 变化都强化下一次斩击」可能把多笔加值交给同一次对拼。多次滑移强化装备、每次对拼登记永久法宝供能，也会累积。先看一轮能触发几次、每次能惠及多少张牌。 [拼点示例](抽样记录/第30轮.txt) · [供能示例](抽样记录/第33轮.txt) |
| **合法却常抽空，或收益给错人** | 「随机选敌卡后降其装备攻击」可能抽到没有装备的牌，随机标记也可能标到永不对拼的牌。若卡面承诺兑现，先缩小目标池。自伤、给对手补灵等反向效果适合作为有明确回报的代价。独立候选已挡掉这类通常只吃亏的参数。 [装备示例](抽样记录/第54轮.txt) · [资源示例](抽样记录/第39轮.txt) |

## P2　卡面写清什么时候、对谁有效

- **本次、下次和直击。** 「下一次实际对拼」只在符合类型的配对里使用，直击不消耗。选卡后登记会记住当时选中的牌，换位或新牌入场不改名单。新获得的卸力留给后续配对。装备攻防变动也只影响之后生成的拼点。 [拼点与目标](抽样记录/第57轮.txt)
- **耗尽和承伤。** 消耗是先扣次数再查条件。最后一次主效果照常结算，灵活牌稍后才离场。想利用实际腾出的格，要等离场。掉 HP 后加盾只能护下一笔伤害，伤害全被挡时也没有掉 HP 触发。成功治疗按实际恢复判定。 [消耗示例](抽样记录/第35轮.txt) · [承伤示例](抽样记录/第61轮.txt)
- **持续时间和轮首。** 「X 轮」注明是本方轮还是敌方轮。按轮计时的效果包含施加当轮。只活本轮的法宝供能要赶在轮首供能前登记，轮末新加的本轮坚甲很快到期。排程一旦登记，之后失去邻卡也照常发放。写 Tick 的效果另按战斗时间，充能加进度，加速和减速从后续 Tick 生效。 [轮首顺序](../../../../Scripts/Game/Domain/Combat/CombatNpc/CombatNpcRoundFunc.cs) · [扫描时钟](../../../../Scripts/Game/Domain/Combat/CombatBackpack/CombatBackpackScan.cs)
- **方位、移动和补灵。** 「共边」看格子边缘，「场序相邻」看队列前后。多卡滑移逐张尝试，走过的灵元保留，终点盖住的格上灵元会被移除。补进空格才扣 MP，一次补灵成功只发一次事件。改变亲和只影响之后的抽灵。 [滑移示例](抽样记录/第50轮.txt) · [补灵示例](抽样记录/第35轮.txt)

## 抽样怎么跑

- **T 是触发，C 是条件，A 是动作。** T 和 C 都可以抽空，A 必选。四种结构是 `T+A`、`T+C+A`、`C+A`、`A`。空触发在中文效果中省略。
- **权重读原 JSON。** 抽中某项的机会是它的权重除以当前池的总权重。空触发权重 34，触发总权重 59。空条件权重 36，条件总权重 54。38 个可抽动作总权重 46。原始抽样按三个池独立抽，参数从 `ParamDefs.Value` 均匀取值。成卡候选先筛兼容模板，再从可用参数组合均匀取一组。两种模式均无评分。
- **默认抽 100 条。** 在 `UnityWorld` 目录运行 `python tools/sample_tca.py --seed 2026112161`。加 `--raw` 可以查看未经过组合筛选的样本。旧的抽样文件保留生成时的权重和规则。 [抽样脚本](../../../../tools/sample_tca.py)
