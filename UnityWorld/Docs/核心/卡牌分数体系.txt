卡牌分数体系（设计备忘，未开发）
====================================

核心思路
--------
卡牌总分 = 基础分数 + 效果分数

基础分数 = CD分 + Size分
效果分数 = Trigger分 + Condition分 + Action分

所有分数通过查表获得，非线性，设计者手配。

分数示例
--------
CD 5s → -5（标准代价）
CD 3s → -1（略好于标准）
CD 1s → +10（几乎无CD，极强）

Size 1 → 0（标准）

Trigger "使用时" → 0（最常见）
Condition "无条件" → 0
Action "斩击5" → 5

示例卡：使用时 + 无条件 + 斩击5 + CD5s + Size1 = 0分（标准基础卡）

总分与境界
----------
总分 = 0：标准新手卡
总分随境界提升：
  练气 → 2分
  筑基 → 5分
  金丹 → 10分

境界决定卡的预算上限，越高级的卡允许越多"溢出"。

Size 的双重作用
--------------
1. 分数贡献：占用卡组空间换取预算（Size 1 = 0，Size 越大给越多预算）
2. 效果解锁门槛：某些强力 Action 要求最低 Size 才能装载
   例："时间停止" 需要 Size ≥ 3（太强，不允许塞进小卡里）

Size 不只是数值调平的旋钮，还是内容分层的硬锁。

两种生成模式
-----------
1. 基于内容（叙事驱动）：
   输入 Tag（如"荣耀"）→ 匹配组件 → 组装卡牌 → 算出总分
   分数是结果，可通过调整 CD/Size 来平衡

2. 基于效果（机制驱动）：
   随机拼效果 → 算出总分 → 根据组件自带的 Tag 亲和度反推主题
   分数是约束，Tag 从组件亲和度中自然涌现

与现有 PowerScore 的关系
------------------------
旧：PowerScore = Trigger.Score + Condition.Score + Σ Actions.Score（只管效果内部）
新：TotalScore = 基础分数 + 效果分数（把使用代价也纳入同一预算体系）

替代旧体系，同时扩展维度。

关键设计点
---------
- 每个可拼接组件同时携带：① 分数 ② Tag亲和度
- 分数表是双向翻译层：连接 Tag空间（叙事/语义）和效果空间（机制/数值）
- Tag 冲突不是问题——浓度决定主题，低浓度 Tag 只是"带一点味道"
