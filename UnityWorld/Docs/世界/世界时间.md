# 世界时间

## 历法规则

世界日期用非负整数“已过周数”作为唯一时间基准。每年依次是新年特殊周、十二个月各四周、除夕特殊周，共五十周；进入下一个新年才换年。读取日期或绘制画面不会推进时间。

普通月四周依次为新月、上弦、满月、下弦。月份地支从寅月排到丑月；年份天干按现实公元纪年锚点计算，公元 4 年为甲，4000 年为庚。这里借用现实干支纪年的算法，年内采用游戏固定周历，不换算真实公农历日期。

本提案采用的特殊周规则：新年和除夕各占一周，普通月份、月内周、月份地支和月相为空；显示特殊周名称，不使用零月或十三月占位。

数字例子：

| 已过周数 | 日期显示 |
|---|---|
| 0 | 4000（庚）年 新年 |
| 1 | 4000（庚）年 1（寅）月 新月 |
| 3 | 4000（庚）年 1（寅）月 满月 |
| 5 | 4000（庚）年 2（卯）月 新月 |
| 48 | 4000（庚）年 12（丑）月 下弦 |
| 49 | 4000（庚）年 除夕 |
| 50 | 4001（辛）年 新年 |

## 日期读取

`WorldDate` 是不可变值快照，所有字段由 `ElapsedWeeks` 推导。`WeekOfYear` 是包含特殊周的年内第 1—50 周，`WeekOfMonth` 只在普通月存在，为第 1—4 周。

```csharp
using UnityWorld.Game.World;

var date = new WorldDate(1);
Console.WriteLine(date); // 4000（庚）年 1（寅）月 新月
Console.WriteLine(date.YearStem.GetDisplayName()); // 庚
```

## 节气

普通月前两周属于前一个节气，后两周属于后一个节气；新年和除夕当前节气为空，不占普通节气位置。这里是每两个普通周一个节气的游戏规则。

| 月份 | 地支 | 新月、上弦 | 满月、下弦 |
|---|---|---|---|
| 1 | 寅 | 立春 | 雨水 |
| 2 | 卯 | 惊蛰 | 春分 |
| 3 | 辰 | 清明 | 谷雨 |
| 4 | 巳 | 立夏 | 小满 |
| 5 | 午 | 芒种 | 夏至 |
| 6 | 未 | 小暑 | 大暑 |
| 7 | 申 | 立秋 | 处暑 |
| 8 | 酉 | 白露 | 秋分 |
| 9 | 戌 | 寒露 | 霜降 |
| 10 | 亥 | 立冬 | 小雪 |
| 11 | 子 | 大雪 | 冬至 |
| 12 | 丑 | 小寒 | 大寒 |

数字例子：已过 1、2 周都是立春；第 3、4 周是雨水。第 48 周是大寒，49 周除夕和 50 周新年都为空，第 51 周再次进入立春。

## 单周推进与通知

`WorldCalendar` 按单线程调用，每次 `AdvanceWeek()` 只提交一个周位，并返回不可变的 `Before`、`After` 及 `SolarTermChanged`。负数初值和上界溢出会明确失败，且不会部分提交。

```csharp
var calendar = new WorldCalendar();
calendar.WeekAdvanced += change => Console.WriteLine(change.After);
calendar.SolarTermChanged += change =>
    Console.WriteLine(change.After.SolarTerm?.GetDisplayName() ?? "特殊周，无当前节气");

var result = calendar.AdvanceWeek(); // 进入一月新月，先通知日期，再通知立春。
Console.WriteLine(result.Before);   // 仍然是 4000（庚）年 新年。
```

日期先提交，然后发送周通知；仅在可空节气身份变化时再发送节气通知。除夕到新年两者都为空，不重复发送节气变化。每次推进开始时保存两种订阅快照，回调期间的订阅增减从下一次推进生效。

通知是对已提交时间的只读观察，不承担天气、产出、NPC 交互或其他世界结算。回调期间再次推进会被拒绝；单个回调异常会被记录，其他观察者照常收到通知，原推进仍成功返回。调用者不应因为观察者报错而重试推进。

## 世界接入与旧秒时钟

全局入口为 `WorldTime.CurrentDate`、`WorldTime.Calendar` 和 `WorldTime.AdvanceWeek()`。`WorldTime.Calendar` 可用于订阅通知；一次成功的世界初始化会替换它，所以新会话应获取新实例并重新订阅。初始化不发送“推进一周”通知。

```csharp
// 世界初始化由现有 WorldMgr.Initialize(...) 管理，不为读取日期重复初始化。
Console.WriteLine(WorldTime.CurrentDate); // 新世界：4000（庚）年 新年
var change = WorldTime.AdvanceWeek();
Console.WriteLine(change.After);         // 4000（庚）年 1（寅）月 新月
Console.WriteLine(change.After.SolarTerm?.GetDisplayName()); // 立春
```

旧 `CurrentTick`、`DeltaTime`、`TotalTime`、`RandomSeed` 和 `Advance(float)` 保留原语义。旧物理帧驱动仍会推进旧秒计时和已接入的世界系统，但不会推进新周历；新周推进也不会改变秒数、更新次数或随机种子，不会执行各管理器 Tick。两者没有默认换算关系，不能把一周换成大量秒数后调用旧世界 Tick 代替周结算。

`WorldMgr.Initialize()` 继续在地图及依赖全部成功后初始化时间。失败初始化保留原周历实例和日期；创建或销毁额外位面也不推进周历。退出本身不重置最后日期，下一次成功初始化才建立新的 4000 年新年周历和订阅生命周期。

未来周结算器负责对象交互、执行顺序和分批预算，整周结果完成后再调用周推进提交日期。时间模型不保存玩家身份或优先级。本次完成后端基础、查询和通知，尚未接入前端、移动、NPC 周结算及节气玩法效果；前端任务应依赖本后端验收完成。
