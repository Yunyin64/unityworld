# 地区拼图世界：生成与配置

主大陆为 **200×200 六边形格，共 40000 格，边界包含在其中**。生成器先建立固定边界及环境，完整放下作者地区，再按适配与权重补齐空隙。地块可以代表一座山及其周围，山地、林山、荒山、火山、雪山为同级类型。

## 运行入口

在 `UnityWorld` 目录构建一次：

```powershell
dotnet build Console/UnityWorld.Console.csproj --nologo
```

导出一个世界（输出父目录下会创建唯一运行目录）：

```powershell
dotnet Console/bin/Debug/net8.0/UnityWorld.Console.dll --map-generate --seed 20261031 --profile china-inspired-v1 --data-root . --output ../docs/world-map-preview
```

成功后打开打印出的 `map.html`。页面包括全图、缩放、平移、地形/自然海拔/排水高度/湿度/温度/水体与河带/汇水量/来源图层、地区轮廓、中心线、地区索引和选格信息。它只读取同一 C# 生成器的导出数据，不在浏览器另行随机。

```powershell
dotnet Console/bin/Debug/net8.0/UnityWorld.Console.dll --map-generation-tests --data-root .
dotnet Console/bin/Debug/net8.0/UnityWorld.Console.dll --map-batch --seed 1 --count 20 --profile china-inspired-v1 --data-root . --output ../docs/world-map-preview
dotnet Console/bin/Debug/net8.0/UnityWorld.Console.dll --map-runtime-hash --seed 20261031 --profile china-inspired-v1 --data-root .
```

最后一条启动真实世界但不推进 Tick，用于与纯生成预览摘要对比。原有战斗测试入口继续使用原参数。

## 数据文件

| 文件 | 作者配置内容 |
|---|---|
| `Data/TileDefines/` | 每种地块的小文件：标签、颜色、环境、基础填充、邻接、移动和初始元气 |
| `Data/RegionDefines/` | 每个地区的小文件：固定布局、数量、适配、地标、水系接口和关键格 |
| `Scripts/Game/World/WorldGenerationOptions.cs` | 普通算法参数，默认值来自代码，可由 PlaneConfig.GenerationOptions 传入 |
| `Data/LandMarkDefines/` | 每个地标的小文件：自然/人工、统一元气偏移、附加修正引用、散布条件 |
| `Data/TileModifierDefines.json` | 修正来源的每秒元气变化量及持续时间 |

`china-inspired-v1` 是开发样例，借鉴中国大陆地貌的多样性，名称和布局不等同于真实地理复刻。边界厚度、南部雨林/沙漠具体分布、地貌权重可以继续调优。西侧长城固定阻断所有移动模式，其余边界是否可进入独立配置。

固定边界复用六份普通小地区模板及 ForcedPositions 锚点列表；不再使用边界专用规则、WorldGenerationDefineMgr 或独立世界生成 JSON。地块、地区、地标定义拆成小文件；简单参数与布局坐标按行分组，保持直接可读。目录加载统一检查重复 ID，文件名及读取顺序不影响生成。完整四万格只出现在运行结果/诊断导出中。

## 一格土地

`ID` 是稳定类型标识。`Tags` 用于查询，不代表类型继承。`Color` 是诊断颜色，`AssetRef` 留给后续客户端素材。

- `InitialAura`：金木水火土的初始浓度，按地块独立复制。
- `AllowFill`：是否允许作为空隙填充；特殊地区专属类型可以关闭。
- `FillWeight`：候选基础权重，零表示不被随机选中。
- `Environment`：海拔、湿度、温度的硬区间，以及软偏好和偏好强度。
- `AllowedNeighborIds` / `ForbiddenNeighborIds`：双向检查的邻接硬限制。
- `NeighborWeights`：与特定类型相邻时的相对偏好。
- `MovementModes` / `MovementCost`：静态可达性和后续旅行使用的数据。
- `WaterKind`：`none/river/lake/ocean`；格内小溪小潭可只写入描述，不开启跨格水系。

填充先筛硬条件，再计算 **基础权重 × 环境适配 × 邻接偏好**。无合法正权重候选时有限回退或报告失败，不强塞平原。

## 固定地区拼图

`TerrainLayout` 的键是相对 Axial 坐标 `dq,dr`，值是地块类型 ID。**这些键就是全部占地**，不是 Width×Height 的实心矩形。没有写入的格子为孔洞/外部空间，可以被其他地区或填充使用。布局保留朝向，不自动旋转、镜像或裁切。

世界边界用 Offset 行列（0..199）；地区锚点转换为 Axial 后再加偏移。不可把相对 Axial 直接当作行列偏移，否则奇偶行会改变形状。

- `MinCount`：必需数量；`MaxCount=-1` 为不限，其余最大数量不可小于最少数量。
- `SpawnWeight`：合法候选中的选择权重；`MinSpacing` 为同类锚点的六边形距离。
- `AnchorEnvironment`：锚点条件。
- `KeyEnvironment`：主峰、河谷等指定相对格的条件。
- `OverallEnvironment` / `RequiredEnvironmentFraction`：占地内满足环境要求的比例。
- `EnvironmentAdjustments`：显式局部修整，必须在配置上限内且不能破坏水系。
- `LandMarkLayout`：固定地标位置，必须属于实际占地；地区完整成功时必然生成。
- `AuraProfile`：保留的兼容偏移，正式内容默认全零，不做专门检查；地区主要用于辅助生成。

必需地区优先安排；可选地区受覆盖率目标和预算控制。覆盖率分母为非固定格扣除海域、河带及整个湖泊地区后的陆格，分子为普通地区在这些陆格上的实际占地。软覆盖目标不足可以带警告成功；必需地区缺失、半块地区、无合法填充则失败。

固定地标忽略其独立散布权重/散布地形过滤，但必须满足引用、占位和唯一性。任一固定地标失败使整块地区候选撤销。独立地标只散布在没有地标的基础填充格，作者地区及边界不会被随机追加地标。

## 水系与通路

跨格河流先按环境规划骨架。涉水地区用 `RiverCells` 明确内部河段，用 `RiverPorts` 明确对外入/出口。方向沿现有六邻接顺序：0 东、1 东南、2 西南、3 西、4 西北、5 东北；相对方向差 3。

每段陆地河流至多一个下游，可接受多条上游汇流。所有河流必须沿合理地势接入海域或指定内陆湖；等高连接也必须无环。地区端口不匹配就换位置，不改作者布局。仅基础填充允许在预算内修补，修补后重检全部约束。

`ConnectivityGroups` 明确哪些关键地点需要用哪种能力互通，包含固定行列坐标或 `regionId:keyPointId`。是否能够渡河独立设置；有意隔绝的岛屿/禁地可不加入徒步互通组。检查仅做静态可达性，不移动角色、不触发探索、不推进世界时间。

## 元气与生命周期

实际生成顺序为 **确定 Tile 类型和基础元气 → 创建全部自然地标 → 原初快照 → 创建全部人工地标**。地区自带和独立散布的位置计划统一按 IsNatural 分组，快照前不会提前创建人工地标或挂上其修正。每格最多一个有效地标，生成不推进时间。

`AuraOffset` 是唯一偏移字段，默认五行全零：仅创世自然地标立即计入浓度和原初快照；创世人工地标以及运行后新增的任何地标（含自然地标）均按每秒变化量累积。例如人工地标火偏移 -2，放置时不变，半秒后火浓度减少 1。创世自然偏移只应用一次，不自动成为持续速率。旧 ModifierDefineIds 作为附加速率保留，不自动改写为偏移；移除地标清理其全部来源修正，保留历史浓度和原初快照。

候选地图在成功前不进入公开管理器；失败不留下地区、地标、修正或快照。位面发布时索引与快照一致，销毁位面/结束世界清理所属数据。快照以位面和坐标共同定位，兼容单坐标查询仅指主世界。

## 复现与输出

相同种子、规范化配置摘要和生成器版本得到相同结构。生成随机流与运行时实体 ID 分离；字典顺序、先前生成与无关战斗随机调用不改变结果。

成功运行目录包含：

- `map.html`：可查看预览，内嵌数据，可直接从本地打开。
- `map.json`：稳定顺序的地块、地区、环境、来源和水文数据。
- `diagnostics.json`：拒绝原因、有限样本、警告、预算使用与修整记录。
- `manifest.json`：最后写入的成功清单，含版本、配置/地图/边界摘要和阶段耗时。

失败返回非零退出码，并在独立目录写 `failure.json`，不借用旧成功输出。

数据迁移先运行检查/输出模式，核对结果后替换源文件；原始备份保留在 `tools/map_legacy_source/`。回退需要同时恢复代码与地图 JSON 的对应版本，不能用新生成器静默重掷已保存世界。

## 独立地标刷新扩展位置

`LandMarkMgr.GetIndependentSpawnCandidates(plane, defineId)` 按 PlacementTypeIds、PlacementTags、地区拓展标签、占位和全局唯一性返回稳定排序的候选，不依赖地区模板或 SpawnWeight。刷新器后续可从中随机抽取 xx..xx 个并调用 `Place`；周期、数量区间和不足数量策略后续细化。运行时刷新可选任意来源的空地标格，创世随机散布仍只使用 Fill 格。

`MapCatalog.cs` 放在 `Scripts/Game/World/`，与 `WorldMgr.cs` 相邻，仍保持独立加载和校验职责。

## 固定锚点：写一份小拼图，重复完整放置

`RegionDefine.ForcedPositions` 是绝对 Offset 锚点列表，每个坐标复制一整份 TerrainLayout。比如 `fixed_east_sea.json` 只写一次 10×10（100 格）海域布局，再列出 20 个锚点，运行时得到 2000 格；不是给 2000 格分别写定义。5×5 拼图同样可以列 20 个位置。

```json
"ForcedPositions": [{"Col": 190, "Row": 0}, {"Col": 190, "Row": 10}, {"Col": 190, "Row": 20}]
```

六份开发样例位于 `Data/RegionDefines/fixed_*.json`：长城 5×10×20，东海 10×10×20，北山 10×10×11，北漠 5×10×15，南沙漠 5×10×15，南雨林 10×10×11，共 92 个地区实例、6700 个固定格。作者工具只生成小模板及锚点列表；源文件不展开全部世界格。

非空固定列表最先执行，跳过权重、MinCount/MaxCount、间距、环境适配等普通筛选，不参加后续随机拼图。非法引用、越界、重复锚点、实际占地冲突和地标唯一性仍失败，不裁切或覆盖。FixedEnvironment 是地区的海拔、温湿度锚点；西墙不可通行来自 great_wall 地块定义。

布局永远是相对 Axial 坐标。锚点奇偶行不会改变拼图邻接关系，但视觉上的 Offset 矩形会随奇偶行平移；连续铺条带时要按模板选匹配的锚点奇偶性。示例的 10 行高度和偶数行锚点可以严格接缝。

固定地区与普通地区来源均为 Region，通过 IsFixed 区分；固定地区不能被随机拼图、补空和修补改写。普通陆地覆盖率分母排除全部固定地区、海域、河带及整个湖泊地区，分子只统计普通地区在可用陆格上的占地。诊断 BoundaryCount/BoundaryHash 保留兼容名称，当前表示固定内容数量及摘要。

`LandMarkDefine.ForcedPositions` 是绝对世界坐标列表，每点一个地标。先预留位置，再按自然→快照→人工阶段创建实例。它可以落在固定地区的空地标格，也可以等基础填充决定 Tile 类型；忽略散布权重和类型筛选，但不能覆盖已有地标或违反 singleton。配置固定位置的地标不再额外随机散布。

实际顺序：固定地区 → 固定地标位置预留 → 连续环境 → 海域 → 必需大湖 → 排水／汇水／实际河带 → 普通必需地区／随机地区 → 基础填充／审计 → 自然地标 → 原初快照 → 人工地标 → 原子发布。

## v3 水域、环境与湖泊作者字段

当前生成器版本为 `region-puzzle-v3`。`river`、`lake`、`ocean` 是同级类型；旧 `TerrainType` 数值3对应 River，Lake使用新值7，其余旧数值不变。河流初始元气仍为金0.8、木1.2、水2.5、火0.5、土0.8。

水域先决定资格，Fill再在该类别的正权重定义中选择；`AllowFill=false` 或零权重没有隐式兜底。陆地继续使用环境硬范围、基础权重×环境软偏好×邻接偏好。海域硬规则为**非固定自然海拔严格小于0.05**，0.049判海，0.05不强制；内陆低地也判海，不要求连到东海。低于阈值的固定陆地保留并记录 `sea.fixed-land-exception`。

三个高度各有用途：`Environment.Elevation` 是自然地形；`Water.DrainageElevation` 是填洼后的辅助高度；`Water.SurfaceLevel` 是海／湖水位。排水不写回自然海拔或温度。普通地区的显式调整不能跨越海平面或抬高到现有排水／水位之上；调整自然高度时温度同步变化 `-0.18×高度差`，然后重查地区条件。汇水贡献记录的是水文阶段采样值，不是实时天气模拟。

| 参数位置 | 默认值／含义 |
|---|---|
| `Environment.NoiseScale / DetailScale` | 34 / 12；大、中尺度，另有半细节尺度的小幅分量；权重0.68/0.25/0.07 |
| `Environment.ElevationAmplitude / MoistureAmplitude / TemperatureAmplitude` | 1.05 / 0.5 / 0.16；连续噪声总幅度 |
| `Environment.FixedSeed / FixedVariationScale` | 271828 / 22；固定环境独立种子和世界采样尺度，跨世界种子稳定 |
| `Environment.BoundaryBlendDistance` | 24；固定影响向腹地的过渡距离 |
| `Region.FixedEnvironment / FixedVariation` | 环境基准／逐轴变化幅度，按世界Axial平面坐标采样，模板副本不重置纹理 |
| `Region.FixedEnvironmentRange` | 三轴允许范围，默认均0..1；固定基准必须落在范围内，最终值也受其约束 |
| `Region.FixedBlendDistance` | 可覆盖本地区的全局过渡距离，未设置时继承 |
| `Region.BlendFixedEnvironment` | 固定内部是否混合其他固定环境；六份样例开启，多源归一化平滑混合 |
| `Region.AllowEnvironmentCliff` | 明确的物理陡变；开发样例仅长城／海岸使用，独立记录，不豁免普通地区边界 |
| `Hydrology.SeaLevel` | 0.05；仅自然高度参与，固定海域也约束在其下 |
| `Hydrology.TributaryThreshold / MainRiverThreshold / WideRiverThreshold` | 90 / 500 / 1800；非负湿润度沿无环排水图累积 |
| `Hydrology.MainRiverWidth / MaxRiverWidth` | 2 / 3；横向实际水格数，细支流1格 |
| `Hydrology.RoutingBudget / LakePlacementAttempts` | 2000000 / 4000；有限边搜索／湖泊候选预算 |
| `RegionGap / RegionCoverageTarget` | 2 / 0.25；跨类型实际footprint最短距离减1；普通陆地软目标 |

`RiverCount` 仅作为旧调用的开关保留：0关闭河网，正值启用汇水河网，已不限制为若干西部水源。旧源头列范围不再参与挑选。封闭湖是显式合法终点，即使优先入海也可终止；旧 `LakeSinks` 仍要求显式允许内陆终点。

### 湖泊模板

`GenerationPhase="lake"` 与 `Lake` 声明让地区在海域之后、河网之前完整放置。`Lake.Role` 为 `flowthrough` 或 `closed`；`Ports` 的 Dq/Dr 指湖面格，Direction朝footprint外，IsInlet区分入／出口。过流湖恰有一个出口；封闭湖没有出口。整片连通湖面收缩成一个图节点，岸线与岛屿仍按作者类型保留，水面不伪造双向连接。

三份样例是 `lake_plain`（15×11）、`lake_mountain`（19×9）、`lake_wetland`（17×13）。各 `MinCount=MaxCount=1`，湿地湖为封闭湖，其余过流；湖面各至少25格。每份JSON只存一份相对布局和少数端口。湖位不足、海域／固定地标冲突或singleton冲突时有限回退并报告缺失，不裁切／减数／覆盖旧世界。

普通涉水地区仍须精确匹配 `RiverCells / RiverPorts`，河带中的侧格也须匹配river类型。固定作者河段可以用 `NarrowRiverCells` 明确声明单格窄峡（Dq/Dr）；仅这些格允许压缩河宽并记录 `authored-narrow-canyon`，下游按汇水恢复。未声明的障碍会改选可容纳宽度的流路或明确失败。

### 导出与验证

`map.json` 每格的 `water` 包含 kind、bodyId、surfaceLevel、drainageElevation、drainageRank、drainageTarget、localRunoff、runoff、width、isCenterline、centerlineIndex、reason及原六方向连接。`drainageTarget` 为行优先格索引；大于等于40000代表 `40000+湖体顺序` 的整体节点，-1为终点／无路。宽河侧格的centerlineIndex指其相邻中心线，runoff保留本格排水汇水量；主河流量可查所属中心线。

运行时 `Tile.Water` 返回独立副本；查询不会改写世界、推进Tick或污染其他位面。`GeneratedWorld.Lakes` 保存湖体归属、共同水位、唯一出口、角色和汇水。配置与全部水域数据进入v3摘要，计时和实体ID排除。

HTML以gzip/base64无损内嵌完整数据，仍可离线自包含打开；绘制使用256级显示调色板与分批路径，数值与选格数据不变。HTML默认不显示地区轮廓，可独立开关；自然高度和排水高度各有图层，水体与河带图层显示真实占地，中心线另叠加，选格展示判断原因。`diagnostics.metrics` 及批量报告包含海平面满足率、湖数／面积、完整湖地区面积、支流／汇流、河宽分布、汇水、最小地区间隔、各轴差分P95／最大值及接缝、固定内部范围。没有两个普通地区时最小间隔记-1。

```powershell
dotnet Console/bin/Debug/net8.0/UnityWorld.Console.dll --map-hydrology-tests --data-root .
python tools/test_water_migration.py
python tools/migrate_water_types.py
python tools/audit_world_map.py --check
```

平滑夹具预先采用每邻边海拔差≤0.12、湿度／温度差≤0.10；包含普通边、普通地区边及固定副本接缝，仅显式长城／海岸陡变单列。真实样本逐项报告而非抹平地图。覆盖不足25%可合法警告，必需地区、三湖、海域、河宽与固定保护均是硬规则。v2历史预览保留；回退需同时恢复代码、定义与生成器版本，导出不是兼容旧存档格式。
