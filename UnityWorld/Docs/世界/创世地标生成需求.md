# 创世地标生成需求

## 范围与目标

第一次创造主世界时，河网、地形和地区拼图先落定。地区自带的地标和绝对固定地标已经有了位置。独立生成在这个基础上补齐首批地标，能按全图数量控制规模，也能按每个合法格的概率制造分布差异。本文记录确定的目标行为，旧实现和 Odyssey 的调研保留在评审稿。 [调研与评审记录](创世地标定义评审.md)

这次按开发期重构处理。删除地标的 `SchemaVersion`、`SpawnWeight`、`PlacementTypeIds`、`PlacementTags`、`PlacementExtraTerrains`，同步调整定义、现有 JSON、生成器、校验、编辑器、数据工具和测试。地区与地块各自的定义字段按其现有规则处理。

## LandMarkDefine 字段

| 属性 | 放在哪 | 规则 |
| --- | --- | --- |
| `ID`、`DisplayName`、`Tags` | 地标定义顶层 | 类型身份、显示名称和地标自身标签 |
| `IsNatural`、`AuraOffset`、`ModifierDefineIds` | 顶层 | 决定元气相关规则。创世仍先创建自然地标、再拍原初快照、最后创建人工地标 |
| `IsSingleton` | 顶层 | 约束全部有效实例的全局唯一性 |
| `ImagePath`、`DrawType` | 顶层 | 图片与绘制方式。取值为 `Icon`、`TerrainMask`、`Shader`、`Atmosphere`、`None`，默认 `Icon` |
| `IsHide` | 顶层 | 默认关闭。启用后，玩家和 NPC 的观察、名称、数量、可互动目标排除该地标 |
| `InitialPlacement` | 顶层可选对象 | 由通用 C# 类型 `InitialPlacement` 承载选址配置，具体内容的生成器负责解释候选格和已有实例 |

隐藏地标仍真实存在，能参与世界生成、占位、计数和施加效果。无绘制的可见地标仍能出现在地点详情或互动入口。地区编辑器是作者视图，可检查同格隐藏和无绘制地标的配置。

### InitialPlacement 字段

| 属性 | 省略时 | 作用 |
| --- | --- | --- |
| `ForcedPositions` | 空 | 固定绝对坐标，计入本张图的首批总数 |
| `PerTileChance` | 普通散布开启后，全部普通候选通过概率关 | 值为 0 也表示全部通过。大于 0 时每格独立抽一次，合法范围是 0–1 |
| `MinCount` | 0 | 正常数量区间下限。普通候选不够时采用可放数量 |
| `MaxCount` | 无上限 | 正常数量区间上限，从地区、固定和补位的合计数量检查 |
| `NeedCount` | 无强制保底 | 正常生成结束后，若总数不足，补到该数量 |
| `MinSpacing` | 0 | 每个新增位置与本位面已规划同类地标之间的最小六边形格距 |
| `TerrainConditions` | 空 | 读最终 Tile 类型。多个正向类型满足任一即可，排除项逐条检查 |
| `LandMarkConditions` | 空 | 读已规划地标，含地区自带的主地标和附加地标。支持同格与近邻前置，逐条检查 |
| `TagConditions` | 空 | 读候选格的地形标签，逐条检查 |
| `ExtraCondition` | 空 | 预留 Lua 文本。当前可保存和导出，选址结果与其内容无关 |

**四个数值字段可以单配，也可以齐配。** 显式填写 `PerTileChance`、`MinCount` 或 `MaxCount` 中任意一项会开启普通散布。只填 `NeedCount` 就从已有数量直接补足。四项都省略时只执行作者布局和绝对坐标。三个数量与间距使用非负整数，同时填了 `MinCount` 和 `MaxCount` 时，上限至少为下限。

## 创世顺序

```text
固定地区与绝对坐标预留
    -> 环境、水文、普通地区与补齐地块
    -> 清点已规划地标
    -> 地形、地标、标签条件筛选与逐格抽签
    -> 核算可有总数，按区间确定正常数量
    -> NeedCount 补足
    -> 地图审计、创建实体与发布
```

### 1. 计算可以有多少

先清点本位面已经规划的同定义实例 `A`，包括实际落地的地区主地标、同格附加地标和绝对坐标地标。再检查基础填充和允许生成的地区空格，应用选址条件、逐格概率、唯一性和间距。**可有总数等于 `A` 加上本轮按种子顺序实际排得下的普通候选数。**

`RegionDefine.AllowInitialLandMarks` 默认是 `true`，也适用于有固定锚点的地区。设为 `false` 时，独立生成和保底补位都跳过其空格。作者铺好的地形、主地标、附加地标与绝对坐标照常保留。地区即使关闭，自带地标仍可被其他地标查询，也计入同类总量。

### 2. 确定正常应该有多少

- 可有总数在 `MinCount–MaxCount` 内，采用该总数。
- 可有总数低于 `MinCount`，采用实际可放数量，记差额，创世照常。
- 可有总数超过 `MaxCount`，在 `max(A, MinCount)…MaxCount` 中随机取一个整数总目标，再从合法位置无放回选取目标与 `A` 的差额。
- 已经摆好的作者地标超过显式上限，报告冲突。调整配额或作者布局即可消解。

**例子。** 1000 格满足条件，设 `MinCount=0`、`MaxCount=100`。如果 `PerTileChance=0.05` 这次恰好命中 50 格，就放 50 个。如果 `PerTileChance=0`，可有 1000 个，这时才随机抽 0–100 的整数。此例假定作者已放 0 个，间距和占位也没有缩减候选。

### 3. 补到 NeedCount

正常结果低于 `NeedCount` 时，差几处就补几处。先用尚未占用且满足普通条件的格，余量不够再从通用约束允许的格中随机补。保底跳过逐格抽签，最后一层保底可以放宽普通选址条件。**策划用「是否填 `NeedCount`」控制是否允许这种放宽。** 有绝对选址限制的河心水府可以省略它。

保底仍尊重地图范围、地区的 `AllowInitialLandMarks`、作者落点、可用空位、唯一性、`MinSpacing` 和已设上限。`NeedCount > MaxCount` 属于配置冲突。硬约束下确实补不齐时，报告地标、缺口和原因。普通下限不足与保底不足是两种不同的生成结果。

有保底缺口的地标优先于无依赖关系的普通散布地标。明确的前置依赖先完成，同级竞争用种子顺序。编辑器只保存配置并校验字段和引用，具体地图是否能满足保底由正式创世判断。

**例子。** 正常抽到 7 个且配置 `NeedCount=20`，就再补 13 个。若已落地的地区自带 4 个灵脉眼，正常目标抽到 6，就只独立放 2 个。

## 四类条件的写法

生效的三类条件之间用「且」。普通字符串表示需要它，`No:` 表示排除它。配置使用稳定 ID 或正式标签值。例如「海且同格没有河心水府」拆成地形条件 `ocean` 加地标条件 `No:river_water_mansion`，前提是已定义该水府 ID。独立生成使用空格，近邻条件适合做地标接力。需要同格组合时，在地区模板配置主地标和附加地标。

| 写法 | 含义 |
| --- | --- |
| `mountain` | 地形条件要求候选格为山地定义 |
| `No:ocean` | 地形条件排除海格 |
| `山类`、`No:寒冷` | 地形标签条件要求山类且排除寒冷 |
| `No:river_water_mansion` | 地标条件排除格内已有的河心水府 |
| `Near(3):natural_leyline_eye` | 地标条件要求六边形格距 3 以内有已规划的灵脉眼 |
| `No:Near(3):natural_leyline_eye` | 地标条件要求 3 格内没有这一地标 |
| `After:natural_leyline_eye` | 只声明灵脉眼先规划 |

普通筛选开始前，地区与绝对坐标地标已经可查。需要读取本轮独立生成的地标时，由地标条件建立依赖先后。出现循环依赖时报告冲突链。

## 常用配法

地区先定下这片地方的性格。创世补位负责让走同一条路的人偶尔遇到不同的事，也让已经放下的地标彼此发生关系。

| 想让玩家遇到什么 | 核心配置 | 放置结果 |
| --- | --- | --- |
| 西南雨林和林山里的千年古木 | `PerTileChance=0.004`、`TagConditions=["林木","No:寒冷"]`、`MinSpacing=6` | 每片林地有自己的机会。作者在秦岭等地区预放的古木也参与间距，附近会自然留白 |
| 北地雪峰上的冰川灵泉 | `MinCount=2`、`PerTileChance=0.003`、`TagConditions=["寒冷"]`、`MinSpacing=8` | 雪原足够大时可能找到几处。碰上只够一处的地图，就留下一处并记录普通下限不足 |
| 东荒灵脉眼，少数地图也留得下修炼去处 | `PerTileChance=0.003`、`MinCount=5`、`NeedCount=3`、`TerrainConditions=["forest","forest_mountain","mountain","hill"]`、`MinSpacing=8` | 区域自带的灵脉眼先计数。全图正常只有两处时优先补在山林，确实没位置时才可移到其它允许落点 |
| 沿着灵脉找到闭关洞府 | `LandMarkConditions=["Near(3):natural_leyline_eye"]`、`TerrainConditions=["mountain","forest_mountain"]`、`PerTileChance=0.15`、`MaxCount=5`、`MinSpacing=3` | 湖区作者自带的一座先计入五座上限；新洞府要在灵脉眼附近的山里，灵脉不够时可以少刷 |
| 路过河道才可能遇见水府 | `TerrainConditions=["river"]`、`PerTileChance=0.05`、`MinCount=0`、`MaxCount=6`、`MinSpacing=6` | 只找最终地形为 `river` 的空格。只剩三次命中就留三处。若要细到只在某类河道中心线，等待额外条件接入 |
| 按地区叙事固定一处宗门建筑 | 地区 `LandMarkLayout` 写山门，`AdditionalLandMarks` 可附藏经阁，地标定义省略 `InitialPlacement` | 两个地标随地区落在作者挑的位置。要求整座宗门都由作者控制时，地区可设 `AllowInitialLandMarks=false` |
| 隐秘的古阵眼与可察觉的灵雾 | 古阵眼用 `IsHide=true`；灵雾用 `DrawType=Atmosphere` 或 `None` 且 `IsHide=false` | 隐阵占位并可作为附近地标的前置。灵雾可留氛围或地点名称，取决于画法 |

前四行可直接对照仓库已有地标定义。水府、古阵眼和灵雾用于试配。需要四个数值一起用时，例如一个可以放在丘陵落点的东荒行旅驿亭设 `PerTileChance=0.01`、`MinCount=2`、`MaxCount=8`、`NeedCount=3`。若地区已有一座，概率再命中一处，正常数量为二，保底再补一处。如果普通可放总数有十一，才在二至八之间抽正常目标，再检查保底。如果只需要世界里出现一座宗门山门，单填 `NeedCount=1` 即可。地区已有一座时补零座，地图上没有时补一座。还要叠加普通随机规则的话，可以加 `MaxCount=1` 限制全图总量。

一张固定种子的调试地图中，灵脉眼计入地区自带的 1 处，最终有 23 处。闭关洞府在条件、概率和间距过后可以有 20 处，正常数量从 1–5 抽到 1，结果只保留湖区自带的洞府。该例中灵脉位置较多，洞府则更稀少。

## 验收

- 真实主世界结果能区分作者已放、普通候选、概率命中、抽取的正常总目标、保底补位和最终数量。
- 用同一配置验证 1000 个候选在概率为 0 和命中 50 时走不同数量分支。未达 `MinCount` 仍成功。抽到 7 且保底 20 时补足 13。
- 地区里的主地标、附加地标、绝对坐标和同类间距都参与本轮规则。地图预览和正式创世用同一种子得到相同落点。
- 地标编辑器能分别保存省略与 0，能导出四字段组合和预留的条件文本。新格式由地图目录直接加载。
- 地区编辑器能编辑地区开关。相同地形和作者布局下，打开的地区空格可以新增，关闭后普通放置和保底均跳过。
- `IsHide=true` 的地标仍能被创世条件查询，玩家与 NPC 的观察结果看不到其名称、数量和交互入口。
