## 🎯 Unity 插件化的几种实现方式

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                      Unity 插件化实现方式                                     │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │ 方式 A：Assembly Definition (asmdef)                                  │  │

│  │      ├── CardGenerator/                                              │  │
│  │      │   └── CardGeneratorUI.cs                                      │  │
│  │      └── Tools.asmdef                                                │  │
│  │                                                                       │  │

│  │  • 正式版：Editor Only 代码不打包                                    │  │

│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │ 方式 B：原生 DLL 插件                                                 │  │
│  │                                                                       │  │
│  │  适合：需要运行时动态加载                                             │  │
│  │                                                                       │  │
│  │  Plugins/                                                            │  │
│  │  ├── CardGeneratorCore.dll                                           │  │

│                                                                              │
```

## 💎 核心收获

1. **三层友好原则**：人类 / 工具 / LLM 各有最适合的数据格式，不必强求统一

2. **游戏内嵌工具更优**：策划 + 玩家双场景，零延迟数据访问

3. **Skill 作为知识胶囊**：核心逻辑 + UI 布局描述 → LLM 翻译到各平台
