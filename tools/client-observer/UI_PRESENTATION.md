# 战斗表现 UI 接入

本轮保留 1600×900 设计画布和 1440×810 默认窗口，以现有皮肤、卡图、五行图标及代码绘制完成表现。所有坐标来自零基占格；只有悬停说明转为 1 起始。

## 组件职责

| 组件 | 职责 |
| --- | --- |
| BattleObserverView | 组合会话、播放器、视图及验证入口 |
| ObserverBattleLayout | 保留构图，组合面板，统一画布缩放 |
| ObserverActorPanel | 气血、灵力、SP 当前/当前上限，护盾、身份 |
| ObserverBackpackView | 原格资源、占格、扫描与 tooltip |
| ObserverCardPainter | 实际占格裁切，需求分段暗亮与冻结覆盖 |
| ObserverPendingPanel | 固定双槽底框和两个可移动内容容器 |
| ObserverPresentationLayer | 灵元、通用入包、头顶提示及碰撞闪光 |
| ObserverLogPanel | 折叠记录及完整滚动历史 |
| ObserverSessionOutput | 输入、原始战报、每步事实文件 |
| ObserverVerificationDriver | 原控制流程、GUI 命中和真实战斗连续帧 |
| ObserverPresentationFixture | 明确标注的纯值构造视觉案例 |

主视图不再混入所有绘制、日志格式或截图流程。新文件不是机械拆分 partial；各组件持有自己的控件和职责。原预览脚本、场景、图片和正式 JSON/Lua 不在本轮 UI 修改范围。

## 数据边界和时序

- PresentationCommitted 的每个完整批次立即交给播放器，并写入版本化 presentation-v1.jsonl。事实日志不因动画压缩、队列超限或缺图而丢失。
- 卡面、灵元和待发使用最新快照加局部过渡。扫描线及行/轮/进度独立读取 session.CurrentSnapshot，不受任何动画队列或文字淡出阻塞；构造视觉案例按其自己的扫描快照显示。
- ActiveCues 提供不可变事实、进度、前后快照和 generation。效果层使用每帧进度绘制，无 Tween 完成回调，不回写核心。
- 暂停立即停会话逻辑，播放器继续收尾；单步只调用一次 Step；正常结束也等待表现结束。重开/退出调用 Cancel，换新进程防止静态核心状态残留。
- --observer-no-animations 可关闭动画并直接显示完整快照，仍保留所有事实日志。

## 表现规则

| 表现 | 开始/结束与视觉规则 |
| --- | --- |
| 灵元分配 | 源格由 ManaAssigned.SourceCell 决定；离格发光、沿短弧线飞至目标实例的真实占格中心；抵达后由播放器更新点亮 |
| 点亮 | 按实际需求总份数、固定五行顺序分段；同元素从左到右点亮；灰暗底色保留，水为亮蓝；精确 x/x 仅在 tooltip |
| 连贯多格卡 | 四邻接占格合并成连续绘制面，内部无格缝/穿图边线；图片与底色连续，仅描外轮廓。L形空洞仍不绘制，分段点亮按并集面积计算 |
| 成功使用 | 短闪后由事件的 after 资源复位；满亮等待保持亮色；无需求主功法/伤口不显示虚假进度 |
| 通用入包 | 实际成功事实后，在所属人物附近浮现并沿弧线移至真实 cells；当前活动入包实例的静态卡面隐藏，落位后恢复一份 |
| 待发对撞 | 只移动原左右两内容容器，每边向中心 68 设计像素；固定底框和背包卡不动；中点闪光、轻微震动；对撞中暂时隐藏中央文字 |
| 对拼终态 | 根据活动事实在这两个内容容器重现双方，即使本 Tick 终态空槽；完成后显示播放器当前待发，不用旧回调清空新卡 |
| 伤害 | 使用 HpDamage 原值，无快照差值；34px 基准带描边和短放大，多条并行采用存活期固定槽位；全盾吸收显示“吸收”，淡出不阻塞后续事件 |
| 生效名称 | 只读 CardApplied，显示所属角色“卡名 · 生效”；同人物多条可同时显示并分行，淡出不占用卡牌播放锁；与伤害使用上下分区 |
| 属性 | 气血、灵力、SP 均当前/当前上限；真实零显示 0；不可用显示 ? 并在 tooltip 提供 StatReadError；SP 不取背包容量 |
| 缩放 | 控件锚点通过当前全局变换转换到统一效果画布，窗口缩放时路径仍对齐；缺图保留名称并继续消费事实 |

动画时长与有界队列规则集中在纯 C# BattlePresentationPlayer。UI 不另造时间线，不等待动画结束再推进模拟。

## 验证入口和证据口径

### 真实战斗

保留 --observer-verify=目录、--observer-mode=auto|step、--observer-restarts=N 等原参数。窗口使用 --resolution 1440x810 或 1600x900。

- 保留暂停、单步、播放、战报展开/收起、重开、错误截图及扫描连续帧。
- 自动模式首次遇到各事件类型，保存 presentation-{Kind}-00..23.png 以及同名 JSONL。
- JSONL 包含核心 Tick、显示 Tick、每个活动事实及进度、待发内容坐标和显示快照，可把像素与事件关联。
- 编码 PNG 前暂停逻辑，采样期间不编码，以免编码时间污染连续帧；完整逻辑轨迹仍通过 FrameCommitted 写出。
- 正常结束等待 player.IsIdle 再截图及退出，避免吞掉最后一批提示。

### 构造的视觉案例

在 Godot 参数 -- 后追加 --battle-observer --observer-presentation-fixture=绝对输出目录；分别使用 --resolution 1440x810 与 --resolution 1600x900，其他参数与真实观察器相同。

此入口在画面明确标注“构造值案例（非正式战斗）”，只构造不可变值包并走同一播放器和 UI，不改正式模板或核心规则。每段保存逐帧 JSONL 与隔帧 PNG：

1. 00-initial：真实 0 上限、SP 上限与背包容量不同、三格水卡 1/3、无蓄灵卡。
2. 01-water-half：两格水卡由 0 到一半亮蓝，正确源格与目标。
3. 02-mixed-frozen：混色 L 形冻结卡，只亮对应元素区域，洞不被覆盖。
4. 03-full-chain：同 Tick 吸收、使用、入槽、对拼、生效、伤害、伤口及普通卡入包；伤害后恢复不抵消飘字。
5. 04-draw：平局仍由原两个待发槽碰撞，双方分别生效。
6. 05-passive-shield-limits：实际被动名称、全吸收、连续独立伤害及动态上限。
7. 06-removal-unavailable：后续移除和明确不可用上限。

完成输出 fixture-result.json 与 OBSERVER_PRESENTATION_FIXTURE_OK。这些图片是视觉渲染证据，不能代替核心观察事件的真实性、观察开关等价或纯属性读取测试；真实战斗证据与构造证据须分别报告。
