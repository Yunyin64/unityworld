# 战斗表现 UI 接入

## 月门论剑台演出时序

依据用户导出的第 260–575 帧与原始时间戳。约 9.62–10.15 秒推近并稳定到交手构图，第 315 帧（10.734 秒）出现首次明显接触。第 441–443 帧（14.934–15.001 秒）显示命中并明显拉开双方间距。第 402–421 帧（13.634–14.268 秒）显示普通交锋的拉镜与交接，18.65 秒的大范围金粒出现在击败掉落反馈之后。

第 261 帧是远景，人物约占画面高 8%–9%。第 300、423 帧进入交手近景，人物约占 18%–22%。本场按 1920×1080 验收，远景人物渲染高约 93 像素，近景目标约 255 像素，相机背景从 1 倍推到 1.78 倍。框选参考里的储物区接近方形，目前两侧各为 270×314，推镜时淡出，拉远时恢复，阵内事件仍持续交付。

入待发的牌沿弧线从实际占格飞到该角色身后，空等时场上留白。拼点近景沿人物外侧展开双方卡面，显示已载入的说明、最终点数和招式图标。斩击、打击、刺击、射击、护盾、格挡、闪避用不同轮廓，颜色取拼点元素，无属性用灰色。底部仍可展开完整战报。

| 演出 | 单次演出时间 |
| --- | --- |
| 对拼 | 普通合计 2.345 秒，约 1.10 秒命中。闪避胜 1.905 秒，格挡或护盾胜 2.045 秒，重击胜 2.505 秒。人物到位后停 105 毫秒，出手段用原动作时长的 62%，接触一亮相再停 90 毫秒，随后才击退 |
| 直击 | 普通仍为 1.56 秒，约 0.49 秒命中。射击 1.48 秒，全额护盾吸收 1.36 秒，重击 1.82 秒。两处停顿也计入这些时长 |
| 主动施法 | 0.70 秒。约 0.29 秒释放并显示卡名，使用卡牌美术配置中的五行颜色 |
| 待发飞牌 | 0.32 秒。起点取实际卡格中心，终点取人物身后当前牌位 |

以上是单次演出的常速。近身命中后追一步，受击者先被撞开再缓步落地。挡住时稳住后脚，闪避在接触前低身抽离，射击者留在远处。紧接的动作从上一击的实际收势和近景开始，交手点保留前三招的推进方向，末招才撤步、闪回、拉远。近景淡出两侧储物阵。招式点数跟随卡面，命中数字留在人物身边。若镜头积压，播放器可以加速。后端 Tick、背包扫描和战报继续按各自时钟推进。对拼和直击由原始事实决定，构造值视觉夹具用于复查节拍、回场与交手姿态。

同一 Tick 的终局确认最后一击的目标已败退时，败者在击退落点跪倒并散为符光，胜者收势回位。败退可以由伤口占用超过 SP 上限触发，结果只取核心快照。

## 原观察器表现接入

观察器默认窗口为 1920×1080。储物阵、状态和底部战报保留响应式锚点。所有卡格坐标来自零基占格，悬停说明以 1 起始。

## 数据边界和时序

- PresentationCommitted 的每个完整批次立即交给播放器，并写入版本化 presentation-v1.jsonl。事实日志不因动画压缩、队列超限或缺图而丢失。
- 卡面、灵元和待发使用最新快照加局部过渡。扫描线及行/轮/进度独立读取 session.CurrentSnapshot，不受任何动画队列或文字淡出阻塞；构造视觉案例按其自己的扫描快照显示。
- ActiveCues 提供不可变事实、进度、前后快照和 generation。效果层使用每帧进度绘制，无 Tween 完成回调，不回写核心。
- 暂停立即停会话逻辑，播放器继续收尾；单步只调用一次 Step；正常结束也等待表现结束。重开/退出调用 Cancel，换新进程防止静态核心状态残留。
- --observer-no-animations 可关闭动画并直接显示完整快照，仍保留所有事实日志。

## 表现规则

| 表现 | 开始/结束与视觉规则 |
| --- | --- |
| 灵元分配 | 源格由 ManaAssigned.SourceCell 决定；离格发光、沿短弧线飞至目标实例的真实占格中心；抵达后由播放器更新点亮 |
| 点亮 | 按实际需求总份数、固定五行顺序分段；同元素从左到右点亮；灰暗底色保留，水为亮蓝；精确 x/x 仅在 tooltip |
| 连贯多格卡 | 四邻接占格合并成连续绘制面，内部无格缝/穿图边线；图片与底色连续，仅描外轮廓。L形空洞仍不绘制，分段点亮按并集面积计算 |
| 成功使用 | 短闪后由事件的 after 资源复位；满亮等待保持亮色；无需求主功法/伤口不显示虚假进度 |
| 通用入包 | 实际成功事实后，在所属人物附近浮现并沿弧线移至真实 cells；当前活动入包实例的静态卡面隐藏，落位后恢复一份 |
| 待发飞牌 | 待发事件提供实际来源格。同一实例飞行或待发时，背包尽头保留原格位置，卡面转移到舞台 |
| 对拼交接 | 同一 Tick 已提交入待发的牌先飞到位，再进入交手镜头。近景使用实际参与的两张牌和结算点数 |
| 击退与回场 | 气血受击先后仰、滑步、撑地，进攻方可以在其落脚后再追一步。镜头短暂拉远给位移留空间，续招继承上一招的站位。尾招面朝对手撤步，再用出发符纹、遁光、落点符纹连接回到原位的落地姿态 |
| 伤害 | 直接显示 HpDamage 和 ShieldAbsorbed。近景飘字沿角色外侧胸口往上走，命中使用 37px 基准，重击使用 46px。多条并行采用存活期固定槽位 |
| 生效名称 | 只读 CardApplied，显示所属角色“卡名 · 生效”；同人物多条可同时显示并分行，淡出不占用卡牌播放锁；与伤害使用上下分区 |
| 非拼点施法 | 选定的主动效果卡在原地结印、推掌和收手。法光从结印位置移到前手，音效和生效名在推出时触发 |
| 属性 | 气血、灵力、SP 均当前/当前上限；真实零显示 0；不可用显示 ? 并在 tooltip 提供 StatReadError；SP 不取背包容量 |
| 缩放 | 控件锚点通过当前全局变换转换到统一效果画布，窗口缩放时路径仍对齐；缺图保留名称并继续消费事实 |

动画时长与有界队列规则集中在纯 C# BattlePresentationPlayer。UI 不另造时间线，不等待动画结束再推进模拟。

## 验证入口和证据口径

### 真实战斗

保留 --observer-verify=目录、--observer-mode=auto|step、--observer-restarts=N 等原参数。主画面使用 --resolution 1920x1080。

- 保留暂停、单步、播放、战报展开/收起、重开、错误截图及扫描连续帧。
- 自动模式首次遇到各事件类型，保存连续 PNG 以及同名 JSONL。常规表现采样 24 帧，对拼和直击按约 30 帧/秒采样到近景结束，上限 120 帧。
- JSONL 包含核心 Tick、显示 Tick、实际采样时间、飞牌进度、近身和命中两次时停、站位、姿态、镜头倍率和音效触发点。构造案例也记录云纹偏移、帧号与山脉的归一化滚动量。
- 编码 PNG 前暂停逻辑，采样期间不编码，以免编码时间污染连续帧；完整逻辑轨迹仍通过 FrameCommitted 写出。
- 正常结束等待 player.IsIdle 再截图及退出，避免吞掉最后一批提示。

### 构造的视觉案例

在 Godot 参数 -- 后追加 --battle-observer --observer-presentation-fixture=绝对输出目录。使用 --resolution 1920x1080 检查主构图，再使用 --resolution 1024x900 检查紧凑布局。

此入口在画面明确标注“构造值案例（非正式战斗）”，只构造不可变值包并走同一播放器和 UI，不改正式模板或核心规则。每段保存逐帧 JSONL 与隔帧 PNG：

1. 00-initial：真实 0 上限、SP 上限与背包容量不同、三格水卡 1/3、无蓄灵卡。
2. 01-water-half：两格水卡由 0 到一半亮蓝，正确源格与目标。
3. 02-mixed-frozen：混色 L 形冻结卡，只亮对应元素区域，洞不被覆盖。
4. 03-full-chain：同 Tick 吸收、使用、入槽、对拼、生效、伤害、伤口及普通卡入包；伤害后恢复不抵消飘字。
5. 04-draw：两张飞牌先到角色身后，近景根据平局事实显示双方卡牌。
6. 05-passive-shield-limits：实际被动名称、全吸收、连续独立伤害及动态上限。
7. 06-removal-unavailable：后续移除和明确不可用上限。
8. 07-parallel-popups 至 10-active-casts：并发提示、直击、全额护盾和主动施法。
9. 11-continuous-exchange：对拼受击后反击，检查近景、受击姿态和落脚点在两个镜头之间连续。
10. 12-evade-heavy：两人换边重击与闪避，检查命中点脱离、低身姿态和连续落脚点。
11. 13-pursuit-counter：重击后追进右半场，接闪避与反刺，检查前后招的落脚点、近景和末招回位。
12. 14-defeat：气血仍大于零时，按已确认结果播放败退终镜。检查败者跪地散去、胜者回位、结算后败者继续离场。

完成输出 fixture-result.json 与 OBSERVER_PRESENTATION_FIXTURE_OK。这些图片是视觉渲染证据，不能代替核心观察事件的真实性、观察开关等价或纯属性读取测试；真实战斗证据与构造证据须分别报告。

## 当前版本验收

- 三层背景在 1920×1080 每秒采样一帧，共 21 帧。远山分别在第 5、10、15、20 秒向左移动 45、90、135、180 像素。石台及立柱的固定取样区域逐像素一致，主云团区域有变化。山图左半和用户素材逐像素一致，内外两处接缝的相邻列 RGB 对齐。
- 正式 A/B 对战跑完 470 Tick。包含起始状态的 471 条快照和事件轨迹逐条比对一致。正式对战的拼点和直击均捕获了两次定格，定格期间人物位置、姿态和镜头倍率保持一致。
- 1920×1080 与 1024×900 构造案例均播到结束。最后一击结算后，败者离场，胜者回到待机。

## 用户实测修正

2026-10-31 取消整 Tick 动画屏障，跨 Tick 提示与位移动画可重叠，只有资源过渡、入包前置和双槽短位移保留必要依赖。旧版按整批收尾的验收不足以证明扫描不停顿；本次在真实战斗连续帧额外记录最新扫描状态、光线位置和活动事件，证明它们同时推进。多格长剑在纯值视觉夹具右侧有独立用例。修正证据在 `.local-verification/battle-presentation-parallel/`。
